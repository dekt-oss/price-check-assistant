## 1. 무엇을 재나

| 단계 | 어디서 | 뜻 |
| --- | --- | --- |

## 3. 검색 중 화면

검색 상자 문구가 단계마다 바뀐다: `1/4 제품 확인 중` → `2/4 같은 제품 거래 찾는 중` → `3/4 같은 품목 참고 시세 계산 중` / `3/4 최근 며칠 거래 실시간 확인 중` → `4/4 회수·판매중지 확인 중`. 앱이 막 켜졌으면 그 전에 내려받기 진행률이 나온다(기존).

## 5. P2b 판단 기준 (작업지시서 잠정 목표)

- 따뜻한 상태 `wall` 중앙값이 10초를 넘거나 `track_b`가 `total`의 절반을 넘으면: 모델별 요약 파일 사전 생성(R2) 후 결론 카드 먼저 그리기
- 차가운 상태에서 10초 안에 진행 표시가 없으면: 내려받기 진행률 표시 조건 점검
- `safety`나 `track_b_live`가 길면: 해당 조회를 결론 뒤로 미루기

## 6. P2b-1 (2026-10-13): 같은 제품 거래 조회의 행마다 추가 조회 제거

- **원인**: 거래조건·사업명 등 4개 칸이 지연 로딩으로 설정돼 있어, 같은 제품 거래 1행마다 SQL을 4번 더 실행했다(HeartOn A16-DS 391행 → 1,564번). 같은 품명 문자열의 제품 판정도 행마다 반복했다.
- **수정**: 조회 한 번에 그 칸을 함께 읽고(인덱스에 칸이 있을 때만), 한 조회 안에서 품명별 판정을 재사용한다. 결과는 같다(기존 테스트 전부 통과, 행 수와 무관하게 SELECT 2번 이하를 확인하는 테스트 추가).
- **로컬 측정**(같은 인덱스, 같은 PC): HeartOn A16-DS 조회 2.88초 → 0.47초(두 번째 조회 2.3초 → 0.03초). 거래 없는 NT960XJG-K72AG는 1.5초(첫 조회) / 0.5초로 대부분 실제 SQL 시간이다.
- **운영 재측정**: 배포 뒤 Price Search Timings 수동 실행 결과를 여기에 적는다.

## 7. P2b-2 (2026-10-13): 모델·제조사 별칭 파일을 한 번만 읽기

- **원인**: 같은 품목의 다른 모델 표를 만들려고 그 품목 모델 전부(HeartOn A16-DS의 저출력심장충격기는 134개 모델, 거래 6,760행)를 판정하는데, 판정 한 번마다 모델 별칭·제조사 별칭 CSV를 디스크에서 다시 열었다(파일 열기 약 2만 번, 20.5초 중 약 17초).
- **수정**: 별칭 목록을 파일별로 한 번 읽어 두고 60초마다 파일 크기·수정 시각만 확인한다. 결과는 같다.
- **로컬 측정**: 같은 품목 모델 집계 20.5초 → 2.3초(두 번째부터 15.9초 → 0.75초). 로컬 앱 HeartOn A16-DS 서버 검색 전체 19.5초 → 4.3초(같은 제품 조회 0.5 · 같은 품목 모델 2.1 · 제품군 0.8초).
