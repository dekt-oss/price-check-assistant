# 가격 검색 시간 기준선 (Track P · Phase P2a)

- 작성일: 2026-10-12 · 작업지시서 `docs/coordination/UX_V11_WORK_ORDER_v1.2.md` 5장 P2
- 상태: **측정 도구 배포, 운영 표본 수집 중.** 1주일 표본이 쌓이면 4장을 채우고 P2b 범위를 정한다.

## 1. 무엇을 재나

| 단계 | 어디서 | 뜻 |
| --- | --- | --- |
| `wall` | 측정 스크립트(브라우저 시계) | 주소를 연 순간부터 결론 카드(또는 빈 결과)가 보일 때까지. 사용자가 실제로 기다리는 시간 |
| `warmup_wait` | 숨김 마커 v2 | 앱이 막 켜져 인덱스를 내려받는 동안 검색이 기다린 시간 |
| `cold` | 숨김 마커 v2 | 검색 시작 때 인덱스를 아직 내려받는 중이었는지(1=차가운 상태) |
| `identity` | 숨김 마커 v2 | 제품 확인(식약처 허가정보 인덱스·검색어 해석) |
| `track_b` | 숨김 마커 v2 | 같은 제품 거래 조회. 제품군 참고 시세 계산을 포함 |
| `category_market` | 숨김 마커 v2 | 제품군 참고 시세 계산만 |
| `track_b_live` | 숨김 마커 v2 | 수집 뒤 며칠 거래 실시간 확인(나라장터 API) |
| `mfds` | 숨김 마커 v2 | 식약처 형명 조회 준비(지금은 버튼 뒤로 미뤄져 거의 0) |
| `safety` | 숨김 마커 v2 | 회수·판매중지 확인 |
| `total` | 숨김 마커 v2 | 서버 검색 전체 |
| `render_card` | 숨김 마커 `purchase-render-timings-v1` | 화면 그리기 시작부터 결론 카드까지 |

선택형 외부 조회(식약처 형명 30초 안팎, 입찰·계약 참고자료)는 버튼을 눌러야 실행되므로 검색 시간에 들어가지 않는다.

## 2. 어떻게 재나

- 도구: `python -m purchase_price.scripts.measure_price_search_timings` (Playwright 필요)
- 정기 실행: GitHub Actions **Price Search Timings** (`.github/workflows/track-b-search-timings.yml`), 매일 09:17·13:17·17:17(한국 시간) + 수동 실행
- 검색어: PNB-704(거래 많음) · SJ-DFM100(같은 제품 거래 없음) · HeartOn A16-DS(입력 오류·이상 거래 있음) · NT960XJG-K72AG(PC)
- 저장: R2 `state/v1/perf/price-search-timings.json`(최근 600개). 작업 요약에 상태별 중앙값·90% 값이 나온다.
- 차가운 상태 표본은 앱이 재시작된 직후 실행에서만 생긴다. 일부러 재시작하지 않는다(재시작은 통합 담당만, 리소스 한도 사고 전례).

## 3. 검색 중 화면

검색 상자 문구가 단계마다 바뀐다: `1/4 제품 확인 중` → `2/4 같은 제품 거래 찾는 중` → `3/4 같은 품목 참고 시세 계산 중` / `3/4 최근 며칠 거래 실시간 확인 중` → `4/4 회수·판매중지 확인 중`. 앱이 막 켜졌으면 그 전에 내려받기 진행률이 나온다(기존).

## 5. P2b 판단 기준 (작업지시서 잠정 목표)

- 따뜻한 상태 `wall` 중앙값이 10초를 넘거나 `track_b`가 `total`의 절반을 넘으면: 모델별 요약 파일 사전 생성(R2) 후 결론 카드 먼저 그리기
- 차가운 상태에서 10초 안에 진행 표시가 없으면: 내려받기 진행률 표시 조건 점검
- `safety`나 `track_b_live`가 길면: 해당 조회를 결론 뒤로 미루기
