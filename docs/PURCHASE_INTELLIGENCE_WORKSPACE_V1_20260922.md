# 구매조사 워크스페이스 V1 설계

작성일: 2026-09-22

## 목표

이 프로젝트를 단순 가격검색기가 아니라 **병원 구매담당자용 제품 조사 엔진**으로 재구성한다.

사용자는 두 가지 방식으로 시작한다.

1. 모델명/품명 직접 검색
2. 견적서 업로드

두 입력은 동일한 조사 파이프라인으로 합류한다.

```text
모델명/견적서
→ 제품 identity 구조화
→ Safety 확인
→ 나라장터 실제 거래
→ 단가/수량/총액/모델/규격/조건 비교
→ 식약처 등록모델·등록업체
→ 나라장터 실제 공급업체
→ 동일품목 경쟁장비
→ 공개조달 Research
→ 원문 근거
```

## 1. 홈 화면

### 상단 검색

하나의 큰 검색창을 유지한다.

예:
- DFM100
- ROTAPRO
- ApeosPrint C5570 GK
- 심장충격기
- Philips Efficia DFM100

오른쪽에 `검색`.

검색창 아래에는 작은 보조 액션만 둔다.

- 정확도 높이기
- 견적서 업로드

기능별 메뉴를 먼저 고르게 하지 않는다.

---

## 2. 검색 결과의 첫 화면 — 구매검토 요약

검색 후 사용자가 가장 먼저 봐야 하는 것은 데이터 테이블이 아니라 **의사결정용 요약**이다.

### A. Safety banner

회수·판매중지/안전성 정보가 있으면 가격보다 먼저 노출한다.

- RED: exact 모델 또는 허가번호 hit
- AMBER: 품목/업체 수준 관련정보
- NONE: 연결된 공식 source에서 일치정보 미확인

### B. 제품 identity card

- 품명
- 제조사
- 모델
- 규격
- G2B 세부품명번호
- MFDS 품목/허가번호
- identity 신뢰수준

자동해석이면 반드시 표시한다.

### C. 핵심 요약 4카드

1. 동일제품 거래
2. 관측 단가 범위
3. 식약처 등록업체
4. 실제 조달 공급업체

예:

```text
동일제품 거래      8건
관측 단가          9.9M ~ 13.2M
식약처 등록업체    6개
조달 공급업체      4개
```

직접가격이 없으면 첫 카드에 `직접근거 없음`이라고 명확하게 표시한다.

## 3. 결과 Navigation

한 페이지 안에서 다음 탭을 사용한다.

### 탭 1 — 요약

- Safety
- 제품 identity
- 직접가격 범위
- 현재 견적 대비 위치
- 업체/공급사 요약
- 경쟁장비 수

### 탭 2 — 거래가격

나라장터 실제 거래를 **행 단위**와 **그룹 단위**로 본다.

#### 거래행 필드

- 거래일
- 모델
- 규격
- 공급업체
- 수요기관
- 수량
- 단위
- 대당단가
- 총액
- 금액 일치검증
- 비교등급 A/B/C
- 품목식별번호
- 세부품명번호
- 원문 provenance

#### 그룹 보기

기본 그룹:
- 모델별
- 모델+규격별
- 공급업체별

표시:
- 거래건수
- 최소단가
- 중앙값
- 최대단가
- 최근거래일
- 총수량

**총액은 시장단가로 사용하지 않는다.**
총액은 거래규모/수량 검증용으로 표시한다.

### 탭 3 — 식약처·업체

#### 등록정보

- 품목명
- 모델
- 허가번호
- 허가일
- 등록업체
- 취소/취하
- 수출전용

#### 등록업체 요약

업체별:
- 활성모델 수
- 허가건수
- 최근허가일
- 대표모델

#### 업허가

- 제조
- 수입
- 판매
- 임대
- 수리
- 영업상태
- 주소

### 탭 4 — 공급사

근거별로 분리한다.

1. 나라장터 실제 공급실적
2. 식약처 품목 등록업체
3. 식약처 업허가 업체
4. 제조사 공식 판매채널
5. 웹

일반 웹업체는 반드시 `웹` 표시.

### 탭 5 — 경쟁장비

동일 식약처 품목의 국내 정상 등록모델.

- 업체
- 모델
- 허가번호
- 공개 조달가격 존재여부
- 실제 공급사 존재여부

임상적으로 대체 가능하다고 표현하지 않는다.

### 탭 6 — Research·근거

- 입찰공고
- 사전규격
- 낙찰
- 계약
- 첨부문서
- 원문 링크
- source 상태

Research의 예산/추정가격/계약총액은 직접 단가와 시각적으로 분리한다.

## 4. 견적서 업로드 UX

견적서를 올리면 먼저 추출결과만 보여주지 않고 **품목별 조사 진행상태**를 표시한다.

예:

| 품목 | 모델 | 견적단가 | 조사상태 |
|---|---|---:|---|
| 심장충격기 | DFM100 | 12,500,000 | 직접가격 2건 · MFDS 확인 |
| 판독모니터 | CX30N | 8,000,000 | 직접가격 없음 · 참고 25건 |
| ROTAPRO | ROTAPRO | - | 거래가격 없음 · 조달 Research 있음 |

각 행을 누르면 동일한 구매조사 상세화면으로 이동한다.

따라서 직접검색과 견적서 검색이 다른 기능처럼 보이지 않게 한다.

## 5. 나라장터 가격 해석

### 반드시 구분할 값

#### 대당단가

공식 source 필드 `prdctUprc`.

가격비교 기본값.

#### 수량

`prdctQty`.

#### 총액

`prdctAmt`.

### 검증

`대당단가 × 수량 = 총액`을 검사한다.

- CONSISTENT
- INCONSISTENT
- NOT_CHECKED

불일치 거래는 숨기지 않고 경고한다.

### 조건

원문에서 이미 수집하는 항목:
- 계약납품유형
- 계약유형
- 납품조건

현재 normalized raw에는 있지만 Serving Index에는 보존되지 않는다.

다음 스키마 확장에서 Serving Index에도 저장한다.

### 모델/규격

G2B 상품명 title에서 파싱한:
- 제조사
- 모델
- 규격

을 거래행에 직접 노출한다.

---

## 6. 가격 요약 규칙

동일제품 A/B만 `직접가격` 요약에 포함한다.

### 거래건수 충분

N >= 5:
- 최저
- 중앙값
- 최고
- IQR 또는 robust range
- 최근거래

### 거래건수 적음

N < 5:
- 개별 거래 전부 노출
- 과도한 통계 요약 금지

### 참고가격

C/Research는 별도 영역.

직접가격과 같은 그래프/범위에 합치지 않는다.

## 8. 구현 순서

### Phase W1 — 거래 상세 foundation

- Track B candidate에 total_amount/model/spec/product_id/detail_code 노출
- 거래 테이블에 총액·수량·대당단가 표시
- amount_check 표시
- 모델/규격 그룹요약

### Phase W2 — Serving condition schema

- contract_delivery_type
- contract_type
- delivery_condition

을 Serving Index에 추가
- existing raw R2에서 index rebuild
- raw 재수집 불필요

### Phase W3 — 결과 workspace UI

- 요약 + 6 tabs
- direct/reference/research 시각분리
- 직접검색/견적서 공통 상세 화면

### Phase W4 — MFDS integration

- 검색 query를 MFDS identity로 전달
- 등록업체 집계
- 업허가 교차조회
- 동일품목 등록장비

### Phase W5 — Safety

- 공식 recall adapter
- RED/AMBER
