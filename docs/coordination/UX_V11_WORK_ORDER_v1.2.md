## 1. 작업 목적

사용자가 다음 질문의 답을 더 빠르고 안전하게 이해하도록 만든다. 기능을 늘리는 작업이 아니다.

1. 받은 견적이 과거 동일 모델 거래와 비교해 어느 위치인가?
2. 비교에 쓴 거래가 충분하고 최신인가?
3. 동일 모델과 같은 품목의 다른 모델은 가격이 어떻게 변했는가?
4. 오늘 먼저 확인할 병원 뉴스 이슈는 무엇인가?
5. 공개 회계자료에서 우리 병원이 비교군과 크게 다른 지표는 무엇인가?

서비스는 구매 적정성, 제품 대체 가능성, 안전성, 경영 원인을 확정적으로 판정하지 않는다. 데이터가 부족하거나 조건이 다르면 결론을 만들지 않고 `비교 근거 부족` 또는 `추가 확인 필요`로 표시한다.

## 3. 공통 제품 원칙

### 3.1 근거 4요소
모든 주요 수치에는 가능한 범위에서 **비교 건수 · 비교 기간 · 가격 계산 단위 · 자료 기준일**을 함께 표시한다. VAT·설치·옵션·보증·교육·유지보수 조건이 확인되지 않은 경우 이를 숨기지 않는다.

### 3.2 동일 모델과 제품군 분리
- `동일 모델 거래`: 식약처 identity(exact) 또는 검증된 별칭(`data/model_aliases.csv`)으로 같은 모델임을 확인한 거래
- `제품군 참고 시세`: 같은 식약처 품목 또는 검증된 나라장터 세부품명에 속한 다른 모델을 포함한 거래(현행 `services/category_market.py`)
- 동일 모델 거래가 충분(초기값: 가격 계산 사용 건수 ≥ 3)하면 제품군 값은 결과 결론에 쓰지 않는다. 부족하거나 없을 때만 `다른 모델을 포함한 참고 시세`로 설명한다.

### 3.3 평균보다 중앙값
- 기본 대표값: 중앙값. 산술평균은 쓰지 않는다.
- 수량가중 평균(Σ단가×수량 ÷ Σ수량, 같은 단위만)은 상세 영역에서만 검토할 수 있다. 중앙값과 차이가 크면 묶음·옵션·이상 거래 영향을 안내한다.

### 3.4 빈 결과·실패는 정상 상태
다음 상태를 별도 UI 상태로 정의하고 임의의 결론을 만들지 않는다. 각 트랙의 0단계 산출물에 문구를 확정한다.

앱·인덱스 준비 중 / 동일 모델 거래 0건 / 1~2건 / 단위 혼합 / 식약처 identity 미확인 / 실시간 보강 실패 / 자료 기준일 지연 / 뉴스 수집 실패·인증 실패 / 경영 비교군 유효값 부족

### 3.5 확정 판정 금지
결과 판정·행동 권고 문구에 다음을 쓰지 않는다: 적정 가격, 구매 권장·비권장, 싸다·비싸다, 확정 절감액, 대체 가능 제품, 안전한 제품, 경영 악화 원인 확정, 인기·대표·추천 모델, 개선 필요·우수·부진.
`적정 여부를 판단하지 않습니다` 같은 주의문은 금지 대상이 아니다. 계약 테스트는 판정 라벨·결론 문장·버튼 문구만 검사한다(현행 `result_summary.has_banned_term` 확장).

## 4. 워크트리·브랜치·배포 규칙

### 4.1 Gate 0 (착수 조건)
1. PR #341을 머지한다(CI 녹색, 4개 파일: `pages/0_홈.py`, `pages/20_병원_News_Radar.py`, 뉴스·홈 계약 테스트 2개). **Claude 세션은 타인 PR 머지 권한이 없어 사용자가 머지한다.**
2. 이 문서가 `main`에 머지된 커밋을 **BASE_SHA**로 `UX_V11_BASE.md`에 기록한다.
3. 두 트랙 브랜치를 BASE_SHA에서 만들고 `origin`에 올린다.
4. #341이 BASE_SHA 뒤에 머지되면 Track H만 `git merge origin/main` 한 번 한다(Track P 파일과 겹치지 않음).

### 4.2 간섭 방지
- 각 트랙은 자기 워크트리 안에서만 작업한다. `main` 체크아웃에서 커밋하지 않는다(다른 세션이 브랜치를 바꾸는 중에 커밋이 `main`에 직접 들어간 사고가 있었다).
- 커밋·푸시 전에 `git branch --show-current`로 브랜치를 확인한다.
- 허용목록 밖 파일은 수정하지 않는다. 필요하면 `HANDOFF`의 "공통 파일 변경 요청"에 적는다.
- `git stash`를 쓰지 않는다(스택이 워크트리 간 공유됨). 임시 WIP 커밋으로 대신한다.
- 로컬 앱: Track P는 포트 **8502~8509**, Track H는 **8602~8609**. Track H 로컬 뉴스 인덱스는 `NEWS_RADAR_INDEX_PATH=.local/news-radar.json.gz`.
- `.claude/launch.json`은 로컬 전용(추적 안 함). 트랙마다 자기 항목만 쓴다.

### 4.3 PR·배포
- Phase 하나 = PR 하나(또는 독립 커밋 묶음), 대상 `main`. 제목은 `[P1] …`, `[H1] …`처럼 Phase 접두어.
- CI(ruff, 기동 스모크, 전체 pytest, 벤치마크 게이트) 녹색 뒤에만 머지. 머지는 곧 운영 배포다.
- 운영 앱은 배포 뒤 옛 모듈을 붙들 수 있다. 화면 동작을 바꾼 모듈에는 런타임 마커 상수를 두고 페이지의 재적재 검사에 넣는다(Track P: `_TRACK_B_RUNTIME_MARKERS`류, Track H: `hospital_benchmark.MODULES_REVISION`류).
- `requirements.txt`의 `# Revision`은 통합 담당만 바꾼다.
- 머지 뒤 운영(`https://bp-price-research.streamlit.app`)에서 자기 화면을 열어 확인하고 캡처를 HANDOFF에 넣는다.

**잠정 원칙**: 동일 모델 중앙값 = 최종 변경차수·명시 단가·선택 기간·선택 단위의 중앙값 / 건수 = 전체 확인 건수와 가격 계산 사용 건수 분리 / 총 수량은 단위 확정 시만 / 견적 차이 = 부호 있는 `중앙값 대비 차이` / 기관 수 = 기관코드 또는 검증된 별칭 우선, 편집거리 자동 병합 금지 / 상위 모델 = 건수와 기관 수 병기.

**미확정(데이터 감사 후 확정)**: 제품군↔세부품명 매핑, 별칭 병합 범위, 입력 오류 기준, 이상 거래 제외, 구간별 최소 표본, 수량가중 평균 제공 여부.

**인수 조건**: fixture 5종의 핵심 숫자가 화면·견적 검토·Excel에서 일치(또는 차이 기록). 다음 Phase가 쓸 데이터 계약 존재. 금지어 목록 확장 테스트.
**산출물**: `docs/metrics/price.md`, 경로 인벤토리, fixture·테스트, `docs/handoffs/HANDOFF_P0.md`.

### Phase P3. 기간별 가격 변동 및 제품군 시장 요약
**동일 모델 그래프**: 구간별 중앙값 점 + 최저~최고(또는 검증된 분위) 범위 + 구간 건수. 표본 부족 구간은 추세에서 제외, 빈 기간을 0원으로 잇지 않음, 선으로 잇지 않음.
**구간 선택(결정적, 캡션에 표기)**: 월별(모든 월 구간 n ≥ 최소치) → 분기별 → 연도별 순으로 조건을 만족하는 가장 촘촘한 단위. 최소치는 P0에서 확정(초기값 3). 캡션 예: `분기별 · 구간당 거래 3건 이상인 단위`.
**비교 선**: 제품군을 같은 그래프에 넣을 때는 점선·별도 영역·`다른 모델 포함 참고 시세` 라벨. 단위·제외 규칙이 다르면 합치지 않음.
**제품군 요약**: 중앙가격, 가격 계산 사용 건수, 거래 확인 모델 수, 납품업체 수, 거래 건수 상위 5, 납품 기관 수 상위 5. 표현 예: `최근 3년 거래 건수가 가장 많은 모델 — NT-381.B · ㈜나눔테크 · 500건 · 납품 기관 00곳 · 중앙값 1,540,000원`.
**인수 조건**: 희소 모델에서 거짓 추세 문장 없음 / 검색 모델이 제품군 목록에서 강조 / 동일 모델·제품군 시각·문구 구분 / 그래프와 같은 내용을 표·텍스트로 확인 / 전체 모델 목록은 접힘.
**산출물**: 밀집·희소·거래 없음 캡처, 그래프 데이터 테스트, `HANDOFF_P3.md`.
