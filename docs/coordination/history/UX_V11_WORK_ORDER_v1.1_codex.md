# 병원 구매정보 도우미 UX 개선 작업지시서 v1.1

- 작성일: 2026-10-12
- 상태: 2차 외부 리뷰 요청용 초안
- 기준 저장소: `dekt-oss/price-check-assistant`
- 구현 시작 조건: 본 문서 리뷰 승인 및 공통 기준 커밋 확정
- 주의: 이 문서는 구현 지시서이며, 현재 코드가 이미 제공하는 기능은 중복 구현하지 않는다.

---

## 1. 작업 목적

현재 서비스는 나라장터 거래가격, 식약처 의료기기 정보, 병원 뉴스, 병원 회계·병상 자료를 폭넓게 제공한다. 이번 개선의 목적은 기능을 더 많이 추가하는 것이 아니라, 사용자가 다음 질문의 답을 더 빠르고 안전하게 이해하도록 만드는 것이다.

1. 받은 견적이 과거 동일 모델 거래와 비교해 어느 위치인가?
2. 비교에 사용한 거래가 충분하고 최신인가?
3. 동일 모델과 같은 품목의 다른 모델은 가격이 어떻게 변했는가?
4. 오늘 먼저 확인해야 할 병원 뉴스 이슈는 무엇인가?
5. 공개 회계자료에서 우리 병원이 비교군과 크게 다른 지표는 무엇인가?

서비스는 구매 적정성, 제품 대체 가능성, 안전성, 경영 원인을 확정적으로 판정하지 않는다. 데이터가 부족하거나 조건이 다르면 결론을 만들지 않고 `비교 근거 부족` 또는 `추가 확인 필요`로 표시한다.

---

## 2. v1.0 대비 주요 변경

Claude 1차 리뷰에서 타당하다고 판단한 사항을 다음과 같이 반영한다.

1. `구매 판단 카드`를 `거래가 비교 결과`로 변경한다.
2. `적정·비싸다·구매 권장·절감액·대체 가능` 같은 확정적 표현을 결과 판정에 사용하지 않는다.
3. 화면 작업 전에 가격 지표 정의와 현재 구현 중복 여부를 먼저 확인한다.
4. 동일 모델 거래와 제품군 참고 시세를 같은 결론처럼 노출하지 않는다.
5. 검색 성능을 차가운 상태, 따뜻한 상태, 선택형 외부 조회로 분리해 측정한다.
6. 가격 그래프는 거래 밀도에 따라 월·분기·연 단위를 선택하고, 표본이 부족하면 추세를 만들지 않는다.
7. 제품군 평균은 기본 결론에서 제외한다. 필요하면 상세 영역에 수량가중 평균으로만 제공한다.
8. 뉴스 주요 이슈는 기사 제목·매체·링크·시각·키워드만 사용하는 결정적 규칙으로 만든다.
9. 경영 브리핑에는 회계연도와 비교군 수를 항상 표시하고 원인을 단정하지 않는다.
10. 가격 트랙과 뉴스·경영 트랙을 별도 워크트리와 파일 소유권으로 분리한다.

## 3. 공통 제품 원칙

### 3.1 결과보다 근거가 먼저 무너지지 않게 한다

모든 주요 수치에는 가능한 범위에서 다음 네 가지를 함께 표시한다.

- 비교 건수
- 비교 기간
- 가격 계산에 사용한 단위
- 자료 기준일

VAT, 설치, 옵션, 보증, 교육, 유지보수 조건이 확인되지 않은 경우 이를 숨기지 않는다.

### 3.2 동일 모델과 제품군을 분리한다

- `동일 모델 거래`: 식약처 identity 또는 검증된 별칭으로 같은 모델임을 확인한 거래
- `제품군 참고 시세`: 같은 식약처 품목 또는 검증된 나라장터 세부품명에 속한 다른 모델을 포함한 거래

동일 모델 거래가 충분한 경우 제품군 값은 결과 결론에 사용하지 않는다. 동일 모델 거래가 없거나 부족한 경우에만 제품군 값을 `다른 모델을 포함한 참고 시세`로 설명한다.

### 3.3 평균보다 중앙값을 우선한다

- 기본 대표값: 중앙값
- 산술평균: 사용하지 않는다.
- 수량가중 평균: 상세 분석에서만 검토할 수 있다.
- 중앙값과 수량가중 평균의 차이가 크면 묶음·옵션·이상 거래 영향을 안내한다.

### 3.4 빈 결과와 실패를 정상 상태로 설계한다

다음 상태를 별도 UI 상태로 정의하고 임의의 결론을 만들지 않는다.

- 앱 또는 인덱스 준비 중
- 동일 모델 거래 0건
- 동일 모델 거래 1~2건
- 단위 혼합
- 식약처 identity 미확인
- 실시간 보강 실패
- 자료 기준일 지연
- 뉴스 수집 실패 또는 인증 실패
- 경영 비교군 유효값 부족

### 3.5 확정 판정 금지 범위

결과 판정 문구에는 다음 표현을 사용하지 않는다.

- 적정 가격
- 구매 권장 또는 구매 비권장
- 싸다 또는 비싸다
- 확정 절감액
- 대체 가능 제품
- 안전한 제품
- 경영 악화 원인 확정

단, `적정 여부를 판단하지 않습니다`, `대체 가능성을 판단하지 않습니다` 같은 주의문까지 단순 문자열 검사로 차단하지 않는다. 금지 문맥은 결과 판정과 행동 권고 문구를 대상으로 계약 테스트한다.

## 5. 워크트리 및 브랜치 운영 규칙

### 5.1 구현 시작 전 Gate 0

1. PR #341의 병합 또는 종료 상태를 먼저 확정한다.
2. 두 트랙이 시작할 공통 `BASE_SHA`를 하나만 선택한다.
3. `docs/coordination/UX_V11_BASE.md`에 다음을 기록한다.
   - BASE_SHA
   - 기준 브랜치
   - 시작 시각
   - Track A 브랜치와 워크트리
   - Track B 브랜치와 워크트리
   - 통합 담당자
4. 두 워크트리는 반드시 같은 BASE_SHA에서 생성한다.
5. A0와 B0 조사 결과를 바탕으로 실제 수정 파일의 경로별 허용목록을 작성하고, A1·B1 구현 전에 통합 담당자가 승인한다.
   - `src/purchase_price/**`, `tests/**`처럼 넓은 디렉터리 단위 소유는 허용하지 않는다.
   - 같은 기존 파일이 두 트랙에 필요하면 한 트랙만 소유하거나 통합 전용 파일로 지정한다.
   - 승인된 허용목록 밖의 파일은 직접 수정하지 않고 HANDOFF에 변경 요청을 남긴다.

### 5.2 전용 브랜치

- Claude: `claude/ux-v11-price`
- Codex: `codex/ux-v11-news-management`
- 통합: `codex/ux-v11-integration`

브랜치가 이미 존재하면 재사용 여부를 먼저 확인한다. 이름이 비슷해도 다른 작업의 기존 워크트리는 사용하지 않는다. 특히 현재 `.worktrees/claude-price`는 다른 브랜치에 연결되어 있으므로 이번 작업에 재사용하지 않는다.

### 5.3 간섭 방지 규칙

- 각 트랙은 자신의 워크트리 안에서만 작업한다.
- 다른 트랙의 브랜치로 직접 커밋하지 않는다.
- 공통 파일 변경을 이유로 상대 트랙의 파일을 임의 수정하지 않는다.
- 테스트 fixture도 트랙별 디렉터리 또는 명확한 접두어를 사용한다.
- 각 Phase는 독립 PR 또는 독립 커밋 묶음으로 종료한다.
- 한 Phase가 완료되기 전에 다음 Phase의 대규모 구현을 섞지 않는다.
- 통합 브랜치는 두 트랙의 승인된 커밋만 가져온다.

## 6. Track A 세부 작업 — Claude

### Phase A0. 현재 구현 조사 및 가격 지표 계약

#### 목적

이미 운영 중인 가격 결과, 기간 선택, 제품군 시세, 견적 비교를 중복 구현하지 않고 모든 가격 숫자의 기준을 하나로 맞춘다.

#### 포함

- 현재 가격 계산·렌더링·Excel 경로 목록 작성
- 각 경로의 중앙값, 건수, 단위, 이상치, 기간 계산 차이 비교
- `docs/metrics/price.md` 작성
- 가격 결과 데이터 계약 작성
- 골든 fixture 최소 5종 작성
  - 거래 다수·단일 단위
  - 거래 다수·단위 혼합
  - 거래 1~2건
  - 거래 0건
  - 입력 오류·이상 거래 포함

#### 가격 지표의 잠정 원칙

- 동일 모델 중앙값: 최종 변경차수, 유효 단가, 선택 기간, 선택 단위에 해당하는 동일 모델 거래의 중앙값
- 거래 건수: 전체 확인 건수와 실제 가격 계산 사용 건수를 분리 표시
- 총 수량: 단위가 확정된 경우에만 병기
- 제품군 중앙값: 다른 모델을 포함하는 참고 시세이며 동일 모델 결과와 분리
- 제품군 평균: 기본 제공하지 않음. 수량가중 평균 제공 여부는 fixture 검증 후 결정
- 견적 차이: 부호가 있는 `중앙값 대비 차이`로 표시
- 기관 수: 기관코드 또는 검증된 별칭 매핑 우선. 편집거리만으로 자동 병합하지 않음
- 상위 모델: 거래 건수와 납품 기관 수를 함께 표시하며 `인기`, `품질`, `권장`으로 표현하지 않음

#### 미확정 항목

다음 항목은 데이터 감사 후 확정한다.

- 제품군과 나라장터 세부품명 매핑 규칙
- 모델 별칭 병합 범위
- 입력 오류 판정 기준
- 이상 거래 제외 기준
- 기간별 최소 표본 수
- 수량가중 평균의 제공 여부

#### 인수 조건

- 화면·견적 검토·Excel에서 같은 fixture의 핵심 숫자가 일치한다.
- 기존 구현과 새 계약이 다른 경우 차이를 문서에 모두 기록한다.
- 숫자 차이를 숨기기 위해 기존 결과를 억지로 맞추지 않는다.
- 다음 Phase가 사용할 dataclass 또는 동등한 명시적 데이터 계약이 있다.

#### 산출물

- `docs/metrics/price.md`
- 가격 계산 경로 인벤토리
- 골든 fixture와 테스트
- `docs/handoffs/HANDOFF_A0.md`

### Phase A1. 거래가 비교 결과 카드

#### 목적

사용자가 상세 표를 읽기 전에 동일 모델 거래와 견적가의 위치를 이해하도록 한다.

#### 기본 구성

1. 결과 상태
   - 거래 범위 안
   - 확인 필요
   - 비교 근거 부족
   - 동일 제품 확인 필요
2. 내 견적가
3. 동일 모델 거래 중앙값
4. 중앙값 대비 차이와 비율
5. 가격 계산 사용 건수와 제외 건수
6. 기간·단위·최근 거래일·자료 기준일
7. VAT·설치·옵션 조건 미확인 안내
8. 근거 수준과 이유

#### 근거 수준

숫자형 점수를 사용하지 않는다. `높음·보통·제한적`과 판정 이유를 함께 표시한다. 세부 기준은 Phase A0의 실제 데이터 분포를 확인한 후 확정한다.

#### 행동 버튼

- 최근 원문 3건 비교
- 납품업체 확인
- 근거자료 저장
- 허가·회수 상세 확인

#### 제품군 표시 규칙

- 동일 모델 거래가 충분하면 제품군 시세를 결과 카드에 표시하지 않는다.
- 동일 모델 거래가 부족하거나 없으면 다음과 같이 안내한다.
  - `이 모델의 직접 비교 거래가 부족합니다.`
  - `아래 값은 같은 품목의 다른 모델을 포함한 참고 시세입니다.`

#### 인수 조건

- 사용자가 스크롤하지 않고 결과 상태와 근거를 확인할 수 있다.
- 거래 0건·1~2건·단위 혼합·identity 미확인 상태가 각각 다르게 표시된다.
- 결과 판정에 확정적 구매 권고 표현이 없다.
- 동일 모델 값과 제품군 값이 같은 시각적 계층으로 보이지 않는다.
- 견적가 변경 시 비교 결과가 즉시 갱신된다.

#### 산출물

- 상태별 화면 캡처
- AppTest 및 계약 테스트
- `docs/handoffs/HANDOFF_A1.md`

### Phase A2. 검색 성능 측정 및 개선

#### A2a. 측정과 단계별 표시

먼저 다음 시간을 분리해 측정한다.

- 앱 초기 진입 가능 시점
- 인덱스 준비 완료
- 제품 identity 확인
- 동일 모델 거래 요약 완료
- 결과 카드 표시
- 제품군 분석 완료
- 선택형 외부 조회 완료

성능을 다음 상태로 나눈다.

- 차가운 상태: 앱 재시작 또는 로컬 인덱스 없음
- 따뜻한 상태: 인덱스 준비 완료
- 선택형 외부 조회: 식약처 상세, 입찰·계약자료 등

#### 로딩 UX

- 1초 안에 검색 시작 또는 현재 준비 단계를 표시한다.
- `제품 확인 → 동일 모델 거래 → 제품군 참고자료 → 허가·안전` 순서를 표시한다.
- 먼저 준비된 핵심 결과를 보여주고 상세 자료는 지연 표시한다.
- 예상시간이 긴 기능에는 예상 범위를 안내한다.
- 실패한 데이터 소스 때문에 이미 준비된 결과를 숨기지 않는다.

#### A2b. 병목에 따른 구조 개선

A2a 측정 결과에 따라 다음 중 필요한 것만 적용한다.

- GitHub Actions에서 모델별·제품군별 작은 요약 파일 사전 생성
- R2 요약 파일 우선 조회
- 큰 인덱스 지연 로딩
- 불필요한 외부 조회 버튼 뒤로 이동
- 캐시 키와 무효화 조건 정리

앱 메모리 사용량을 늘리는 사전집계는 피한다. 사전계산을 도입하면 전체 인덱스 결과와 수치가 일치하는지 계약 테스트한다.

#### 잠정 성능 목표

목표는 운영 측정 후 확정한다. 초기 검토 기준은 다음과 같다.

- 따뜻한 상태: 핵심 결과 카드 중위수 3초 이내
- 따뜻한 상태: 기본 결과 중위수 10초 이내
- 차가운 상태: 10초 이내 진행 상태 표시
- 선택형 외부 조회: 예상시간 사전 안내 및 별도 실패 처리

#### 인수 조건

- 전·후 단계별 시간 분포가 문서화된다.
- 차가운 상태와 따뜻한 상태 결과가 분리되어 있다.
- 피크 메모리가 기존 운영 허용범위를 넘지 않는다.
- 검색 중 사용자가 현재 단계를 알 수 있다.
- 상세 조회 실패가 핵심 가격 결과를 지우지 않는다.

#### 산출물

- `docs/performance/UX_V11_PRICE_BASELINE.md`
- 전후 성능 측정표
- 요약 파일 스키마가 도입된 경우 해당 문서
- `docs/handoffs/HANDOFF_A2.md`

### Phase A3. 기간별 가격 변동 및 제품군 시장 요약

#### 동일 모델 가격 그래프

- 기본 통계: 구간별 중앙값
- 보조 범위: 최저~최고 또는 검증된 분위 범위
- 각 구간에 거래 건수 표시
- 표본이 부족한 구간은 추세선에서 제외
- 빈 기간을 0원으로 연결하지 않음

#### 구간 선택 규칙

- 월별: 월별 표본이 충분한 밀집 모델
- 분기별: 월별은 부족하지만 분기 표본은 충분한 모델
- 연도별: 희소 모델
- 구간 최소 표본은 Phase A0 데이터 감사 후 확정

#### 비교 선

동일 모델과 제품군 참고 시세를 같은 그래프에 표시할 경우 다음을 지킨다.

- 동일 모델은 주 강조색
- 제품군은 `다른 모델 포함 참고 시세` 점선 또는 별도 영역
- 단위와 제외 규칙이 다르면 한 그래프에 합치지 않음

#### 제품군 시장 요약

- 제품군 중앙가격
- 가격 계산 사용 건수
- 거래가 확인된 모델 수
- 납품업체 수
- 거래 건수 상위 모델 5개
- 납품 기관 수 상위 모델 5개

표현 예시:

> 최근 3년 거래 건수가 가장 많은 모델  
> NT-381.B · ㈜나눔테크 · 500건 · 납품 기관 000곳 · 중앙값 1,540,000원

`가장 인기 있는 모델`, `대표 모델`, `추천 모델`로 표현하지 않는다.

#### 인수 조건

- 거래가 희소한 모델에서 거짓 추세 문장이 생성되지 않는다.
- 검색 모델이 제품군 목록에서 명확히 강조된다.
- 동일 모델과 제품군 참고 시세가 시각·문구로 구분된다.
- 그래프와 동일한 내용을 표 또는 텍스트로 확인할 수 있다.
- 전체 모델 목록은 접힌 상세 영역에 둔다.

#### 산출물

- 밀집·희소·거래 없음 모델 화면 캡처
- 그래프 데이터 테스트
- `docs/handoffs/HANDOFF_A3.md`

### Phase B1. 병원 뉴스 주요 이슈

#### 목적

전체 기사보다 먼저 사용자가 확인할 주요 이슈 최대 5개를 보여준다.

#### 사용할 수 있는 데이터

- 기사 제목
- 링크
- 매체 또는 도메인
- 발행 시각
- 매칭 키워드와 키워드 그룹

본문, 검색 API description, AI 요약, 감성 분석은 사용하지 않는다.

#### 이슈 그룹화

다음 기준은 초기 가설이며, 실제 기사 표본 평가 후 확정한다.

- 정규화한 제목 토큰 유사도
- 일정 시간 범위 안의 기사
- 서로 다른 매체 수
- 우리 병원·경쟁병원·정책·안전 키워드 그룹

`72시간`, `Jaccard 0.6` 같은 숫자는 구현 전 확정하지 않는다. 최소 30~50개 기사 표본으로 잘못 묶인 이슈와 누락 이슈를 평가한다.

#### 화면 구성

- 제목: `오늘의 주요 이슈`
- 최대 5개
- 이슈 제목
- 관련 병원·분류
- 서로 다른 매체 수
- 관련 기사 수
- 최초·최근 보도 시각
- 대표 기사 링크
- `관련 기사 N건` 접기

#### 키워드 설정과 알림 안내

- 기존 키워드 설정 기능이 확인되면 주요 이슈 상단에서 바로 진입할 수 있는 간단한 설정 동선을 제공한다.
- 기존 기능이 없다면 이번 Phase에서 발송 기능을 새로 만들지 않고, 키워드 설정 요구사항과 저장 위치를 B0 산출물에 먼저 기록한다.
- 문자·이메일 알림은 `준비 중` 배지와 짧은 안내만 표시한다.
- 실제 SMS·이메일 발송, 수신자 저장, 동의·수신 거부, 외부 발송 서비스 연동은 이번 범위에서 제외한다.

#### 중요도 원칙

- 우리 병원 직접 언급
- 회수·판매중지·규제 등 위험 키워드
- 서로 다른 매체의 반복 보도
- 최근성
- 의료 전문매체 또는 지역 주요 매체
- 사용자 중요 키워드

기사 수만으로 중요도를 결정하지 않는다.

#### 전체 기사 목록

주요 이슈 아래에 유지한다.

- 주요 이슈
- 우리 병원
- 경쟁병원
- 정책·안전
- 전체 기사

#### 인수 조건

- 같은 사건의 반복 기사가 기본 화면에서 하나의 이슈로 보인다.
- 서로 다른 사건이 잘못 묶이는 비율을 표본 평가로 기록한다.
- B0에서 존재가 확인된 기존 알림·일일 요약 동작과 준비 중 안내를 깨뜨리지 않는다.
- 미구현 상태에서 문자·이메일 알림이 이미 제공되는 것처럼 보이지 않는다.
- 인덱스 이전 버전을 읽을 수 있거나 명시적 마이그레이션이 있다.
- 본문·description·AI를 사용하지 않는 계약 테스트가 통과한다.
- 뉴스가 없거나 수집에 실패해도 다음 행동이 안내된다.

#### 산출물

- 뉴스 군집 표본 평가 문서
- 주요 이슈 화면 캡처
- `docs/handoffs/HANDOFF_B1.md`

### Phase B2. 병원 경영 브리핑

#### 목적

사용자가 표와 그래프를 읽기 전에 최신 공개 회계연도의 주요 차이를 이해하도록 한다.

#### 브리핑 첫 줄

항상 다음 정보를 포함한다.

> 2024 회계연도 공시 기준 · 비교병원 4곳

회계연도와 현재 병상수의 기준일이 다르면 분리 표기한다.

#### 브리핑 구성

- 비교군보다 차이가 큰 지표 최대 3개
- 최근 연도 변화가 큰 지표 최대 2개
- 유리·불리 같은 가치판단보다 수치 차이를 우선
- 비교군 유효값이 부족하면 `비교 보류`
- 원인 대신 추가 확인이 필요한 자료를 안내

표현 예시:

> 의료수익 증가율은 비교군 평균보다 8.8%p 낮습니다.  
> 인건비율은 비교군 평균보다 2.8%p 높습니다.  
> 병상당 의료수익은 비교군 평균보다 6.1% 높습니다.

추가 확인 예시:

- 의료수익 변화는 환자 수, 진료단가, 환자구성 자료를 추가 확인해야 합니다.
- 인건비율 차이는 부서별 인력과 인건비 자료를 추가 확인해야 합니다.

#### 금지

- 특정 원인을 데이터 없이 확정
- 개선 필요, 우수, 부진 등 가치평가를 자동 생성
- 현재 연도 수치처럼 표현
- 비교군 3곳 미만인 지표를 대표 결론으로 사용

#### 화면 정보 계층

1. 경영 브리핑
2. 핵심 지표 요약
3. 의료수익·의료이익률 그래프
4. 비용 구조 상세
5. 전체 지표와 자료 상태

AI 설명은 필수 기능이 아니다. 운영에서 사용할 수 없으면 설정 부족 문구를 사용자에게 노출하지 않고 결정적 브리핑만 제공한다.

#### 인수 조건

- 모든 브리핑에 회계연도와 비교병원 수가 있다.
- 원인 단정 문구가 없다.
- 비교군 부족 상태가 `비교 보류`로 표시된다.
- 화면 브리핑과 다운로드 리포트의 수치가 일치한다.
- 브리핑 없이도 기존 상세 지표 기능이 유지된다.

#### 산출물

- 병원·비교군별 브리핑 예시
- 결정적 문장 테스트
- `docs/handoffs/HANDOFF_B2.md`

통합 단계에서만 다음을 검토한다.

- 오늘 확인할 뉴스 주요 이슈 수
- 최근 가격 조사 또는 저장된 비교 결과
- 최신 경영 브리핑 상태
- 전체 카드 클릭 이동

트랙 구현 중 홈을 동시에 수정하지 않는다.

### 통합 인수 조건

- 가격, 뉴스, 경영 메뉴가 서로의 상태를 깨뜨리지 않는다.
- 각 트랙 단독 테스트와 전체 테스트가 모두 실행된다.
- 1440px, 1024px, 390px에서 핵심 결론을 읽을 수 있다.
- 키보드로 주요 이동·필터·접기·버튼을 사용할 수 있다.
- 그래프의 핵심 숫자를 텍스트나 표로도 확인할 수 있다.
- URL에 보존하기로 한 검색어·기간·필터 상태가 새로고침 후 유지된다.
- 앱 준비 중, 빈 결과, 외부 조회 실패 상태를 실제로 확인한다.

## 9. 단계별 HANDOFF 규격

각 Phase 종료 시 `docs/handoffs/HANDOFF_<PHASE>.md`를 작성한다.

필수 항목:

1. 기준 커밋과 작업 브랜치
2. Phase 목적
3. 완료한 요구사항
4. 변경 파일 목록
5. 데이터 계약 또는 API 변경
6. 실행한 테스트와 실제 결과
7. 미검증 항목
8. 알려진 위험
9. 다음 Phase 시작 지점
10. 재현 명령
11. 화면 캡처 또는 결과 예시 경로
12. 다른 트랙에 필요한 공통 파일 변경 요청

작업 한도에 도달하면 완료로 표시하지 않는다. 위 형식으로 현재 상태와 정확한 재개 지점을 남긴다.

## 10. 우선순위

### Must

- Gate 0 공통 BASE_SHA와 워크트리 분리
- Phase A0 가격 지표 계약과 기존 기능 조사
- Phase A1 거래가 비교 결과 카드
- Phase A2a 성능 측정과 단계별 로딩
- Phase B0 뉴스·경영 현재 구현 조사
- Phase B1 뉴스 주요 이슈
- Phase B2 경영 브리핑
- 동일 모델과 제품군 참고 시세 분리
- 모든 주요 수치의 건수·기간·단위·기준일 표기

### Should

- Phase A2b 사전 요약 파일
- Phase A3 거래 밀도 기반 가격 그래프
- 제품군 상위 거래 모델·기관 수 비교
- 뉴스 군집 표본 평가 자동화
- 다운로드 자료와 화면 수치 일치 테스트
- 자료 기준일 지연 경고

### Could

- 제품군 수량가중 평균 상세 제공
- 관심 모델 가격·허가·회수 감시
- 분기 단위 가격 그래프
- AI 경영 참고 해석
- 모바일 전용 카드 레이아웃

### 이번 범위에서 제외

- 산술평균을 대표 가격으로 표시
- 숫자형 신뢰도 점수
- 확정 절감액
- 제품 대체 가능 판정
- 뉴스 본문 또는 AI 요약
- 경영 원인 자동 확정
- 편집거리만으로 기관·모델 자동 병합
- 앱 메모리에 대규모 인덱스 중복 적재

## 11. 2차 리뷰 요청사항

리뷰어는 다음 사항을 우선 확인한다.

1. Track A와 Track B의 파일 소유권이 실제 저장소 구조에서 충분히 분리되는가?
2. Phase A0 없이 시작하면 안 되는 가격 기능이 더 있는가?
3. 거래가 비교 결과의 상태 문구가 구매 적정성 판정으로 오해될 가능성이 남아 있는가?
4. 동일 모델과 제품군 참고 시세의 노출 규칙이 충분히 명확한가?
5. 성능 목표가 측정 가능한 형태이며 차가운·따뜻한 상태가 적절히 분리됐는가?
6. 가격 그래프의 동적 월·분기·연 단위 선택이 거짓 추세를 막을 수 있는가?
7. 뉴스 주요 이슈가 본문·AI 없이도 유용하고 약관에 안전한가?
8. 경영 브리핑이 오래된 공시자료를 현재 상황으로 오해하게 만들지 않는가?
9. 각 Phase가 독립적으로 커밋·테스트·리뷰·재개 가능한가?
10. HANDOFF 문서만으로 다른 AI가 중간부터 작업을 이어갈 수 있는가?

리뷰 단계에서는 구현하지 않는다. Critical/High 문제, 수정 조건, 단계 간 충돌, 검증이 필요한 가정을 우선 보고한다.
