# MFDS 의료기기 시장조사 모듈

## 목적

병원 관리부가 특정 의료장비 구매요청을 검토할 때 처음 영업한 한 업체에 경쟁업체·비교견적 후보까지 다시 요청하는 구조를 줄인다.

가격검색과 별도로 다음 질문에 답하는 기능을 만든다.

1. 이 장비가 식약처에 어떤 품목/모델로 등록되어 있는가?
2. 해당 품목에 등록된 다른 모델은 무엇인가?
3. 제조·수입업체 및 공개 근거로 확인 가능한 공급업체 후보는 누구인가?
4. 해당 제품/품목에 회수·판매중지 또는 안전성 정보가 있는가?

최종 구매결정이나 임상적 대체 가능성은 자동 판단하지 않는다.

---

## 사용자 업무 흐름

```text
견적서 업로드 또는 모델 직접검색
→ 식약처 등록정보 확인
→ 품목명/허가번호/모델/제조·수입업체 확인
→ 동일 식약처 품목의 다른 등록모델 조회
→ 제조·수입업체 / 실제 공공조달 공급업체 / 공식 판매채널 후보 수집
→ 회수·판매중지·안전성 정보 확인
→ 기존 공개가격 검색결과와 함께 구매검토 화면 표시
```

### 핵심 원칙

- `같은 식약처 품목`은 **경쟁장비 후보군**이지 자동 대체품이 아니다.
- 사용목적 문장이나 주요사양의 유사도만으로 임상적 대체품을 자동 추천하지 않는다.
- 모델명 문자열 부분일치만으로 동일 의료기기로 확정하지 않는다.
- 공급업체 후보는 근거별 등급을 분리한다.
- 안전정보는 가격점수와 합산하지 않고 별도 경고로 표시한다.

## Source 설계

### S1. 식약처 의료기기 표준코드별 제품정보

공식 Source:
`https://www.data.go.kr/data/15073875/openapi.do`

공식 API base:
`https://apis.data.go.kr/1471000/MdeqStdCdPrdtInfoService03`

operation:
`getMdeqStdCdPrdtInfoInq03`

공식 설명에서 확인된 주요 필드:

- UDI-DI
- 품목명
- 의료기기 분류번호
- 등급
- 품목허가번호 / 허가일자
- 모델명
- 제품명
- 사용목적
- 제조·수입 업체명
- 추적관리대상 여부
- 요양급여대상 여부 등

역할:

- 견적서에서 추출한 모델의 공식 등록 identity 확인
- 품목/분류번호를 경쟁장비 탐색의 기준축으로 연결
- 제조·수입업체 후보 확보

주의:

- endpoint 존재와 제공필드는 공식 명세로 확인했다.
- 실제 request filter parameter와 live response field casing은 별도 live smoke로 고정한다.
- live 검증 전에는 추정 parameter를 production 검색에 사용하지 않는다.

### S2. 식약처 의료기기 형명정보

공식 Source:
`https://www.data.go.kr/data/15073899/openapi.do`

API:
`https://apis.data.go.kr/1471000/MdeqModlInfoService01/getMdeqModlInq01`

공식 request 중 이번 기능에서 사용할 수 있는 필드:

- `PRDLST_NM`: 품목명
- `INDT_NM`: 업종
- `INST_AREA_DIVS_NM`: 기관지역구분
- `pageNo`
- `numOfRows`

공식 response 주요 필드:

- `MDEQ_PRDLST_SN`: 의료기기품목일련번호
- `INDT_NM`: 업종
- `PRMSN_DCLR_DIVS_NM`: 허가신고구분
- `MEDDEV_ITEM_NO`: 의료기기품목허가번호
- `PRDLST_NM`: 품목명
- `PRMSN_YMD`: 허가일자
- `RTRCN_DSCTN_DIVS_CD`: 취소/취하구분
- `DSCTN_RTRCN_YMD`: 취소취하일자
- `PRDT_NM_INFO`: 상품명
- `TYPE_INFO`: 형명/모델
- `EXPORT_YN`: 수출용 여부

역할:

- 공식 품목명이 확정된 뒤 같은 품목의 등록 모델 후보를 조회
- 취소/취하 및 수출전용 모델은 일반 경쟁후보에서 별도 표시

### S3. 식약처 의료기기 제조·수입업 허가정보

공식 Source:
`https://www.data.go.kr/data/15057971/openapi.do`

API:
`https://apis.data.go.kr/1471000/MdlpMnfcturPrmisnInfoService01/getMdlpMnfcturPrmisnList01`

공식 request:

- `Entrps`: 업체명
- `Induty_type`: 업종구분
- `Prmisn_dt`: 허가일자
- `Meddev_entp_no`: 업허가번호

공식 response:

- `ENTRPS`: 업소명
- `INDUTY_TYPE`: 제조업/수입업/수리업/판매업/임대업 등
- `BIZ_STTUS`: 폐업/휴업/재개/취소 등
- `PRMISN_DT`: 허가일자
- `ADRES1`, `ADRES2`: 업소주소
- `MEDDEV_ENTP_NO`: 업허가번호

역할:

- 후보 업체가 실제 의료기기 관련 허가업체인지 확인
- 제조/수입/판매/임대업 구분 및 휴폐업 상태 표시

### S4. 식약처 의료기기 회수·판매중지정보

공식 Source:
`https://www.data.go.kr/data/15056785/openapi.do`

공식 제공항목에는 다음이 포함된다.

- 제조·수입업체명
- 품목명
- 품목허가번호
- 등급
- 모델명
- 제조번호 / 제조일자
- 판매중지·회수 사유
- 공표·명령일

역할:

- exact 모델/허가번호 hit를 최우선 안전경고로 표시
- 모델이 없으면 품목/업체 수준 hit는 `품목 수준 경고`로 분리
- 가격평가 점수에 섞지 않음

### S5. 식약처 의료기기 안전성서한

식약처 위해정보 공식 페이지:
`https://www.mfds.go.kr/brd/m_550/list.do`

역할:

- 장비 품목 관련 안전성서한 존재 여부를 참고경고로 표시
- 회수·판매중지와 별도 Evidence type으로 취급
- 초기에는 공식 링크 기반 검색/표시를 우선하고, 구조적 API가 별도로 확인될 때 adapter로 분리

## 경쟁장비 후보 기준

### 자동 후보로 허용

식약처 공식정보에서 **동일 `PRDLST_NM` 또는 검증된 동일 분류번호**에 속하는 다른 등록 모델.

화면 라벨은 `동일 식약처 품목 등록모델`로 한다.

이 라벨은 다음을 의미하지 않는다.

- 임상적으로 완전 대체 가능
- 동일 성능
- 동일 옵션/구성
- 동일 수가/급여 조건
- 동일 설치환경

### 이번 단계에서 자동 후보로 금지

- 사용목적 자연어가 비슷하다는 이유만으로 다른 품목을 후보화
- 주요사양 수치가 비슷하다는 이유만으로 다른 품목을 후보화
- LLM/embedding 유사도만으로 경쟁장비 판정
- 제조사 마케팅 문구만으로 대체품 판정

필요하면 이후 사람이 `기능적 대체 후보(D)`로 직접 큐레이션한다.

## 공급업체 후보 등급

### A. 규제상 공식업체

식약처 제품정보 또는 품목허가에 연결된 제조·수입업체.

표시:
`식약처 제조/수입업체`

### B. 실제 공공조달 공급업체

기존 G2B Shopping/향후 계약정보 source에서 동일 모델 또는 검증된 동일제품을 실제 공급한 업체.

표시:
`공공조달 공급실적 확인`

단, 한 번의 납품실적이 현재 공식 총판관계까지 의미하지는 않는다.

### C. 공식 판매채널

제조사 공식 홈페이지에서 확인되는 공식 대리점·총판·파트너.

표시:
`제조사 공식 판매채널`

### D. 일반 웹 판매업체

공식 관계를 검증하지 못한 판매업체.

초기 production-like 화면의 기본 공급사 후보에는 포함하지 않고 참고/검토 큐로 분리한다.

## 안전정보 표시 규칙

### RED

- exact 모델 또는 동일 품목허가번호의 회수/판매중지 hit

### AMBER

- 동일 품목명/업체 수준 회수정보지만 exact 모델 연계가 미확정
- 관련 식약처 안전성서한 존재

### NONE

- 검색범위 내 공식 hit 없음

중요:
`NONE`은 안전하다는 보증이 아니라 `연결된 공식 source에서 현재 hit를 찾지 못함`을 뜻한다.

## Streamlit UI 목표

새 페이지 이름 후보:
`의료기기 시장조사`

입력:

- 모델명
- 품목명(알면 입력)
- 제조사/현재 업체(선택)

출력 블록:

1. **식약처 등록정보**
   - 품목 / 모델 / 허가번호 / 등급 / 제조·수입업체 / 상태
2. **동일 품목 등록장비**
   - 다른 모델 / 상품명 / 허가번호 / 허가일 / 취소취하여부
3. **공급업체 후보**
   - 업체명 / 근거등급 / 허가업종 / 상태 / 조달실적 근거
4. **안전정보**
   - 회수·판매중지 / 안전성서한
5. **가격근거**
   - 기존 제조사/G2B 가격검색 결과 재사용

## 비용 원칙

핵심 경로는 AI 없이 동작한다.

- Excel 구조 파싱: 로컬 Python
- MFDS: 공공데이터 API
- G2B: 공공데이터 API
- 가격 계산/매칭: 로컬 Python

LLM은 추후 문서 필드가 모호하거나 사용자에게 설명을 생성할 때만 optional fallback으로 검토한다.
LLM이 없어도 제품등록/동일품목 후보/업체허가/안전정보/가격근거 기능은 동작해야 한다.

## 비목표

- 임상 적합성 자동판정
- 의료진 의사결정 대체
- 동일 품목이라는 이유만으로 최저가 장비 구매 권고
- 비공개 유통망/거래조건 추정
- 공급업체와 공식 총판관계 추정
- AI가 근거 없는 경쟁제품/업체 생성

## 검증 원칙

1. API 명세와 live response가 다르면 live 근거를 기록하고 parser를 수정한다.
2. 서비스키 권한이 없는 source는 `미연결`로 표시하며 빈 검색결과로 위장하지 않는다.
3. exact model 미확인 시 같은 제품으로 표시하지 않는다.
4. 동일 식약처 품목은 `경쟁 후보`로만 표시한다.
5. 회수/판매중지 hit는 가격상 이점보다 우선해 화면 상단에 안전경고로 노출한다.
