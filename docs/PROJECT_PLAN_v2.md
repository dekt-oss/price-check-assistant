# 관리부 구매가격 검색·검토 보조시스템 구축 기획 v2

## 1. 추진 배경

관리부는 의료장비, 의료기구, 의료비품, 공기구비품, 소프트웨어, 의료장비 유지보수, 전산비품 등 다양한 품목을 구매하고 있다.

구매 검토 과정에서는 현재 제출된 견적가격이 적정한 수준인지 판단하기 위해 과거 자료, 나라장터, 제조사 자료, 공개 판매가격, 유사 공공기관 구매사례 등을 개별적으로 검색해야 한다.

그러나 관련 정보가 여러 사이트와 문서에 분산되어 있어 시장조사에 시간이 많이 소요되고, 검색 결과 역시 담당자가 직접 규격·모델·조건 차이를 비교해야 한다.

이에 병원 ERP·EMR 등 기존 전산시스템을 변경하지 않고, 공개된 외부정보를 자동 수집·정리하여 구매 담당자의 가격 검토를 보조하는 소규모 시스템을 우선 구축하고자 한다.

1차는 공개 웹 기반으로 기능을 검증하고, 실제 활용성이 확인되어 병원 내부 승인을 받은 경우 본원 구매단가 및 내부 견적자료를 연계하는 방식으로 단계적으로 확대한다.

---

# 2. 시스템의 핵심 목적

본 시스템의 핵심 목적은 다음 질문에 빠르게 답할 수 있도록 하는 것이다.

> **“이 제품의 현재 견적가격은 공개적으로 확인 가능한 시장·조달가격과 비교했을 때 어느 수준인가?”**

이를 위해 다음 두 가지 진입방식을 제공한다.

### ① 제품 직접 검색

품목명, 제조사, 모델명, 규격 등을 입력하여 가격자료를 조회한다.

### ② 견적서 업로드

견적서에서 제품명·제조사·모델·규격·수량·가격 등을 추출하고 해당 제품의 외부 가격자료를 자동 검색한다.

최종적으로 시스템은 단순히 가장 낮은 가격을 보여주는 것이 아니라,

- 어떤 자료를 찾았는지
- 동일 제품인지 유사 제품인지
- 조건 차이가 무엇인지
- 현재 견적가격이 비교자료 중 어느 수준인지
- 비교 결과를 얼마나 신뢰할 수 있는지

를 함께 제시한다.

# 3. 기본 원칙

본 시스템은 **구매결정 시스템이 아니라 구매검토 보조도구**로 한정한다.

### 운영 원칙

1. AI가 구매 여부 또는 업체를 결정하지 않는다.
2. 가장 낮은 가격을 자동으로 적정가격이라고 판단하지 않는다.
3. 모델·규격·옵션 등이 다른 제품을 동일 제품으로 자동 간주하지 않는다.
4. 가격에는 반드시 출처와 수집일자를 표시한다.
5. 가격 비교 시 VAT, 설치비, 배송비, 옵션, 보증기간 등 조건 차이를 가능한 범위에서 함께 표시한다.
6. 비교근거가 부족한 경우 임의의 적정가격을 생성하지 않고 **‘비교근거 부족’​**으로 표시한다.
7. 시스템의 최종 판단은 담당자의 원자료 확인을 전제로 한다.

# 5. 핵심 기능

## 5.1 구매가격 통합 검색

품목명, 제조사, 모델명, 규격 등을 검색하면 여러 공개정보에서 가격관련 자료를 수집하여 하나의 화면으로 보여준다.

### 주요 검색 대상

- 나라장터 입찰·계약·조달 관련 공개정보
- 공공기관 구매사례
- 제조사 공개자료
- 공개된 B2B·유통가격
- 일반 공개 판매가격
- 기타 신뢰 가능한 가격자료

모든 출처를 동일한 가격으로 취급하지 않고 자료의 성격을 구분한다.

# 6. 제품 식별 및 비교등급

구매가격 비교에서 가장 중요한 것은 단순한 제품명 검색이 아니라 **동일 제품인지 여부를 정확히 판단하는 것**이다.

예를 들어 같은 제조사의 제품이라도 모델, 크기, 구성품, 옵션 등에 따라 가격 차이가 크므로 비교자료를 다음과 같이 구분한다.

| 등급 | 기준 | 활용 |
|---|---|---|
| **A** | 동일 제조사·동일 모델·동일 규격 | 직접 비교 가능 |
| **B** | 동일 모델이나 옵션·계약조건 일부 차이 | 조건 보정 후 비교 |
| **C** | 동일 제품군·유사규격 | 시장범위 참고 |
| **D** | 기능적으로 유사한 타 제품 | 참고정보 |
| **X** | 동일성 판단 불가 | 가격비교 제외 |

가격분석의 중심은 A·B 등급 자료로 하고 C·D 자료는 참고자료로 별도 표시한다.

# 7. 적정 참고가격대 산정

본 시스템에서 말하는 **적정가격대**는 AI가 임의로 결정하는 가격이 아니다.

동일·유사 제품에서 확보한 실제 가격관측값을 이용하여 **현재 확인 가능한 참고가격 범위**를 계산한다.

예시:

### 검색제품

ABC Medical / XYZ-100

### 현재 견적

**38,500,000원**

### 확인된 가격자료

| 출처 | 가격 | 비교등급 |
|---|---:|---|
| 공공기관 계약 A | 35,800,000원 | A |
| 공공기관 계약 B | 36,400,000원 | A |
| 조달 구매사례 | 36,900,000원 | B |
| 공개 판매가격 | 37,500,000원 | B |
| 유사모델 | 34,000,000원 | C |

### 시스템 표시 예시

**직접 비교자료 가격대**

35.8 ~ 37.5백만원

**현재 견적**

38.5백만원

**비교결과**

직접 비교자료 상단 대비 +1.0백만원

**비교 신뢰도**

높음

**확인 필요**

- 현재 견적에 설치비 포함
- 일부 비교자료는 설치비 포함 여부 미확인
- 무상보증기간 차이 존재

# 8. 가격평가 결과 표현

가격평가 결과는 과도한 단정 표현을 사용하지 않는다.

다음 정도로 표시한다.

### 참고가격대 내

> 현재 견적은 확보된 직접 비교자료 가격범위 내에 위치함.

### 참고가격보다 높은 경우

> 현재 견적은 확보된 직접 비교자료 상단보다 6.2% 높음. 설치·보증·옵션 조건 확인 필요.

### 참고가격보다 낮은 경우

> 현재 견적은 확보된 직접 비교자료 하단보다 8.1% 낮음. 제품구성 및 조건 동일 여부 확인 필요.

### 자료 부족

> 직접 비교 가능한 가격자료가 충분하지 않아 참고가격대 산정 불가.

**‘적정/부적정’, ‘구매 권고/비권고’와 같은 최종 의사결정 문구는 사용하지 않는다.**

# 9. 가격 신뢰도

참고가격대를 제공할 때 반드시 신뢰도를 함께 표시한다.

예:

| 신뢰도 | 기준 예시 |
|---|---|
| 높음 | 동일제품 직접 비교자료 다수 확보 |
| 보통 | 동일제품 자료 일부 + 조건차이 존재 |
| 낮음 | 유사제품 중심 |
| 산정불가 | 비교자료 부족 |

단순히 검색결과가 많다고 신뢰도를 높이지 않고 **동일성·규격·출처·최근성**을 종합하여 판단한다.

### 표시정보

- 제조사
- 제품명
- 모델명
- 회수정보
- 판매중지
- 안전성정보
- 조치일
- 정보 출처

### 예시

동일제품 여부: 확인 필요

안전정보가 확인되더라도 시스템이 자동으로 구매중단을 판단하지 않고 담당자에게 확인 필요사항으로 표시한다.

# 13. 공개 웹 기반 1차 구축

1차는 금리수집기와 유사하게 **공개 웹 서비스 형태로 개발**한다.

목적은 실제 병원 데이터를 바로 사용하기 위한 것이 아니라,

> 공개정보만으로 구매가격 검색과 견적검토 기능이 어느 수준까지 가능한지 먼저 보여주는 것

이다.

### 공개 버전에서 사용하는 데이터

- 공개 조달정보
- 공개 계약정보
- 제조사·유통 가격정보
- 식약처 안전정보
- 샘플 제품
- 샘플 또는 비식별 견적서

### 공개 버전에서 사용하지 않는 데이터

- 실제 본원 구매단가
- 실제 거래업체별 계약단가 DB
- 실제 본원 연간 구매수량
- 내부 결재문서
- 비공개 계약자료

실제 업체 견적서도 병원 내부 승인 전에는 공개 웹 서버에 영구 저장하지 않는 구조를 원칙으로 한다.

# 14. 병원 내부 이식

공개 PoC에서 활용성이 확인되고 내부 승인을 받을 경우 동일 코드베이스를 병원 내부환경으로 이전한다.

내부 버전에서는 향후 다음 기능을 추가할 수 있다.

### 본원 구매이력 연계

현재 견적

vs.

본원 최근 구매가

vs.

본원 과거 가격추이

vs.

외부 공개가격

비교가 가능해진다.

### 내부 확장 후보

- 본원 과거 구매가격
- 업체별 구매가격
- 구매수량
- 가격변동
- 진료재료 간납단가
- 실제 견적서
- 연간 구매금액

ERP와 직접 연동할지는 별도 검토하며 초기에는 Excel 등으로 데이터를 반영하는 방식을 우선 검토한다.

---

# 15. 단계별 추진안

## Phase 0. 데이터 가능성 조사

대표 품목 10~20개를 선정하여 외부 공개가격 수집 가능성을 검증한다.

확인사항:

- 동일제품 식별 가능 여부
- 나라장터 가격자료 존재 여부
- 제조사·유통가격 수집 가능 여부
- 가격조건 비교 가능 여부
- 안전정보 매칭 가능 여부

---

## Phase 1. 공개 구매가격 검색기

제품을 검색하면

- 제품정보
- 공개 가격자료
- 출처
- 가격분포
- 비교등급

을 표시한다.

---

## Phase 2. 참고가격대 분석

동일·유사 제품 분류와 가격조건을 반영하여

- 참고가격대
- 현재가격 위치
- 가격 차이
- 비교 신뢰도

를 표시한다.

---

## Phase 3. 안전·회수정보

의료기기에 대해 식약처 등 공개 안전정보를 자동 연결한다.

---

## Phase 4. 견적서 분석

견적서 업로드

→ 제품정보 자동추출

→ 외부가격 검색

→ 품목별 참고가격대

→ 비교표 생성

기능을 구현한다.

---

## Phase 5. 내부 이식 검토

실제 업무 활용성이 확인되면 내부 승인 후

- 본원 구매이력
- 실제 견적
- 내부 단가정보

를 결합한다.

진료재료 가격분석도 이 단계 이후 별도 확장한다.

---

# 16. 1차 시범사업 성공 기준

기능이 구현됐다는 것만으로 성공으로 판단하지 않는다.

다음 사항을 검증한다.

### 가격검색 성능

대표품목 중 실제 비교 가능한 외부가격을 얼마나 확보할 수 있는가.

### 제품매칭 정확도

동일 모델·유사 모델을 정확하게 구분할 수 있는가.

### 가격분석 신뢰성

비교조건이 다른 가격을 잘못 동일가격으로 판단하지 않는가.

### 견적검토 시간

기존 수작업 시장조사와 비교하여 실제 시간이 단축되는가.

### 업무 활용성

담당자가 실제 구매검토 과정에서 다시 사용할 의사가 있는가.

---

# 17. 기대효과

## 시장조사 시간 단축

여러 사이트를 각각 검색하던 과정을 하나의 검색화면으로 통합한다.

## 가격검토 근거 강화

현재 견적을 단순한 경험이 아니라 외부 가격자료와 비교해 검토할 수 있다.

## 협상자료 확보

비교 가능한 공공계약·공개시장 가격을 가격협상의 참고근거로 활용할 수 있다.

## 견적검토 표준화

담당자에 따라 다르게 수행되는 시장조사와 가격비교 방식을 일정 수준 표준화할 수 있다.

## 정보 축적

개별 담당자의 검색 경험이 아닌 제품·가격 데이터 자체가 지속적으로 축적된다.

## 향후 내부 구매정보 연계 기반 확보

공개정보 기반으로 먼저 시스템을 검증한 뒤 본원 가격정보를 추가하면 더 정교한 구매가격 분석이 가능하다.

---

# 18. 본 사업에서 하지 않는 것

1차 사업에서는 다음 영역을 포함하지 않는다.

- ERP·EMR 연동
- 계약관리
- 재고관리
- 자동발주
- 입찰 자동평가
- 업체 자동선정
- 구매 승인
- 진료재료 가격분석
- 본원 실제 구매단가 공개웹 저장

---

# 19. 최종 목표

본 사업의 최종 목표는 복잡한 병원 구매시스템을 새로 구축하는 것이 아니다.

관리부 직원이 제품을 검색하거나 견적서를 받았을 때,

> **“이 물건이 무엇인지”**

> **“비교 가능한 가격자료가 어디에 있는지”**

> **“현재 견적이 그 자료들과 비교했을 때 어느 수준인지”**

> **“가격 차이가 제품·규격·옵션 차이 때문인지 확인할 필요가 있는지”**

> **“제품과 관련된 안전·회수정보가 있는지”**

를 한 화면에서 빠르게 확인할 수 있도록 하는 것이 목표다.

1차는 공개정보 기반 검색서비스로 효과를 증명하고, 실제 업무효과가 확인되면 병원 내부환경으로 이식하여 본원 구매가격을 결합한다.
