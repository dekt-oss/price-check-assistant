# 화면 와이어프레임 — 시각 명세

`docs/RESTRUCTURE_QUOTE_REVIEW.md`가 **구조**(파일 배치·상태 객체·함수 시그니처)를 정한다면, 이 폴더는 **화면이 어떻게 보여야 하는가**를 정한다. 두 문서가 다르면 구조 문서의 계약이 우선이고, 시각은 이 폴더가 기준이다.

각 `.html`은 독립 실행 파일이다. 브라우저로 바로 열면 되고, 외부 리소스는 Google Fonts 하나뿐이다. 폰트가 없어도 레이아웃은 유지된다.

## 파일

| 파일 | 화면 |
| --- | --- |
| `01-정보구조.html` | 현재 15개 메뉴 → 5개 영역 매핑 |
| `02-대시보드.html` | 진행 중 견적, 시스템 상태, 사람 조사 필요 목록 |
| `03-견적검토-막힌경우.html` | mapping이 없어 판정까지 못 가는 경우 (Flow-C) |
| `04-빠른검색.html` | 견적 없이 근거만 조회 |
| `05-의료기기조회.html` | 식약처 identity → 공급사·경쟁장비·안전·UDI 탭 |
| `06-관리.html` | 근거 레지스트리 · 운영진단 · UAT · 벤치마크 |
| `S1-업로드추출.html` ~ `S6-승인판정.html` | 견적 검토 6단계 |

S1~S6은 같은 견적(레이저프린터 1대, 3,500,000원)이 처음부터 끝까지 흐르는 하나의 시나리오다. 순서대로 열어야 흐름이 보인다.

**화면 속 숫자·업체명은 예시**다. `[ ]`는 자리표시. 실제 데이터로 착각하지 말 것.

## 레이아웃 규칙

**견적 검토(S1~S6)는 3열 고정.** 단계가 바뀌어도 왼쪽·오른쪽은 그대로다.

```
[사이드바 220] [품목 목록 300] [현재 단계 = 가변] [상태·판정 카드 340]
```

- Streamlit에서는 `st.columns([300, 1, 340])` 정도로 근사한다. 픽셀 일치는 목표가 아니다.
- 상단에 6단계 스텝퍼: 완료=초록 원+체크, 현재=파란 테두리+굵게, 미도달=회색.
- **오른쪽 카드는 항상 "지금 상태 + 다음으로 가는 조건"**이다. 조건 목록은 `can_enter()`가 반환한 `reasons`를 번호 매겨 그대로 쓴다. 화면에서 문장을 지어내지 않는다.

다른 화면(대시보드·빠른 검색·의료기기·관리)은 사이드바 + 본문 1열.

## 색 — 상태에만 쓴다

브랜드 색이 아니다. 장식으로 쓰지 않는다.

| 클래스 | 배경 / 글자 | 의미 |
| --- | --- | --- |
| `.ok` | `#e4f2ea` / `#1f5e42` | 완료 · 검증됨 · 일치 |
| `.warn` | `#f7ecd6` / `#7a5410` | **사람이 지금 할 일** (승인 대기, 확인 필요) |
| `.err` | `#f8e1e1` / `#8a2a2a` | 실패 · 차단 · 조건 충돌 |
| `.muted` | `#eeece7` / `#5a5750` | 근거가 없어 멈춘 보류 · 참고용 후보 · 미확인 |
| `.info` | `#e3eef3` / `#1f6f8b` | 중립 정보 |

"보류"가 회색인 것은 의도다 — 노랑(사람이 할 일)과 구별해야 한다. 담당자가 색만 보고 "내가 지금 뭘 해야 하나"를 판단할 수 있어야 한다.

기본 팔레트: 배경 `#f6f5f2`, 카드 `#fff`, 테두리 `#e2dfd8`, 본문 `#1c1b19`, 보조텍스트 `#6b6862`, 강조/링크 `#1f6f8b`.

## 근거와 후보는 절대 같은 모양이 아니다

이 규칙이 이 설계의 핵심이다. `S4-근거수집.html`과 `03-견적검토-막힌경우.html`을 나란히 보면 차이가 보인다.

| | 직접 비교 근거 (A/B) | 미검증 후보 |
| --- | --- | --- |
| 카드 | 실선 테두리, 흰 배경 | **점선** 테두리, `#fbfaf8` 배경 |
| 금액 | 기본 검정 | **회색** `#6b6862` |
| 컬럼명 | `단가` | **`표기 금액 (미검증)`** |
| 기본 상태 | 펼침 | **접힘** |
| 하단 | — | 노란 안내: 검증 전에는 가격범위·견적판정에 쓰지 않음 |

후보 표에는 등급(A/B) 열이 없다. 등급이 없는 자료이기 때문이다.

## 관측 가격은 조건별로 나눠 그린다

`S4-근거수집.html` 오른쪽 카드를 볼 것. VAT 상태가 다른 근거를 **하나의 범위·중앙값으로 합치지 않는다.**

```
나라장터 · 67건   [VAT 미확인]   2,981,000원
FUJIFILM 공식몰 · 1건  [VAT 포함]   5,500,000원
```

`(출처, VAT 상태)`로 묶어 각각 표시한다. 합친 범위는 보고서에서 "참고"로만 쓴다.

## 판정 문구 규칙

`S6-승인판정.html` 참고.

- 승인 근거가 1건이거나 독립 출처가 1개면 **"적정"이라는 단어를 쓰지 않는다.** "승인 근거 대비 위치"로만 쓴다.
- 판정에서 제외된 근거가 있으면 그 사실과 이유를 같은 카드에 쓴다 (예: "나라장터 67건은 조건 미확인으로 제외, 참고 범위로만 보고서에 실림").
- 판정이 보류일 때 오른쪽 카드는 **왜 보류인지 + 판정으로 가는 길**을 번호로 보여준다. `03-견적검토-막힌경우.html` 오른쪽 참고.

## 아이콘

이모지를 쓰지 않는다. 인라인 SVG(stroke 기반, 18~28px, `stroke-width: 2`)만 쓴다. 스텝퍼의 `✓`는 텍스트로 허용.

## 접근성

- 클릭 대상 높이 44px 이상 (`.btn`, `.nav a`)
- 색만으로 상태를 전달하지 않는다 — 칩에는 항상 글자가 함께 있다
- 표의 열 이름은 축약하지 않는다 (`근거ID`, `표기 금액 (미검증)`)

## 이 폴더를 고칠 때

와이어프레임은 구현의 기준이므로, 구현하면서 화면이 달라지면 **여기도 함께 고친다.** 코드와 이 폴더가 다르면 다음 사람이 어느 쪽을 믿어야 할지 모른다.
