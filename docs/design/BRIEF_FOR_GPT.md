# 화면 설계 의뢰 — GPT용

> **쓰는 법:** 이 문서 전체를 ChatGPT에 붙여 넣고, `docs/design/current-screens/`의 그림 8장을 함께 첨부하세요.
> 같은 의뢰를 Claude Design에도 보냅니다. 두 결과를 9장 목차대로 비교해 좋은 부분만 골라 실제 화면에 반영합니다.

## 1. 무엇을 만드는 서비스인가

**병원 구매팀이 받은 견적이 적정한지 공개 자료로 확인하는 웹 도구**입니다. 지금은 내부 시험판(PoC)으로 운영 중이고, 구매팀 팀원에게 공유하기 전에 화면 구성과 사용성을 다듬으려 합니다.

- **주 기능 (구매가격 조사)**
  - 모델명·품목명·업체명 중 하나를 검색하거나, 받은 견적서(PDF·Excel·사진)를 올립니다.
  - 조달청 **나라장터** 쇼핑몰의 실제 거래 기록에서 같은 제품이 얼마에 팔렸는지 보여줍니다. 2021년~현재, 수십만 건입니다.
  - **식약처** 허가정보(허가 여부, 제조·수입업체, 회수 이력)를 함께 보여줍니다.
- **부가 기능 (병원 경영 정보)**
  - **병원 News Radar**: 관심 키워드의 병원 업계 기사 모음과 알림
  - **병원 경영 Benchmark**: 공개 회계자료로 병원끼리 비교
- **운영 환경:** Python **Streamlit 1.63** 웹앱(Streamlit Community Cloud)입니다. 화면은 이 프레임워크로 구현할 수 있어야 합니다(6장 제약 참고).

## 2. 누가, 어떤 상황에서 쓰나

- **사용자:** 병원 구매·자재팀 담당자. 전산 용어에 익숙하지 않고, 하루에 여러 품목을 빠르게 확인합니다. 주로 사무실 PC(1440~1920px)에서 씁니다.
- **대표 상황**
  1. 업체가 "환자감시장치 M40, 1대 650만 원" 견적을 보냈다. 나라장터에서 실제로 얼마에 거래됐는지, 이 가격이 비싼지 알고 싶다.
  2. 견적서 한 장에 품목이 10개 있다. 품목마다 시세를 빨리 훑고, 이상한 품목만 자세히 보고 싶다.
  3. 거래가 하나만 유난히 비싸다(예: 1세트 3,651만 원). 왜 그런지 원문(사업명, 조건)을 확인하고 싶다.
  4. 결과를 Excel로 저장해 결재 문서에 붙인다.
- **성공 기준:** 검색 후 **10초 안에 "이 가격이 적정한가"를 한 문장으로 이해**하고, 근거(거래 목록·원문)는 필요할 때만 펼쳐 봅니다.

## 3. 지금 메뉴와 화면

왼쪽 사이드바 메뉴는 아래와 같습니다. 괄호 안은 첨부 그림 파일입니다.

| 메뉴 | 주요 내용 | 첨부 |
| --- | --- | --- |
| 홈 | "AI Hospital Intelligence" 제목, 오늘의 현황 숫자 3개, 세 기능으로 가는 카드 | `01-home.png` |
| 구매가격 조사 (기본 화면) | 검색창, 견적서 올리기 → 결과 | `02`, `03`, `04` |
| 병원 News Radar | 오늘/이번 주 기사 수, 키워드별 기사 목록, 이메일 알림 | `05-news-radar.png` |
| 병원 경영 Benchmark | 비교군 선택, 주요 경영지표, 5년 추이 | `06-benchmark.png` |
| 의료기기 상세 | 식약처 허가·안전·조달 근거 상세 | `07-medical-device.png` |
| (메뉴에 없음) 견적 상세 검증 | 견적 원문 대조, 조건 확인, 최종 판정 | `08-quote-detail.png` |

**구매가격 조사 결과 화면**은 위에서 아래로 이렇게 구성돼 있습니다(`04-price-result.png`).

1. **제품 제목:** 품목·허가번호·제조사 한 줄
2. **내 견적가 입력칸**과 **거래 기간 선택**(최근 3년 · 최근 5년 · 전체). 기본은 3년이고, 거래가 없으면 자동으로 넓힙니다.
3. **결론 박스:** "같은 제품이 나라장터에서 17번 거래됐고, 1대당 가운데 값은 4,400,000원입니다." 그 아래 최저~최고 가격 막대가 있고, 내 견적가를 넣으면 막대 위에 표시됩니다.
4. **카드 4장:** 거래가(가운데 값), 납품업체 수, 식약처 허가 상태, 안전정보(회수 이력)
5. **자료 기준 한 줄:** "나라장터 2026-10-05 수집분 + 10-09까지 실시간 확인"
6. **얼마에 거래됐나**
   - 단위(대·세트)와 거래조건별 요약표
   - **연도별 표:** 연도, 건수, 1대당 가운데 값, 최저~최고
   - 가운데 값보다 3배 넘게 벗어난 거래 경고와 해당 거래 설명. 예: "73,026,000원 ÷ 2 set = 1 set당 36,513,000원 · 사업명 「취약지 응급의료기관 장비지원사업」 · 총액계약 · 구매기관 · 날짜"
   - **[같은 제품 거래 N건 전체 보기]** 펼침: 거래일, 모델, 거래 총액, 수량, 1단위 가격, 나라장터 원문 링크, 사업명, 거래조건, 납품업체, 구매기관, 규격. 행을 누르면 그 거래의 조달청 원문 패널이 열립니다.
7. **누가 파는가:** 납품업체별 건수·최저·최고·최근 거래
8. **같은 품목의 다른 모델:** 식약처 같은 품목 안의 다른 모델과 거래 가격대
9. **상세 자료** 펼침: 견적 조건, 안전정보, 식약처 원자료, 자료 기준
10. **입찰·계약 참고자료:** 버튼을 누르면 수십 초 걸려 불러옵니다.

**검색에서 결과까지의 흐름**

- **같은 이름 제품이 여러 개일 때:** 모델명만 검색하면(예: "M40") 같은 이름의 제품이 여러 개 나옵니다(`03`). 사용자가 **"조사할 제품 고르기"**에서 하나를 고른 뒤 결과가 나옵니다.
- **견적서를 올렸을 때:** 품목 표가 먼저 나오고, 행을 누르면 그 품목의 결과가 아래에 나옵니다.
- **서버를 막 켰을 때:** 자료를 내려받는 동안 진행 막대에 "가격 자료를 내려받는 중입니다 77% (246/319 MB) · 남은 자료: 식약처 제품 자료"가 표시됩니다.

## 4. 개선하고 싶은 점

1. **메뉴 구조가 흐립니다.** 구매가격 조사, 의료기기 상세, 견적 상세 검증의 관계가 사용자에게 안 보입니다. 홈은 구매 도구와 병원 경영 정보가 섞여 "무엇을 하는 곳"인지 흐립니다.
2. **결과 화면이 길고 정보 위계가 약합니다.** 결론 다음에 안내 문구(단위·기간·자료 기준·이상치 경고)가 여러 줄 이어져 핵심이 묻힙니다.
3. **Streamlit 기본 모양 그대로입니다.** 빨간 기본 버튼, 비슷비슷한 표와 카드라 "업무용 도구다운" 신뢰감이 부족합니다.
4. **견적서 여러 품목 흐름**에서 품목 사이 이동과 전체 요약(품목별 적정/주의)이 약합니다.
5. **의료기기 상세** 화면에 개발자 용어("식약처 품목 identity", "Research 후보")가 남아 있습니다.
6. **로딩·빈 결과·자동 기간 넓힘·오류 같은 상태 화면**의 일관성이 없습니다.

## 5. 화면별로 꼭 담아야 할 것

아래 정보는 빼지 말고 배치와 위계만 바꿔 주세요.

- **A. 전체 메뉴(IA):** 구매 업무(조사 → 견적 검토 → 상세 검증)와 병원 경영 정보(News·Benchmark)를 어떻게 묶을지, 사이드바 구성과 화면 이름을 제안해 주세요.
- **B. 홈:** 두 업무 묶음으로 들어가는 입구. 구매팀이 매일 여는 첫 화면이라고 가정합니다.
- **C. 구매가격 조사 · 검색 시작:** 검색창 하나, 견적서 올리기, 예시 검색어
- **D. 제품 고르기:** 같은 이름 제품 여러 개 중 선택. 품목·허가번호·유형·모델·제조사·등급을 보여줍니다.
- **E. 결과 화면 (가장 중요)**
  - 결론 한 문장
  - 내 견적가 비교(싸다·비싸다·몇 %)
  - 거래 기간 선택
  - 카드 4장
  - 연도별, 거래 목록, 원문 링크, 사업명
  - 누가 파는가, 다른 모델, 상세, 입찰 참고자료

  **첫 화면(스크롤 없이)에 무엇을 둘지 결정해 주세요.**
- **F. 거래 원문 패널:** 한 거래의 조달청 원문. 사업명, 단가, 수량, 계약방법, 납품기한, 구매기관 등 20여 항목과 "나라장터에서 이 거래 보기" 버튼이 있습니다.
- **G. 견적서 여러 품목:** 품목 요약표(품목, 견적가, 시세 가운데 값, 차이 %, 판정)와 품목별 결과 사이 이동
- **H. 상태 화면**
  - 자료 내려받는 중 진행률
  - 결과 없음
  - "최근 3년 거래가 없어 5년으로 넓혔습니다"
  - 실시간 확인 실패
  - 단위가 섞여 따로 보여줌
  - 가운데 값과 크게 다른 거래 경고
- **I. 의료기기 상세, 견적 상세 검증, News Radar, Benchmark:** 전체 디자인 체계(색·카드·표)와 맞추는 수준이면 됩니다.

## 6. 구현 제약 (Streamlit 1.63)

화면은 아래로 만들 수 있어야 합니다. 맞춤 React 컴포넌트는 쓰지 않습니다.

- **배치:** `st.columns`, `st.container(border=True)`, `st.tabs`, `st.expander`, `st.popover`, `st.dialog`(모달), `st.sidebar`
- **입력:** 텍스트 입력, 파일 올리기, `st.segmented_control`, `st.pills`, `st.selectbox`, `st.radio`, 버튼
- **표:** `st.dataframe`(정렬, 링크 열, 행 선택, 숫자 형식 지정 가능)
- **차트:** Altair/Plotly
- **꾸밈:** `st.markdown(..., unsafe_allow_html=True)`로 넣는 HTML/CSS 카드·배지·막대, 테마 설정(주 색상, 배경, 글꼴, 모서리)
- **안 되거나 비싼 것:** 드래그앤드롭 재배치, 화면 일부만 실시간 애니메이션, 브라우저 저장소 의존 기능, 마우스 오버 툴팁 위주 설계
- **화면 폭:** PC 기준(1440px)으로 설계하되, 태블릿(1024px)에서 깨지지 않으면 됩니다.

## 7. 문구 원칙 (꼭 지켜 주세요)

- **쉬운 우리말:** 구매팀이 쓰는 말을 씁니다. 예: "가운데 값(중앙값)", "거래 총액", "1대당 가격", "납품업체", "구매 기관", "원문 보기"
- **화면에 쓰지 않는 말:** Track B, identity, Research 후보, 매칭등급, A/B/C 등급, source_record_id, API, 스키마, 인덱스, 캐시 같은 개발 용어
- **사실과 판단 구분:** "싸다/비싸다"는 데이터가 충분할 때만 씁니다. 1건뿐이면 "판단하기에는 부족합니다"라고 말합니다.
- **단위:** 대·세트 등 단위를 섞어 계산하지 않습니다. 화면에 단위를 항상 함께 씁니다.

## 9. 받고 싶은 결과물 (목차를 꼭 이대로 맞춰 주세요)

다른 디자이너에게도 같은 의뢰를 보내 결과를 항목별로 나란히 비교합니다. **아래 번호와 제목을 그대로 써 주세요.**

1. **디자인 원칙 3~5개.** 이 도구에 맞는 원칙과 이유 한 줄씩
2. **메뉴 구조(IA).** 사이드바 항목, 화면 이름, 화면 사이 이동 흐름(5장 A)
3. **화면별 목업.** 5장의 B~I 각각. E(결과 화면)는 스크롤 없이 보이는 첫 화면과 전체 화면을 모두 그려 주세요.
4. **상태 화면.** 5장 H의 여섯 가지
5. **컴포넌트 목록.** 결론 박스, 가격 막대, 카드, 표, 배지, 경고, 원문 패널 등. 이름, 용도, 들어가는 정보
6. **디자인 토큰.** 색(주 색, 강조, 성공·주의·위험, 배경, 글자), 글꼴과 크기 단계, 간격, 모서리. Streamlit 테마와 CSS로 옮길 수 있는 값으로
7. **문구표.** 화면 제목, 버튼, 안내 문구, 빈 결과·오류 문구. 지금 문구가 있으면 "지금 → 제안"으로
8. **Streamlit 구현 메모.** 화면마다 어떤 Streamlit 요소로 만들지 한두 줄씩. 6장 제약 안에서
