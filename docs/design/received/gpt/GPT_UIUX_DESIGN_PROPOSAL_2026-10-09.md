# 관리부 시장가격조사기 UI/UX 설계 제안서

**작성 기준**: `BRIEF_FOR_GPT.md`와 2026-10-09 현행 화면 8장. **설계안이지 배포된 기능이 아닙니다.** 이미지 목업에 사용한 M40 견적가 6,500,000원은 의뢰서의 예시이며 실제 원본 견적서에서 확인한 값이 아닙니다.

**핵심 제안**: (1) 구매 업무와 병원 경영 정보를 메뉴에서 분리 (2) 가격 결과의 최상단에 차이율과 비교조건을 함께 제시 (3) 단위·계약조건 차이로 인한 오판을 예방 (4) 다품목 견적은 요약표·품목별 근거의 2단 구조 (5) 결과 미확인·로딩·오류의 표준 상태를 도입.

---

## 1. 디자인 원칙 3~5개

| 원칙 | 적용과 근거 |
|---|---|
| **10초 요약** | 첫 화면에서 품명, 단위, 내 견적, 거래 중앙값, 차이율, 비교가능성을 읽는다. 거래 목록을 펼치기 전 검토 방향을 잡는다. |
| **사실과 판단 분리** | `관측값`(거래수·중앙값·단가)과 `확인 필요`(구성·계약조건)를 별도 영역으로 둔다. 거래가 1건뿐이면 ‘비교 근거 부족’으로 표시한다. |
| **비교 단위 엄수** | `대` vs `세트` vs `식`을 합산하거나 같은 분포·축에 표시하지 않는다. VAT·설치비·보증·옵션 차이는 비교 제한을 알린다. |
| **요약에서 원문까지 2번 이내** | 결론 → 이상 거래 보기 → 거래 원문으로 이동. 원문 사업명·수량·단가·조건·원문 링크를 확인할 수 있게 한다. |
| **조용한 시각 체계** | 업무용 남색·청록색, 균일한 카드·표·간격을 사용하며 주의색은 실제 확인사항에만 적용한다. |

**정책 예외**: 회수/판매중지 등 중대한 안전정보가 제품에 연결되면, 일반 가격 결론보다 **상위에 위험 배너**를 띄운다. 단, 조치대상 모델·로트 동일성 확인 전에는 ‘회수 대상 확정’으로 단정하지 않는다. 이는 별도의 최우선 안전 규칙이다.

**판단어 사용 기준**: 데이터가 충분하고 규격·옵션·단위·거래조건의 비교가능성이 확보된 경우에만 ‘거래 사례보다 높은 편/낮은 편’을 쓴다. UI에서 구매 적정/부적정 확정, 자동 업체 선정은 금지한다. 가격 차이는 ‘중앙값 대비 %’로 계산해 보이되 ‘적정’ 판정과 분리한다.

## 2. 메뉴 구조(IA)

### 사이드바

```text
┌─────────────────────────────┐
│ 병원 구매정보 도우미        │
│                             │
│ 홈                          │
│                             │
│ ─ 구매 업무 ─               │
│  구매가격 조사              │
│  견적서 검토                │
│  의료기기 정보 확인        │
│                             │
│ ─ 병원 경영 정보 ─          │
│  병원 뉴스                  │
│  병원 경영 비교             │
│                             │
│ 시범 서비스 · 공개자료 기반│
└─────────────────────────────┘
```

- **결과 화면 / 제품 선택 / 거래 원문**: 독립 사이드바 메뉴가 아닌 구매가격 조사의 내부 화면(단계). 뒤로가기 동작과 검색어/선택제품/기간/견적입력 상태 유지.
- **견적 상세 검증**: `견적서 검토` 내부의 **원문 대조·조건 확인** 단계로 통합. 파일 중복 업로드 방지.
- **의료기기 정보 확인**: 단독 탐색도 가능하되 결과 화면의 허가/회수 카드에서 바로 해당 제품의 상세를 연다.
- **병원 뉴스 / 병원 경영 비교**: 구매 업무와 분리되지만 동일 디자인 토큰, 표, 상태 메시지를 공유.

### 대표 4개 작업 흐름

```text
① M40 견적 650만원:
   구매가격 조사 → M40 입력 → 유사한 이름의 제품 목록 →
   '메디아나 / 환자감시장치 / 인증 제인 20-5001호' 선택 →
   6,500,000원·1대 입력 → 거래 비교 → 원문 확인

② 10품목 견적서:
   견적서 검토 → PDF/Excel/사진 업로드 → 추출된 품목·수량 검토 →
   10행 비교표 → 조건 확인/자료부족 필터 → 선택 품목 세부 검토 → 저장

③ 36,513,000원/세트의 이상 거래:
   가격 결과 → '세트 단위 거래 2건' →
   73,026,000원÷2세트 거래 선택 → 사업명·계약조건·원문 링크

④ Excel 결재 자료:
   가격 결과 또는 견적서 검토 → 조사 기준·품목별 판정상태 확인 →
   Excel로 저장 (요약 / 근거 거래 / 출처·수집일 / 확인 필요 항목)
```

**이유**: 현재 서로 떨어져 있는 `구매가격 조사`, `견적 상세 검증`, `의료기기 상세`를 하나의 작업 흐름으로 연결한다. 사용자에게 업무별 도착점이 명확해지며 메뉴 이동과 동일 정보 재입력이 줄어든다. 절약 시간은 실제 사용자 테스트 전까지 수치로 단정하지 않는다.

## 3. 화면별 목업

**아래 모든 ASCII 그림의 왼쪽 메뉴 폭은 약 17%(245/1440px), 본문은 약 83%**로 가정한다. 본문 카드 비율·접힘 상태는 상대값이다. 화면 제약은 1440×1000 데스크톱 우선, 1024px 태블릿 대응이다.

### 크기·간격

- 글꼴: `Noto Sans KR`가 있으면 사용, 없으면 `Pretendard` → 시스템 산세리프. Streamlit 테마에는 안정적인 `sans serif`를 두고 custom CSS로 선택적 지정.

- 간격: 4 / 8 / 12 / 16 / 24 / 32px의 4px 배수.
- 모서리: 카드 12px, 입력·버튼 8px, 알림 9px, 배지 6px. 카드 그림자는 미약하게(`0 2px 11px rgba(23,52,89,.04)`).
- 데스크톱: 사이드바 240~250px, 본문 폭은 최소 1000px 확보하는 `layout="wide"` 기준. 주요 좌우 패널 비율 E=75/25 또는 실제 구현 70/30, G=65/35. 태블릿 1024px은 좌우 패널을 위아래로 변경.
- 모든 상태는 텍스트 + 아이콘으로 판독 가능해야 하며 색만으로 구분하지 않음. 경고 본문 최소 12~13px 유지.

### Streamlit 테마 예시

```toml
backgroundColor = "#F4F7FB"
secondaryBackgroundColor = "#FFFFFF"

```

## 8. Streamlit 구현 메모

| 화면/요소 | 구현 구상 (Streamlit 1.63) | 상태·성능·제약 |
|---|---|---|
| 전역 메뉴 | `st.sidebar`, native 페이지 네비게이션 또는 페이지 라우팅, `st.session_state` | 독립 5메뉴+홈. 제품 ID/견적선택 상태 보존 |
| 홈 | `st.columns`, `st.container(border=True)`, `st.text_input`, `st.file_uploader` | 검색/업로드 핸들러는 조사/견적서 검토로 이동 |
| 검색 | `st.text_input` + `st.button` + `st.expander` | 입력 형식 안내, 불필요한 검색 조건 기본 숨김 |
| 후보 선택 | `st.dataframe(on_select="rerun", selection_mode="single-row")`, `st.selectbox` 대체 | 후보의 허가번호·업체 등 확인 전 자동 판정 금지 |
| 가격 결론 | `st.columns` + `st.container`; 독립 CSS HTML 요약 카드 | 입력 단위가 바뀌면 비교군도 재선택. 가격 차이 계산/판정 분리 |
| 가격 막대 | Altair/Plotly 또는 CSS 절대 좌표(비율 기반) | 동일 단위만, 최고=최저 처리, 범위 밖 입력값 처리 |
| 카드 4장 | `st.columns(4)` + 정보 카드 | 수치 없으면 '확인되지 않음'으로 표시 |
| 거래표 | `st.dataframe` + `st.column_config.LinkColumn` / `NumberColumn`; 행 선택 | 원문 주소가 실제 있는 기록만 외부 링크 활성 |
| 거래 원문 | `@st.dialog` 또는 별도 상세 컨테이너 | 긴 내용/태블릿에서 팝업 과밀 방지 |
| 견적서 다품목 | 파일 업로드 → 품목표 `st.dataframe` 행 선택 → 오른쪽 `st.container` | 추출한 품목 수정/확정 후 조회. 이전/다음은 일반 버튼으로 구현 |
| 결과 탭 | `st.tabs` 또는 `st.segmented_control` + 조건부 렌더링 | `st.tabs`의 비선택 탭 내용도 실행될 수 있음. 무거운 입찰조회는 클릭 버튼 뒤에서만 실행 |
| 안전경고 | 조건에 따라 `st.warning` / `st.error` 또는 일관된 HTML 카드 | 안전정보가 있으면 가격결론 앞에 표시 |
| 자료 로딩 | `st.progress`, `st.status`, `st.spinner` | 실제 바이트/건수 기반 값만 출력, 추정 잔여시간 지양 |
| News / Benchmark | `st.selectbox`, `st.radio`, `st.dataframe`, Altair/Plotly | 기존 로직 유지, 색상·상태 문구·표의 여백만 통일 |
| Excel | `st.download_button` + 서버에서 xlsx 생성 | 다운로드에 '데이터 기준일/출처/거래조건' 시트 반드시 포함 |

### 구현을 위한 상태 모델(권장)

```text
검색상태 = 초기 | 검색중 | 후보선택 | 비교완료 | 무자료 | 오류
견적상태 = 미업로드 | 추출중 | 품목확인 | 다품목검토 | 완료/오류
가격비교상태 = 비교가능 | 계약조건확인 | 비교근거부족 | 단위불일치
안전상태 = 관련정보없음(조회범위) | 관련정보확인필요 | 대상일치확인 | 조회실패
```

- **데이터가 없는 상태**와 **검색이 실패한 상태**를 명확히 분리한다. 실패를 `0건`으로 대체하지 않는다.
- 다품목 견적의 `st.dataframe` 행 선택 이벤트와 선택항목 `session_state`를 동일한 키로 연결하고, 정렬 후 선택한 원본 ID가 유지되는지 검증한다. 행번호가 바뀌더라도 다른 품목을 잘못 표시해서는 안 된다.
- `st.file_uploader`에서 실제 구매자료를 받는 운영 정책·삭제·보유기간은 병원 내부 보안 검토가 선행돼야 함. 공개 PoC는 샘플/비식별 문서를 우선 사용.
- 사용자가 원문 클릭 시 원래 검색결과로 되돌아왔을 때 검색어·선택제품·거래기간·견적가·테이블 필터를 보존한다.

### Streamlit 제약을 넘는 제안과 대체안

| 디자인에서 기대할 수 있는 기능 | 제약 | Streamlit 내 대안 |
|---|---|---|
| 표 행 클릭하면 매끄러운 좌측 고정/우측 상세 실시간 변화 | rerun 때문에 웹앱처럼 완전 무중단 전환은 어려움 | `st.dataframe` 단일 행 선택 → `st.session_state` → 선택상세 컨테이너 렌더링; `st.fragment` 사용은 운영 버전 검증 후 |
| 복잡한 호버·드래그·고정 스크롤 영역 | 기본 Streamlit 위젯의 제약 | 클릭·탭·확장 중심, 일반 표 선택/정렬 사용 |
| CSS 카드 자체를 버튼처럼 클릭 | 정적 HTML 카드에는 이벤트 없음 | 정보 카드는 CSS, 행동은 바로 옆 진짜 `st.button` |
| 긴 거래 20여 항목의 우측 슬라이드 패널 | 독립 웹 컴포넌트 필요할 수 있음 | `st.dialog`(큰 크기) 또는 페이지 내 상세 섹션 |
| 1024px에서 4카드 완전 한 줄 유지 | 가독성 저하 | 2×2 카드와 상하 스택 패널 적용 |

**검증 체크리스트**: 1440/1024 화면 깨짐, 검색어/단위/견적값 유지, 3년→5년 자동 확대 동기화, 1건 자료의 판정 보류, 대/세트 별도 집계, 안전 회수상단 배너, 원문 링크 대응, 품목 선택 정확성, Excel 단가·총액·출처 일치, 실시간 장애 시 마지막 성공자료 표시.
