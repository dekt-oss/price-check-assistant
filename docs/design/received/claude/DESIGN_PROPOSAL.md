# 구매 도우미 화면 설계 제안 (Claude Design, 2026-10-09)

프로토타입: `제안 프로토타입.dc.html` (사이드바·펼침·원문 패널·거래 기간·상태 보기가 동작) · 현재 화면 복제본: `현재 화면 (복제).dc.html`
참고 데이터: M40 · PNB-704 · Efficia DFM100 (의뢰서 8장 그대로)

## 1. 디자인 원칙 3~5개

1. **결론 먼저, 근거는 한 번 더 눌러서.** 첫 화면은 결론 한 문장 + 가격 막대 + 카드 4장으로 끝낸다. 표·원문은 탭과 펼침 아래. (성공 기준 "10초 판단")
2. **판단은 숫자가 충분할 때만.** 거래 3건 미만이면 "판단하기에는 부족합니다"로 쓰고, 색도 회색(neutral)으로 둔다. 초록·주황은 3건 이상에서만.
3. **단위는 항상 함께, 절대 섞지 않는다.** "1대당", "1 SET당"을 숫자 옆에 붙이고, 다른 단위 거래는 표에서 배경색으로 구분해 따로 둔다.
4. **빨간색은 위험에만.** 기본 버튼 색을 청록(#1f6f8b)으로 바꿔 "경고"와 "실행"이 같은 색이 되지 않게 한다. 빨강은 회수·판매중지와 조건 충돌에만.
5. **구매팀 말로만 쓴다.** identity·Track B·exact·매칭등급 같은 말은 화면에서 지우고 "같은 제품", "허가 확인", "원문 보기"로 바꾼다.

## 2. 메뉴 구조(IA)

사이드바를 두 묶음으로 나눈다. 기본 주소(`/`)는 가격 조사.

```
구매 도우미 (홈)
├ 구매 업무
│  ├ 가격 조사            /            검색 → (제품 고르기) → 결과
│  ├ 견적서 검토          /quote       여러 품목 요약표 → 품목별 결과 → [펼침] 원문 확인·조건 대조·승인
│  └ 의료기기 허가·안전   /device      허가·등록 | 안전정보·업체 | UDI-DI
└ 병원 경영 정보
   ├ 뉴스 레이더          /news-radar
   └ 경영 비교            /hospital-benchmark
```

- 옛 "견적 상세 검증"은 메뉴에서 빼고 견적서 검토 화면 아래 펼침("원문 확인 · 조건 대조 · 승인")으로 넣는다. 결재용으로만 쓰는 단계라 평소에는 접혀 있다.
- 옛 "의료기기 상세"는 "의료기기 허가·안전"으로 이름을 바꾸고, 결과 화면 머리글의 "허가·안전 상세 →" 링크와 양방향으로 잇는다.
- 화면 사이 이동: 홈 검색창 → 가격 조사 결과 / 홈 "견적서 올리기" → 견적서 검토 / 결과 머리글 → 의료기기 허가·안전 / 의료기기 등록표 "가격 조사 →" → 결과 / 견적서 요약표 행 → 아래 품목 결과 → "가격 조사 화면에서 전체 보기".

## 3. 화면별 목업 (프로토타입 화면 이름)

- **B 홈** — 날짜, 검색창(바로 조사), 예시 검색어, 구매 업무 카드(견적서 올리기·허가 확인), 병원 경영 카드(오늘 기사 6건·비교 가능 병원 38개), 최근 조사 표. 구매팀이 매일 여는 첫 화면이므로 검색창이 가장 크다.
- **C 검색 시작** — 한 줄 검색창 + "견적서 올리기" 버튼이 머리글에 고정. 아래는 3단계 안내와 "조건 직접 입력" 펼침.
- **D 제품 고르기** — "M40 이름의 제품이 4개 있습니다". 라디오형 카드 행(품목·허가번호·유형·모델·제조사·등급·UDI-DI). 고르기 전에는 가격을 보여주지 않는다는 안내.
- **E 결과 — 첫 화면(스크롤 없음, 1440×900 기준)**
  - A안 **결론 중심**(기본): 제품 머리글(이름 + "허가 확인" 배지 + 기간 선택 + Excel) → 결론 박스(한 문장, 범위, 내 견적 문장, 가격 막대) + 오른쪽 내 견적가 입력 패널(% 크게) → 카드 4장 → 알아 둘 것 한 줄(기간·단위·자료 기준 칩).
  - B안 **표 중심**: 결론을 한 줄 띠로 줄이고 연도별 표를 바로 보여준다. 카드 4장은 오른쪽 세로 목록. 견적가 입력은 띠 안.
  - 두 안 모두 첫 화면에 들어가는 것: 결론 문장, 가운데 값, 범위, 내 견적 위치(%), 거래 기간, 허가·안전 상태. 들어가지 않는 것: 거래 목록, 납품업체, 다른 모델.
- **E 결과 — 전체 화면** — 얼마에 거래됐나(탭: 연도별 | 단위·거래조건별 | 거래 전체 N건, 전체 탭 위에 이상 거래 경고) → 누가 파는가 | 같은 품목의 다른 모델(2단) → 상세 자료 펼침 → 입찰·계약 참고자료(불러오기 버튼).
- **F 거래 원문 패널** — `st.dialog`. 제목=사업명, 상단 3칸(거래 총액·수량·1단위 가격), SET 단위 안내, 20개 항목 2단 표, "나라장터에서 이 거래 보기" 버튼, 원문 확인값.
- **G 견적서 검토** — 파일 칩(파일명·품목 수·추출 방식) → 판정 범례 → 품목 요약표(#, 품목·모델, 견적 단가, 거래 가운데 값, 차이, 판정, 근거) → 선택 품목 띠 → 결론 박스 + 카드 4장 → [펼침] 원문 확인·조건 대조·승인(6단계 스텝, 품목 목록 | 조건 대조표 | 남은 일).
- **I 의료기기 허가·안전** — 탭 3개, 입력 4칸(품목명·모델명·제조·수입업체·규격), 등록표(검색 모델 강조, 판매 상태 배지, 나라장터 거래 연결).
- **I 뉴스 레이더** — 숫자 카드 4장, 멈춤 안내, 필터 한 줄, 기사 목록(키워드 칩·읽음·중요 버튼).
- **I 경영 비교** — 기준 병원 카드 + 비교군 카드(비교 방식 pills), 비교군 표, 경영지표(연계 전 안내).

## 6. 디자인 토큰

프로토타입 `<style>:root{…}` 그대로.

**색**
- 주 색 `--color-primary: #1f6f8b` (지금 결론 박스 띠 색을 그대로 주 색으로), 바탕 `#e6f0f4`
- 글자 `--color-ink: #1c1b19`, 보조 `#52514e`, 안내 `#6b6862`, 표 머리글 `#898781`
- 배경 `#ffffff`, 보조 배경(사이드바·입력칸) `#f6f5f1`, 표 머리글 배경 `#efeee9`
- 테두리 `#e1e0d9`, 진한 테두리 `#c3c2b7`
- 성공 `#2e7d5b` / `#e9f3ee` · 주의 `#b45309` / `#fdf3e4` · 위험 `#b91c1c` / `#fbeaea` · 중립 `#94a3b8`

**글꼴** Pretendard Variable (없으면 Malgun Gothic). 크기 단계 12 · 13 · 14(본문) · 16 · 18(소제목) · 22(화면 제목) · 28(제품명·큰 숫자) · 34. 숫자는 `font-variant-numeric: tabular-nums`.

**간격** 4 · 8 · 12 · 16 · 24 · 32 · 48. **모서리** 6px(버튼·입력·칩) · 10px(카드·박스).

**Streamlit `.streamlit/config.toml`**
```toml
[theme]
base = "light"
primaryColor = "#1f6f8b"
backgroundColor = "#ffffff"
secondaryBackgroundColor = "#f6f5f1"
textColor = "#1c1b19"
font = "sans serif"
```
Pretendard는 `st.markdown`으로 `<link>`와 `html, body, [class*="css"] {font-family:…}`를 한 번 넣는다.

## 8. Streamlit 구현 메모

- **사이드바** — `st.navigation(position="hidden")` 유지. `with st.sidebar:` 안에 `st.caption("구매 업무")` → `st.page_link` 3개, `st.caption("병원 경영 정보")` → 2개. 아이콘은 `:material/search:` 식 Material 아이콘. 테마 `secondaryBackgroundColor`가 사이드바 색.
- **홈** — `st.text_input` + `st.button(type="primary")`를 `st.columns([6,1])`로. 예시는 `st.pills`. 카드 2장은 `st.columns(2)` + `st.container(border=True)`. 최근 조사는 `st.dataframe(on_select="rerun")`.
- **검색/결과 머리글** — `st.columns([1,6,1,1.3])`에 제목·입력·검색·견적서 올리기. `st.file_uploader`는 `st.popover("견적서 올리기")` 안에.
- **제품 고르기** — `st.radio`(세로)로 1열 카드처럼 쓰거나, `st.dataframe(selection_mode="single-row")` + 상단 `st.warning`.
- **결과 첫 화면** — `st.columns([2.4,1])`: 왼쪽 결론 박스(`st.markdown` HTML, 기존 `render_conclusion_html`), 오른쪽 `st.container(border=True)`에 `st.text_input("내 견적가")` + `st.markdown` %. 카드는 기존 `render_cards_html`에서 왼쪽 띠 대신 오른쪽 위 점으로 CSS만 바꾼다. 안내 칩은 markdown HTML 한 줄.
- **거래 기간** — `st.segmented_control(["최근 3년","최근 5년","전체"], default=…)`.
- **얼마에 거래됐나** — `st.tabs(["연도별","단위·거래조건별","거래 전체 16건"])`. 각 탭 `st.dataframe`, 숫자 열은 `column_config.NumberColumn(format="%,d원")`. 거래 전체 탭은 `on_select="rerun", selection_mode="single-row"` → 선택 시 `st.dialog` 원문 패널.
- **원문 패널** — `@st.dialog("거래 원문", width="large")`. 상단 3칸 `st.columns(3)` + `st.metric`, 항목은 `st.columns(2)` 안 markdown 표. `st.link_button("나라장터에서 이 거래 보기", url)`.
- **견적서 검토** — 요약표 `st.dataframe(on_select="rerun")`; 선택 행 → 아래 결론 박스·카드 재사용. 상세 검증은 `st.expander("원문 확인 · 조건 대조 · 승인")` 안에 기존 `render_stepper` + `st.columns([0.9,2.4,1.1])`.
- **상태 화면** — 로딩 `st.progress` + `st.caption`; 결과 없음·넓힘은 `st.info`/markdown HTML; 실시간 실패 칩 옆 `st.button("다시 확인")`.
- **의료기기** — `st.tabs` 3개, 입력 `st.columns(2)`, 등록표 `st.dataframe`에 판매 상태 열은 글자로.
- **뉴스/경영 비교** — 숫자 카드는 `st.columns(4)` + `st.container(border=True)` + `st.metric`. 비교 방식은 `st.pills`.
- **6장에 없는 모양** — 라디오형 카드 행(제품 고르기): 대안은 `st.dataframe` 단일 행 선택. 결과 표 행의 hover 강조: 생략. 사이드바 그룹 제목: `st.caption`으로 충분. Pretendard: `st.markdown`으로 `<link>` 주입.
