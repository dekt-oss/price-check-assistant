구매 도우미 화면 설계 제안

프로토타입 제안 프로토타입.dc.html · 현재 화면 복제본 현재 화면 (복제).dc.html · 같은 내용의 Markdown DESIGN_PROPOSAL.md

참고 데이터는 의뢰서 8장의 M40 · PNB-704 · Efficia DFM100을 그대로 썼습니다.

1. 디자인 원칙 3~5개

  1. 결론 먼저, 근거는 한 번 더 눌러서. 첫 화면은 결론 한 문장 + 가격 막대 + 카드 4장으로 끝낸다. 표·원문은 탭과 펼침 아래. (성공 기준 "10초 판단")
  2. 판단은 숫자가 충분할 때만. 거래 3건 미만이면 "판단하기에는 부족합니다"로 쓰고 색도 회색으로 둔다. 초록·주황은 3건 이상에서만.
  3. 단위는 항상 함께, 절대 섞지 않는다. "1대당", "1 SET당"을 숫자 옆에 붙이고, 다른 단위 거래는 표에서 배경색으로 구분해 따로 둔다.
  4. 빨간색은 위험에만. 기본 버튼을 청록(#1f6f8b)으로 바꿔 "경고"와 "실행"이 같은 색이 되지 않게 한다. 빨강은 회수·판매중지와 조건 충돌에만.
  5. 구매팀 말로만 쓴다. identity·Track B·exact·매칭등급은 화면에서 지우고 "같은 제품", "허가 확인", "원문 보기"로 바꾼다.

2. 메뉴 구조(IA)

사이드바를 두 묶음으로 나눕니다. 기본 주소(/)는 가격 조사.

구매 도우미 (홈)
├ 구매 업무
│  ├ 가격 조사            /              검색 → (제품 고르기) → 결과
│  ├ 견적서 검토          /quote         여러 품목 요약표 → 품목별 결과 → [펼침] 원문 확인·조건 대조·승인
│  └ 의료기기 허가·안전   /device        허가·등록 | 안전정보·업체 | UDI-DI
└ 병원 경영 정보
   ├ 뉴스 레이더          /news-radar
   └ 경영 비교            /hospital-benchmark
  • 옛 "견적 상세 검증"은 메뉴에서 빼고 견적서 검토 아래 펼침("원문 확인 · 조건 대조 · 승인")으로 넣습니다. 결재용으로만 쓰는 단계라 평소에는 접혀 있습니다.
  • 옛 "의료기기 상세"는 "의료기기 허가·안전"으로 이름을 바꾸고, 결과 머리글의 "허가·안전 상세 →"와 양방향으로 잇습니다.
  • 이동 흐름: 홈 검색창 → 결과 / 홈 "견적서 올리기" → 견적서 검토 / 결과 머리글 → 의료기기 / 의료기기 등록표 "가격 조사 →" → 결과 / 견적서 요약표 행 → 품목 결과 → "가격 조사 화면에서 전체 보기".

3. 화면별 목업

프로토타입 위쪽 "프로토타입 보기" 막대에서 상태·결과 안(A/B)·제품 자료를 바꿀 수 있습니다.

B 홈
날짜, 큰 검색창(바로 조사), 예시 검색어, 구매 업무 카드(견적서 올리기·허가 확인), 병원 경영 카드(오늘 기사 6건·비교 가능 병원 38개), 최근 조사 표.
C 검색 시작
검색창 + "견적서 올리기"가 머리글에 고정. 아래는 3단계 안내와 "조건 직접 입력" 펼침.
D 제품 고르기
"M40 이름의 제품이 4개 있습니다". 라디오형 카드 행(품목·허가번호·유형·모델·제조사·등급·UDI-DI). 고르기 전에는 가격을 보여주지 않는다는 안내.
E 결과 · 첫 화면
A안 결론 중심(기본): 머리글(제품명·허가 배지·기간 선택·Excel) → 결론 박스(문장·범위·내 견적 문장·가격 막대) + 오른쪽 견적가 패널(% 크게) → 카드 4장 → 알아 둘 것 칩 한 줄.
B안 표 중심: 결론을 한 줄 띠로 줄이고 연도별 표를 바로. 카드는 오른쪽 세로 목록, 견적가 입력은 띠 안.
첫 화면에 두는 것: 결론 문장, 가운데 값, 범위, 내 견적 위치(%), 거래 기간, 허가·안전 상태. 두지 않는 것: 거래 목록, 납품업체, 다른 모델.
E 결과 · 전체
얼마에 거래됐나(탭: 연도별 | 단위·거래조건별 | 거래 전체 N건, 전체 탭 위에 이상 거래 경고) → 누가 파는가 | 같은 품목의 다른 모델 → 상세 자료 펼침 → 입찰·계약 참고자료.
F 거래 원문 패널
모달. 제목=사업명, 상단 3칸(거래 총액·수량·1단위 가격), SET 단위 안내, 20개 항목 2단, "나라장터에서 이 거래 보기", 원문 확인값.
G 견적서 검토
파일 칩 → 판정 범례 → 품목 요약표(품목·모델, 견적 단가, 거래 가운데 값, 차이, 판정, 근거) → 선택 품목 띠 → 결론 박스 + 카드 → [펼침] 원문 확인·조건 대조·승인(6단계 스텝).
I 의료기기
탭 3개(허가·등록 / 안전정보·업체 / UDI-DI), 입력 4칸, 등록표(검색 모델 강조, 판매 상태 배지, 나라장터 거래 연결).
I 뉴스 레이더
숫자 카드 4장, 멈춤 안내, 필터 한 줄, 기사 목록(키워드 칩·읽음·중요).
I 경영 비교
기준 병원 카드 + 비교군 카드(pills), 비교군 표, 경영지표(연계 전 안내).

9. 우선순위

  1. 결과 첫 화면 재배치 (A안) — 결론 박스 옆 견적가 패널, 안내 4줄을 칩 한 줄로, 카드 바로 아래. 난이도 중
  2. 주 색·테마 교체 + 문구표 적용 — config.toml 테마, 버튼 빨강 → 청록, 7장 문구 치환. 난이도 하
  3. 사이드바 두 묶음 + 견적 상세 검증을 펼침으로 — Home.py 사이드바, 2_견적_검토.py를 견적서 검토 아래 expander로. 난이도 중
  4. 거래 보기 탭 + 행 선택 → 원문 st.dialog — 연도별/조건별/전체 탭, 이상 거래 경고를 전체 탭 위로. 난이도 중~상
  5. 견적서 검토 요약표 판정 열 + 범례 — 범위 안/밖/판단 부족 규칙(3건 기준)과 색 점. 난이도 중
