# 화면 설계 의뢰 (2026-10)

구매팀에 공유하기 전에 화면 구성과 메뉴를 다듬으려고, 같은 의뢰를 두 곳에 보내고 좋은 부분만 골라 씁니다.

| 파일 | 보내는 곳 | 받는 것 |
| --- | --- | --- |
| [BRIEF_FOR_CLAUDE_DESIGN.md](BRIEF_FOR_CLAUDE_DESIGN.md) | Claude Design | 클릭되는 HTML 프로토타입, 디자인 토큰(CSS 변수) |
| [BRIEF_FOR_GPT.md](BRIEF_FOR_GPT.md) | ChatGPT | 와이어프레임, 이미지 목업 2장, 문구표, 판단 근거 |
| `current-screens/` | 두 곳 모두 첨부 | 운영 화면 캡처 8장(2026-10-09) |

두 의뢰서의 1~8장은 같은 내용이고, 10장(도구별 요청)만 다릅니다. 9장 결과물 목차도 같아서 항목별로 나란히 비교할 수 있습니다.

## 보내기 전에 확인할 것

- `05-news-radar.png`에는 관심 키워드로 등록한 병원 이름과 기사 제목이 보입니다. 외부 서비스에 올려도 괜찮은지 확인하고, 필요하면 그 부분을 가리세요.
- `04-price-result.png`의 거래 기록(구매기관·업체명)은 나라장터 공개 자료입니다.

## 받은 뒤 고르는 기준

두 결과를 9장 번호별로 놓고 항목마다 점수를 매깁니다(1~5점).

| 기준 | 질문 |
| --- | --- |
| 10초 판단 | 결과 화면 첫 화면만 보고 "이 견적이 적정한가"를 알 수 있나 |
| 근거 추적 | 튀는 거래에서 원문(사업명·조건)까지 두 번 안에 갈 수 있나 |
| 견적서 여러 품목 | 품목 10개를 빠르게 훑고 이상한 것만 고를 수 있나 |
| 구현 가능성 | Streamlit 1.63 요소로 만들 수 있나(6장) |
| 문구 | 개발 용어 없이 구매팀 말로 쓰였나(7장) |
| 일관성 | 다섯 메뉴가 같은 색·카드·표 체계를 쓰나 |

고른 항목은 `DESIGN_DECISIONS.md`(받은 뒤 작성)에 "어느 쪽의 무엇을 왜"로 남기고, 우선순위(9장 9번)대로 PR을 나눠 반영합니다.
