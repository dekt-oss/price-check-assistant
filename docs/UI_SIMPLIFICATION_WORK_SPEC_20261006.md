# UI/UX 단순화 작업명세서 — 구매팀 공유용 화면으로 올리기

작성일: 2026-10-06
대상 레포: `dekt-oss/price-check-assistant` (`main` = `4b496d4`, PR #282까지 반영)
작성 근거: 로컬에서 앱을 띄워 `HeartOn A16-DS` 검색 결과, 업체·조달 탭, 동일품목 비교 탭, 견적 검토·상세 검색·의료기기 조회 페이지를 직접 확인하고 `pages/1_대시보드.py`(2,741줄)와 `src/purchase_price/ui/*`를 읽은 결과.

## 0. 한 줄 목표

> **구매팀 팀원이 설명 없이 모델명 하나를 넣고 30초 안에 "얼마에 거래되는 물건이고, 내 견적이 그 안에 드는지"를 읽을 수 있어야 한다.** 그 밖의 모든 자료는 한 번 더 눌러야 보이게 한다.

이 작업은 **화면 층만** 바꾼다. 가격 판정·동일성 등급·안전 게이트·수집 로직(`services/`, `collectors/`)은 손대지 않는다. "보여주지 않는 것"과 "판정을 완화하는 것"은 다르다. 보여주는 양을 줄이되, 보류·실패·미확인 상태는 숨기지 않고 더 짧은 말로 쓴다.

## 1. 지금 화면이 왜 많게 느껴지는가 (진단)

### 1-1. 메뉴가 6개인데 팀원이 쓸 메뉴는 1개다

| 현재 메뉴 | 실제 역할 | 팀원에게 필요한가 |
| --- | --- | --- |
| 통합 검색 | 핵심 화면. 검색 + 견적서 업로드 + 결과 | **예** |
| 견적 검토 | 견적서 다품목 요약 + 6단계 상세검증 | 부분 (품목 요약표만) |
| 상세 검색 | 품명·제조사·모델·규격 4칸 입력형. 통합 검색의 "정확도 높이기"와 중복 | 아니오 (통합 검색 안에 이미 있음) |
| 의료기기 조회 | 식약처 품목명 입력형 3탭 | 드물게 (식약처 상세가 필요할 때만) |
| 견적추출 UAT / 전체 구매검토 UAT | 개발·검증 도구 | **아니오** (관리자용) |

### 1-2. 결과 화면 한 장에 "눌러야 하는 것"이 8개, 표가 2개, 설명문이 6개

`HeartOn A16-DS` 검색 직후 첫 화면(스크롤 전)에 보이는 요소를 센 결과:

| 종류 | 개수 | 예 |
| --- | --- | --- |
| 버튼·펼침·탭 | 8 | 검색, 새 검색, 견적서 업로드·상세 검색(펼침), Excel 내려받기, 국내 정상·취소 상태 불러오기(10~40초), 확인 내역·안전정보·검색어 해석(펼침), 내 견적가와 비교(펼침), 영역 탭 3개 |
| 설명 문장 | 6 | "자료 기준 · 나라장터 2026-09-18까지 수집 · 실시간 보강 … · 식약처 제품정보 53% 수집 중" 등 |
| 표 | 2 | 모델·규격·조건별(9열) + 거래 93건(기본 10열, Excel 24열) |

가장 중요한 답인 **"내 견적이 거래가 대비 어디쯤인가"**는 "내 견적가와 비교" 펼침 안의 5칸 입력을 거쳐야 보인다. 반대로 가장 덜 중요한 **수집 진행률·실시간 보강 결과·검색어 해석**은 접히지 않은 채 상단에 있다.

### 1-3. 용어가 개발자 말이다

화면에 그대로 나오는 말: "직접 동일성 확인 거래", "품목 책임주체", "참고거래", "매칭근거", "원문근거키", "식약처 품목번호 [허가]", "형명정보", "serving index", "exact", "identity", "A/B 근거", "UDI-DI". 구매팀원은 이 말을 배워야 화면을 읽을 수 있다.

### 1-4. 느린 버튼이 주 동선에 있다

"국내 정상·취소 상태 불러오기 (약 10~40초)", "입찰·계약 참고자료 불러오기"가 결과 첫 화면과 가격 탭 하단에 있다. 팀원은 눌러야 하는 줄 알고 누르고, 40초 기다린다.

### 1-5. 탭 3개가 "같은 질문의 다른 조각"을 흩어 놓는다

가격 비교 / 업체·조달 / 동일품목 비교 탭은 각각 "얼마인가 / 누가 파는가 / 대신 살 수 있는 건 뭔가"라는 한 흐름이다. 탭으로 나누면 한 번에 비교가 안 되고, 각 탭마다 표·체크박스·버튼이 또 생긴다.

### 1-6. 이미 잘 된 것 (지킨다)

- 상단 4장 카드(거래가 / 납품업체 / 식약처 등록 / 안전정보)와 색 규칙(W3, PR #271). 이 구조는 유지하고 말만 바꾼다.
- 홈의 큰 검색창 하나 + 견적서 업로드 카드.
- 안전정보 RED/AMBER는 가격보다 먼저 띄우는 규칙.
- `docs/wireframes/README.md`의 색 의미(초록=확인, 노랑=사람이 할 일, 빨강=차단, 회색=보류)와 "근거와 후보는 같은 모양이 아니다" 규칙.

## 2. 목표 화면 (설계)

### 2-1. 정보 3단계 원칙

| 단계 | 무엇 | 어떻게 보이나 |
| --- | --- | --- |
| **0단계 · 결론** | 이 물건이 무엇이고, 얼마에 거래되고, 내 견적은 어디쯤인가 | 스크롤 없이 첫 화면. 문장 1개 + 가격대 막대 + 카드 4장 |
| **1단계 · 핵심 자료** | 결론의 근거 표 3개, 각각 상위 5행 | 결론 아래 세로로 쌓음. 탭 없음 |
| **2단계 · 상세** | 전체 거래행, 식약처 원자료, 안전정보 확인 내역, 검색어 해석, 입찰·계약 참고자료, 수집 상태 | 각 섹션의 "전체 보기" 또는 맨 아래 "상세 자료" 한 묶음. 기본 접힘 |
| **3단계 · 내보내기** | 전부 | 시장조사표 Excel (현행 유지) |

**첫 화면 예산(1440×900 기준, 스크롤 전)**: 버튼 3개 이하, 설명문 2줄 이하, 표 0개(요약 막대만), 입력칸 2개(검색창, 내 견적가).

### 2-2. 메뉴 (사이드바)

```
가격 조사            ← 통합 검색 + 견적서 업로드 (기본 화면)
의료기기 상세        ← 현 '의료기기 조회'. 결과 화면의 링크로도 진입
──────────
(ADMIN_MODE=1 일 때만)
관리 · 검증          ← 견적추출 UAT, 전체 구매검토 UAT, 관리
```

- `상세 검색` 페이지는 메뉴에서 뺀다. 기능은 가격 조사 홈의 "조건 직접 입력" 펼침이 이미 담고 있다. 파일은 한 PR 동안 유지 후 삭제.
- `견적 검토` 페이지는 메뉴에서 뺀다. 견적서 업로드는 가격 조사 홈에 있고, 품목 요약표는 2-5절처럼 같은 화면에 넣는다. 6단계 상세검증은 "상세 검증 열기" 링크로만 간다(페이지 파일은 유지).

### 2-3. 결과 화면 — 0단계 (결론)

```
┌─────────────────────────────────────────────────────────────┐
│ [검색창: HeartOn A16-DS            ] [검색] [새 검색]        │
│                                                             │
│ HeartOn A16-DS                           [시장조사표 Excel] │
│ 저출력심장충격기 · 제조·수입 (주)메디아나 · 허가 제허 19-527 │
│                                                             │
│ ▸ 최근 1년 나라장터에서 같은 제품이 93번 거래됐고,            │
│   대부분 1,980,000원(중앙값)에 팔렸습니다.                   │
│   내 견적가 [ 2,100,000 ] 원  → 중앙값보다 6% 높음           │
│                                                             │
│   297,000 ────────●━━━━━━━━━━━━━━━━━━━━━━━━┫ 1,980,000       │
│   최저            내 견적 ▲                 최고             │
│                                                             │
│ ┌거래가──────┐┌납품업체────┐┌식약처 등록──┐┌안전정보─────┐  │
│ │1,980,000원 ││2곳         ││확인됨       ││회수 없음    │  │
│ │93건·최근10/1││72개 기관   ││제허 19-527 ││공식 자료 기준│  │
│ └────────────┘└────────────┘└────────────┘└────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

규칙:

- **결론 문장 1개**는 새 presenter 함수가 만든다(`ui/result_summary.py`, 순수 함수, 단위테스트). 화면에서 문장을 조립하지 않는다.
- 결론 문장은 자료 상태별로 고정 템플릿을 둔다. 직접거래 0건이면 "같은 제품으로 확인된 거래가 없습니다. 비슷한 품목 거래 N건은 아래에서 참고만 하세요." 조회 불가면 "가격 자료에 연결하지 못했습니다." **"적정"이라는 단어는 쓰지 않는다**(wireframes 규칙 유지).
- **내 견적가**는 결론 바로 옆 입력칸 1개. 단위·VAT·조건은 2단계 "상세 자료 > 견적 조건"으로 내린다. 입력하면 결론 문장과 막대 위 마커가 바뀐다.
- 가격대 막대: 최저–최고 선, 중앙값 굵은 점, 견적가 삼각형. 색은 상태색만. 직접거래 2건 이하이면 막대 대신 "거래 n건: 금액, 금액"으로 나열(막대가 과장하지 않게).
- "자료 기준 · … 53% 수집 중" 문장은 **카드 아래 작은 회색 한 줄**로 줄인다: `나라장터 2026-09-18 수집분 + 10-06까지 실시간 확인 · 식약처 자료 53% 수집 중`. 실시간 보강 건수 같은 세부는 2단계로.
- "국내 정상·취소 상태 불러오기" 버튼은 0단계에서 뺀다. 식약처 카드 안의 작은 글자 링크 "취소 여부 확인(약 30초)"로 옮긴다.

### 2-4. 결과 화면 — 1단계 (핵심 자료 3개, 탭 없이 세로)

각 섹션 = 제목 1줄 + 요약 표(최대 5행, 최대 6열) + "전체 N건 보기" 1개.

**① 얼마에 거래됐나**
- 표: 규격 · 거래조건 · 건수 · 최저 · 중앙값 · 최고 (현 `model_price_group_rows`에서 열만 고름)
- "거래 93건 전체 보기" → 같은 화면 안에서 펼침(`st.expander`) 또는 창(`st.dialog`). 열은 현행 10열 유지, 행은 전체.
- 비슷한 품목 거래(현 "참고거래")가 있으면 표 아래 한 줄: "비슷한 품목 거래 N건은 비교에 넣지 않았습니다 · 보기".

**② 누가 파는가**
- 표: 납품업체 · 거래 건수 · 납품 기관 수 · 최저 · 최고 · 최근 거래 (현 `supplier_rows`에서 Source·원문근거키 제외)
- 그 아래 한 줄: "식약처에 같은 품목으로 등록한 제조·수입업체 12곳 · 보기" → 펼치면 현 업체·조달 탭의 업체표 + 업허가 확인 버튼.

**③ 같은 품목의 다른 모델**
- 표: 모델 · 제조·수입업체 · 거래 건수 · 가격범위 · 최근 거래 (현 `same_item_ui.build_same_item_rows`에서 5열). 기본은 거래가 있는 모델만, 상위 5개.
- 체크박스 2개("조달가격 있는 것만", "취소·취하·수출용 포함")는 "전체 보기" 안으로 내린다.
- 섹션 끝에 "이 제품을 의료기기 상세에서 열기" 링크(현행 유지).

### 2-5. 결과 화면 — 2단계 (상세 자료, 맨 아래 한 묶음)

`st.expander("상세 자료 · 원문 · 확인 내역")` 하나 안에 소제목으로:

1. 견적 조건(단위 · VAT · 설치·운송) 입력
2. 안전정보 확인 내역(확인 시각, 확인키, 회수 기록표, 외부 링크 3개)
3. 식약처 등록 원자료(제품정보 인덱스표, 형명정보, 업허가)
4. 검색어 해석(품명·제조사·모델로 어떻게 풀었나)
5. 입찰·계약 참고자료 — "불러오기" 버튼은 여기에만. 결과도 여기에만.
6. 자료 기준 · 수집 상태(현 홈의 53.4% 펼침 내용)

### 2-6. 견적서를 올렸을 때 (같은 화면, master-detail)

```
견적서: 2026-10 OO업체 견적.pdf · 품목 4개 · [추출 내용 확인·수정]
┌───┬──────────────┬────────────┬───────────┬───────────┬──────────┐
│ # │ 품목·모델     │ 견적 단가   │ 거래 중앙값 │ 견적 위치  │ 상태      │
├───┼──────────────┼────────────┼───────────┼───────────┼──────────┤
│ 1 │ HeartOn A16-DS│ 2,100,000  │ 1,980,000 │ +6%       │ 확인됨    │
│ 2 │ (모델 미확인)  │   350,000  │ —         │ 비교 불가  │ 모델 확인 │
└───┴──────────────┴────────────┴───────────┴───────────┴──────────┘
행을 누르면 아래에 그 품목의 결론·핵심 자료가 그대로 뜬다 (2-3 ~ 2-5).
```

- 표의 "상태" 열은 노랑(사람이 할 일)/초록/회색 칩 텍스트. 색만으로 전달하지 않는다.
- 6단계 상세검증(원문 대조·조건 대조·승인)은 표 위 "상세 검증 열기" 링크로 현 `2_견적_검토.py`에 간다. 거기서 돌아오는 링크도 둔다.

### 2-7. 홈 (검색 전)

- 남기는 것: 제목 1줄, 검색창 + 검색 버튼, "조건 직접 입력" 펼침, 견적서 업로드 카드.
- 빼는 것: "식약처 데이터 수집 중 53.4%" 펼침(→ 2-5의 6번과 관리 메뉴), 검색창 아래 해석 설명 2문장, 페이지 맨 아래 면책 문장(→ 결과 화면 2단계 안으로).
- 검색창 아래 예시 한 줄만: `예: HeartOn A16-DS · 심장충격기 · (주)메디아나`

### 2-8. 용어 사전 (화면 문구 전부 교체)

| 지금 | 바꿀 말 | 비고 |
| --- | --- | --- |
