이 문서는 화면에 나오는 모든 "같은 제품 거래" 숫자의 정의다. 화면 문구가 아니라 계산 규칙을 적는다.

## 1. 계산 대상

| 항목 | 정의 |
| --- | --- |
| 같은 제품 거래 | 식약처 identity 정확 일치 또는 검증된 별칭으로 같은 모델임이 확인된 나라장터 납품요구 행(매칭등급 A/B). 비슷한 품목 거래(C/D/X)는 어떤 숫자에도 넣지 않는다 |
| 행 단위 | 납품요구번호 × 품목순번 1행 = 거래 1건. 한 납품요구에 같은 모델이 두 줄이면 2건이다(지금 모든 경로가 같음) |
| 변경차수 | 같은 납품요구·품목순번 중 가장 큰 변경차수 1행만 쓴다. 최신 행의 수량이 0이면 취소로 보고 뺀다(인덱스 조회와 실시간 보강이 같은 규칙) |
| 거래일 | 납품요구일(`cntrctDlvrReqDate`) |
| 기간 | 거래일이 기준일 이상인 행. 기본은 최근 3년이고, 사용자가 고르지 않았는데 3년 안에 거래가 없으면 5년, 전체 순으로 넓힌다. 날짜를 읽을 수 없는 행은 모든 기간에 남긴다 |
| 단가 | 원문 단가(`prdctUprc`)만. 금액 ÷ 수량으로 만든 단가는 세기만 하고 가격 계산에 넣지 않는다. 감사 결과 지금 인덱스에는 단가가 빈 행이 0건이라 실제 화면과 차이는 없다 |

## 2. 제외 규칙 (세기는 하고 값에는 넣지 않음)

| 규칙 | 기준 | 화면에서 |
| --- | --- | --- |
| 입력 오류 의심 | 단가 10원 이하, 또는 단가·수량 뒤바뀜(단가 10원 이하 · 수량 1,000 이상 · 수량×단가 = 총액) | 별도 상자에 사유와 함께 표시 |
| 다른 단위 | 기준 단위가 아닌 행. 단위는 대소문자·공백만 맞춰 비교하고 대와 set은 다른 단위다 | 단위별로 따로 표시 |
| 계산 단가 | 원문 단가가 없어 금액 ÷ 수량으로 만든 단가 | 지금은 0건 |

기준 단위는 가장 많이 쓴 단위다. 같으면 가장 최근 거래의 단위, 그다음 단위 이름 순으로 정한다. 전체 기간에서 고른 단위가 이번 기간에도 있으면 그 단위를 그대로 쓴다(기간을 바꿔도 같은 단위를 비교). 단위가 비어 있는 행은 기준 단위에 남긴다.

3배 이탈 거래(가운데 값의 3배 이상이거나 3분의 1 이하)는 **빼지 않는다**. 가격 계산 행이 3건 이상일 때만 "가운데 값과 크게 다른 거래"로 표시한다. 감사에서 기준 단위 거래가 4건 이상인 의료기기 모델 678개 중 328개(48%)에 이런 거래가 있었다. 가운데 값은 이런 거래에 크게 흔들리지 않으므로 빼지 않는 현재 방식을 유지한다.

## 3. 지표

| 지표 | 산식 | 표시 조건 |
| --- | --- | --- |
| 확인 건수 | 기간 안 같은 제품 행 수(모든 단위, 입력 오류 포함) | 항상 |
| 가격 계산 건수 | 기준 단위 · 원문 단가 · 입력 오류 아님 · 단가 0 초과인 행 수 | 항상. 확인 건수와 다르면 "제외 N건"을 함께 |
| 가운데 값(중앙값) | 가격 계산 행 단가를 정렬해 가운데 값. 짝수면 가운데 두 값의 평균 | 가격 계산 1건 이상. 3건 미만이면 값만 나열하고 판단 문구 없음 |
| 최저 · 최고 | 가격 계산 행의 최소·최대 | 가운데 값과 같음 |
| 총 수량 | 가격 계산 행 수량의 합. 한 행이라도 수량이 없으면 표시하지 않음 | 단위가 확정된 경우만 |
| 구매 기관 수 · 납품업체 수 | 공백·괄호만 지운 이름의 서로 다른 개수. 모든 단위, 입력 오류 제외. 비슷한 이름을 자동으로 합치지 않음 | 항상 |
| 최근 거래일 · 첫 거래일 | 기간 안 행의 최대·최소 거래일 | 항상 |
| 수량가중 평균 | Σ(단가×수량) ÷ Σ수량, 기준 단위만. 수량이 빈 행이 하나라도 있으면 계산하지 않음 | 상세 영역만(P3에서 제공 여부 결정) |
| 산술 평균 | 쓰지 않음 | — |

구매 기관 이름 정규화 효과를 감사했다. 의료기기 구매 기관 이름 9,856개 중 공백·괄호를 지워 합쳐지는 것은 4개다. 기관 코드가 인덱스에 없으므로 이름 그대로 센다.

## 4. 견적 비교와 근거 수준

**견적 차이**: 견적 단가 − 가운데 값(원), 그리고 (견적 단가 − 가운데 값) ÷ 가운데 값 × 100(소수 첫째 자리). 부호를 그대로 쓴다.

**비교 결과 상태** (네 가지뿐)

| 상태 | 조건 |
| --- | --- |
| 동일 제품 확인 필요 | 검색한 모델과 같은 제품인지 확인되지 않음 |
| 비교 근거 부족 | 가격 계산 건수 3건 미만, 또는 견적 단가 없음 |
| 확인 필요 | 견적 차이가 +20%를 넘음(비싸다는 뜻이 아니라 조건 확인), 또는 −20%보다 낮음(단위·수량·구성이 거래와 같은지 확인). 2026-10-13 최종 리뷰에서 아래쪽도 추가 |
| 거래 범위 안 (조건 미확인) | 그 밖. "(조건 미확인)" 꼬리말은 빼지 않는다 |

**근거 수준** (숫자 점수 없음, 이유를 함께 표시)

| 수준 | 조건 |
| --- | --- |
| 제한적 | 가격 계산 3건 미만, 또는 같은 모델명의 식약처 등록이 여러 건이라 같은 제품인지 모호함. 매칭등급 B(모델명은 같지만 제조사 미입력)만으로는 낮추지 않음 |
| 높음 | 가격 계산 10건 이상 · 구매 기관 3곳 이상 · 최근 12개월 안 거래 · 단위 혼합 없음 · 같은 제품 확인이 모호하지 않음 |
| 보통 | 그 밖 |

단위 혼합은 "제한적"이 아니라 "보통"으로만 막는다. 최근 3년 거래가 3건 이상인 의료기기 모델 1,187개 중 646개(54%)가 단위를 섞어 쓰고, 그중 대와 set을 섞은 모델이 203개다. 가운데 값은 이미 기준 단위만 쓰므로 단위 혼합만으로 근거를 낮게 보지 않는다.

감사 기준(정확 일치 가정)으로 근거 수준을 근사하면, 최근 3년 3건 이상 모델 1,187개 중 높음 89개, 보통 890개, 제한적 208개다.

**자료 기준일 지연**: 거래 인덱스 기준일이 오늘보다 3일 넘게 오래됐으면 지연으로 표시한다.

**제품군 참고 시세를 결론에 올리는 조건**: 같은 제품 가격 계산 건수가 3건 미만일 때만. 지금 화면은 0건일 때만 올린다(P1에서 바꾼다).

## 6. 현재 경로 인벤토리와 차이

| 경로 | 쓰는 곳 | 가운데 값 | 기간 | 단위 | 건수 |
| --- | --- | --- | --- | --- | --- |
| 결과 화면 (`pages/1_대시보드.py` → `ui/purchase_workspace.build_purchase_workspace_stats`) | 가격 조사 결론·카드 | `statistics.median` | 사용자 선택(기본 3년, 비면 넓힘) | 전체 기간 기준 단위 우선 | 단가 0 이하 행도 셈 |
| 견적 검토 (`ui/quote_review_layout.comparable_trade_stats`) | 견적서 품목 판정 | 계약 `price_metrics.summarize_same_model` | 항상 기본값(3년, 비면 넓힘) | 전체 기간 기준 단위 우선 (P1) | 가격 계산 행 |
| 의료기기 상세 (`ui/device_page.build_trade_summary`) | 의료기기 허가·안전 페이지 | `statistics.median` | 항상 기본값 | 기간 안 기준 단위 | 가격 있는 행 |
| 모델 목록 (`lookup_model_summaries` → `category_market.median`) | 같은 품목 다른 모델 표 | 직접 계산 | 전체 | 기준 단위 | 모델당 최대 500건(등급 판정 뒤) |
| 연도 표 (`ui/result_summary.year_summary_rows`) | 연도별 표 | 직접 계산 | 화면 기간 | 기준 단위 | 모든 단위 |
| 제품군 참고 시세 (`services/category_market.py`) | 같은 품목 시장 | 직접 계산 | 화면 기간 | **대·세트·식·조를 한 단위로 묶음** | 3배 이탈 **제외**, 동물용·부품 제외 |
| 쇼핑몰 참고 (`services/market_price_research.py`) | 입찰·계약 참고자료(판정에 안 씀) | 직접 계산 | 없음 | 섞임 | 입력 오류 검사 없음 |
| Excel (`services/market_survey_export.py`) | 시장조사표 | 계산 안 함 | 화면 기간 | **모든 단위 행을 그대로** | 입력 오류는 별도 시트 |

**차이 목록** (P1 이후 정리 대상)

1. **기준 단위 선택** — 해결됨 (P1): 견적 검토도 결과 화면처럼 전체 기간 기준 단위를 우선한다. `unit_changes_by_period`에서 둘 다 set 1건(9,500,000원)을 비교하고 견적 검토는 `비교 근거 부족`이 된다. 의료기기 상세는 아직 기간 안 기준 단위를 쓴다.
2. **건수 정의**: 결과 화면 건수는 단가 0 이하 행까지 센다. 실제 인덱스에서는 단가 0 이하 행이 입력 오류로 이미 빠지므로 차이가 나지 않는다.
3. **제품군 단위 묶음**: 제품군 참고 시세는 대·세트·식·조를 같은 단위로 보지만 같은 제품 가격은 대와 set을 나눈다. 두 숫자는 같은 화면에 있으므로 P3에서 제품군 쪽 설명 문구에 "대·세트·식을 1대로 봄"을 계속 표시한다.
4. **제품군 3배 이탈**: 제품군은 3배 이탈 거래를 시세에서 빼고, 같은 제품 가격은 빼지 않는다. 모집단이 다르므로 유지한다(작업지시서 3.2).
5. **제품군 계산 단가**: 제품군 로더는 단가가 비면 금액 ÷ 수량을 쓴다. 지금 인덱스에는 해당 행이 없다.
6. **Excel**: A_B 시트는 모든 단위 행을 넣고 가운데 값을 쓰지 않는다. 시트에서 직접 계산한 가운데 값은 단위가 섞인 모델에서 화면과 다르다. P1에서 요약 시트에 계약 지표(가격 계산 건수·가운데 값·기준 단위)를 쓴다.
7. **조회 상한**: 결과 화면 조회는 등급 판정 전 5,000행에서 자르고, 모델 목록은 판정 뒤 모델당 500건에서 자른다. 감사 기준 의료기기 모델 최대 거래 수는 5,000행보다 훨씬 작아 지금은 영향이 없다(미검증: 비의료 대량 품목).
8. **견적 차이 반올림**: 결과 화면·견적 검토·계약은 소수 첫째 자리, 쇼핑몰 참고는 반올림하지 않는다(판정에 쓰지 않음).
9. **제품군 거래 상한**: 제품군 참고 시세와 상위 모델은 같은 품목 코드의 최근 6,000줄(`CATEGORY_TRADE_LIMIT`)만 읽는다. 거래가 많은 품목(HeartOn A16-DS가 속한 자동심장충격기 등)은 기간 앞부분이 빠져, 상위 모델의 검색 모델 건수(163건)가 결론의 같은 제품 건수(266건)보다 적게 나온다. 화면 설명에 실제로 센 시작일을 적는다. 상한을 올릴지는 P2b 측정 뒤 정한다.
