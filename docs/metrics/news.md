# 병원 뉴스 지표·데이터 계약

- Phase: H0
- 조사 기준: `020224cf50f9e054e02982e1fac9d319dd6b6cd1`
- 예정 UI 기준: PR #341 커밋 `087fae2` (2026-10-12 조사 시점 `main` 미머지)
- 정본 코드: `services/news_radar.py`, `services/news_radar_index.py`, `clients/naver_news.py`

## 1. 사용할 수 있는 뉴스 필드 5개

뉴스 주요 이슈의 군집·점수·화면 표시는 아래 다섯 종류만 사용한다.

| 종류 | 현재 인덱스 필드 | 사용 범위 |
| --- | --- | --- |
| 제목 | `title` | 제목 토큰 유사도, 대표 제목, 화면 표시 |
| 링크 | `url`, `naver_link` | 원문 중복 제거, 대표 기사 이동 |
| 매체 | `source_domain` | 서로 다른 매체 수, 출처 표시, `data/news_sources.json` 등급 |
| 시각 | `published_at`, `detected_at` | 시간 창, 최초·최근 보도 시각, 최근성 |
| 키워드 | `keywords`와 인덱스의 `group_key`, `group_name` | 관련 병원·분류, 위험·정책 그룹 |

`article_id`는 식별자, `detected_at`은 수집 관리 시각이다. 이 둘은 별도의 기사 내용으로 취급하지 않는다.

## 2. 사용할 수 없는 데이터와 처리

- NAVER 검색 결과의 `description`과 기사 본문은 읽거나 저장하지 않는다.
- 검색 결과를 LLM, AI 요약·분류·학습, 감성 분석에 넘기지 않는다.
- 읽음·중요·관심없음 상태를 이슈 중요도 입력으로 사용하지 않는다.
- 허용된 원자료가 아닌 검색 결과에서 사건 원인이나 긍정·부정을 추론하지 않는다.
- 기사와 기사에서 파생한 이슈는 게시·최초 발견 시각 기준 21일을 넘겨 보관하지 않는다.

현재 v1 인덱스는 `news/v1/index.json.gz`이며 `version=1`, `retention_days=21`이다. 기사 payload는 `article_id`, `title`, `url`, `naver_link`, `source_domain`, `published_at`, `keywords`, `detected_at`만 가진다. H1이 이슈를 추가할 때도 원문이나 description을 추가하지 않는다.

## 3. 저장 위치와 지속성

| 데이터 | 운영 위치 | 실제 운영 지속성 |
| --- | --- | --- |
| 기사 인덱스 | R2 `news/v1/index.json.gz` | 수집 Job이 쓰고 앱은 읽음 |
| 읽음·중요·관심없음 | R2 `news/v1/status.json` 지원 코드 | 운영 앱 키가 읽기 전용이므로 현재는 세션에만 유지 |
| 키워드 정본 | `data/news_keywords.json` | 저장소 배포로 변경 |
| 그룹 켜기·끄기 | Streamlit `session_state` | 현재 브라우저 세션에만 유지 |
| 로컬 H 작업 | `.local/news-radar.json.gz` | 로컬 파일, Git 추적 제외 |

화면은 상태 쓰기가 실패하면 `STATUS_SESSION_ONLY_KEY`를 설정하고 이후 상태를 세션에만 둔다. H1은 운영에서 읽음·중요 상태가 영구 저장된다고 안내해서는 안 된다.

## 4. 키워드 설정 요구사항

1. 키워드 문구·제목 필수어·제외어·알림 방식의 정본은 `data/news_keywords.json`이다.
2. 사용자는 화면에서 그룹 단위로 켜고 끌 수 있다. 이 설정은 세션에만 적용된다.
3. H1 화면은 PR #341의 접힌 `관심 키워드 설정` 진입을 유지한다.
4. 화면에서 키워드 문구를 직접 추가·삭제해 저장하는 기능은 H1 범위가 아니다.
5. 문자·이메일은 실제 제공 상태에 맞게 표시한다. 미설정 기능을 제공 중으로 보이게 하지 않는다.
6. 구독자 주소는 별도 구독 저장소의 책임이며 뉴스 인덱스나 이슈 점수에 넣지 않는다.

## 5. PR #341 반영 뒤 화면 구조

PR #341이 머지된 뒤 기준 구조는 다음과 같다.

1. 제목 `병원 뉴스`와 원문 그대로 표시한다는 설명
2. 핵심 지표 3개: 새 기사, 오늘 기사, 마지막 확인
3. `새 기사 확인` 단일 주 행동
4. 문자·이메일 알림 준비 상태 안내
5. 접힌 `관심 키워드 설정`
6. `최신 기사`
7. 접힌 `상세 필터` 안의 자동 수집 상태·키워드 필터·정렬·상태 필터
8. 기사 카드: 시각, 제목, 출처, 키워드, 원문 링크, 상태
9. 구독 저장소가 연결됐을 때만 이메일 신청 UI

H1의 `오늘의 주요 이슈`는 4번과 5번 아래, `최신 기사` 위에 둔다. 기존 최신 기사 목록과 알림 준비 상태는 제거하지 않는다.

조사 시점에는 PR #341이 `origin/main`에 없으므로 위 구조는 커밋 `087fae2`의 diff로 확인한 예정 구조다. H1 착수 전 머지 여부를 다시 확인하고, 머지됐으면 Track H 브랜치에서 `git merge origin/main`을 한 번 실행한다.

## 6. 뉴스 빈 상태 매트릭스

아래 문구를 H1의 확정 문구로 사용한다. 원인과 다음 행동을 함께 보여 준다.

| 상태 | 확정 문구 |
| --- | --- |
| 인덱스 준비 중 | `뉴스 목록을 준비하고 있습니다. 잠시 뒤 다시 확인해 주세요.` |
| 저장 인덱스 없음·첫 수집 전 | `아직 자동으로 모은 기사가 없습니다. 첫 자동 확인이 끝나면 여기에 표시됩니다.` |
| 인증 정보 없음 | `뉴스 검색 연결 설정이 없습니다. 자동 수집 자료는 볼 수 있고, 직접 새 기사 확인은 연결 후 사용할 수 있습니다.` |
| 활성 키워드 0개 | `활성화된 관심 키워드가 없습니다. 관심 키워드 설정에서 한 개 이상 켜 주세요.` |
| 검색 결과 0건 | `선택한 조건에 맞는 기사가 없습니다. 기간이나 키워드 필터를 확인해 주세요.` |
| 수집 전체 실패 | `뉴스를 확인하지 못했습니다. 기존에 모은 기사는 그대로 표시합니다. 잠시 뒤 다시 확인해 주세요.` |
| 일부 키워드 실패 | `일부 키워드는 확인하지 못했습니다. 확인된 기사만 표시합니다: {키워드 목록}` |
| 인덱스 읽기 실패 | `자동으로 모은 기사를 불러오지 못했습니다. 잠시 뒤 다시 열거나 새 기사 확인을 이용해 주세요.` |
| 자동 수집 지연 | `자동 확인이 1시간 넘게 멈춰 있습니다. 마지막 확인 시각 이후 기사가 빠질 수 있습니다.` |
| 이슈 0건, 기사 있음 | `묶어서 보여 줄 주요 이슈가 없습니다. 아래 최신 기사에서 전체 내용을 확인해 주세요.` |
| 읽음·중요 저장 불가 | `읽음·중요 표시는 이 화면을 연 동안만 유지됩니다.` |

수집 실패나 이슈 0건은 기존 기사 목록을 숨기는 조건이 아니다.

## 7. H1 평가 계약

- 30~50건 저장 표본을 사람이 같은 사건 묶음으로 표시한다.
- 제목·매체·시각·키워드 그룹만 사용한 결과와 기준 묶음을 비교한다.
- 잘못 묶음과 누락을 각각 건수와 비율로 기록한다.
- 시간 창과 제목 유사도 임계는 평가표를 근거로 확정한다.
- 동일 입력은 항상 동일 이슈, 동일 순서, 동일 점수를 만든다.
- 기사 수만으로 중요도를 결정하지 않는다.
