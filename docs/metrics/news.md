## 1. 사용할 수 있는 뉴스 필드 5개

뉴스 주요 이슈의 군집·점수·화면 표시는 아래 다섯 종류만 사용한다.

| 종류 | 현재 인덱스 필드 | 사용 범위 |
| --- | --- | --- |
| 제목 | `title` | 제목 토큰 유사도, 대표 제목, 화면 표시 |
| 링크 | `url`, `naver_link` | 원문 중복 제거, 대표 기사 이동 |
| 매체 | `source_domain` | 서로 다른 매체 수, 출처 표시, 출처 등급 |
| 시각 | `published_at`, `detected_at` | 시간 창, 최초·최근 보도 시각, 최근성 |
| 키워드 | `keywords`와 인덱스의 `group_key`, `group_name` | 관련 병원·분류, 위험·정책 그룹 |

`article_id`는 식별자이고 `detected_at`은 수집 관리 시각이다. 별도의 기사 내용으로 취급하지 않는다.

## 2. 사용할 수 없는 데이터와 제목 불일치 기사

- NAVER 검색 결과의 `description`과 기사 본문은 읽거나 저장하지 않는다.
- 검색 결과를 LLM, AI 요약·분류·학습, 감성 분석에 넘기지 않는다.
- 읽음·중요·관심없음 상태를 이슈 중요도 입력으로 사용하지 않는다.
- 허용된 원자료가 아닌 검색 결과에서 사건 원인이나 긍정·부정을 추론하지 않는다.
- 기사와 기사에서 파생한 이슈는 게시·최초 발견 시각 기준 21일을 넘겨 보관하지 않는다.

NAVER 검색은 본문에만 검색어가 있는 결과도 돌려줄 수 있지만 애플리케이션은 `description`이나 본문을 읽지 않는다. 따라서 `news_radar.title_matches()`가 거짓인 항목은 단지 **제목 불일치 검색 결과**다. H1 화면은 이를 `제목에 키워드 없음`으로 표시한다. H1 군집·기사 수·매체 수·30~50건 평가 표본에서는 제목 불일치 항목을 제외한다.

H1 인덱스는 기존 경로 `news/v1/index.json.gz`에서 `version=2`, `retention_days=21`을 사용한다. 기사 payload는 `article_id`, `title`, `url`, `naver_link`, `source_domain`, `published_at`, `keywords`, `detected_at`만 가진다. 파생 `issues`에는 식별자, 대표 원문 제목, 기사 식별자, 그룹, 매체·기사 수, 최초·최근 시각, 대표 기사 식별자, 내부 정렬 점수만 저장한다. v1 payload와 `news-radar-index-v1` R2 메타데이터를 계속 읽고 다음 수집 때 v2로 쓴다. 파생 이슈 한 건이 깨진 경우 그 이슈만 건너뛰고 원본 기사 목록은 계속 읽는다.

다음 인덱스 형식 변경은 **리더 먼저, 라이터 나중** 순서를 지킨다. 새 리더가 현재 형식과 다음 형식을 모두 읽는 배포가 운영에 반영된 것을 확인한 뒤 수집 Job의 payload `version`과 R2 `schema`를 바꾼다. 동시 배포를 확인할 수 없으면 기존 version/schema를 유지하고 옛 리더가 무시할 수 있는 선택 필드를 덧붙이거나, 별도 키에 새 형식을 쓴다. 새 라이터가 옛 리더를 즉시 깨뜨리는 단일 단계 전환은 금지한다.

## 3. 저장 위치와 지속성

| 데이터 | 운영 위치 | 확인된 지속성 |
| --- | --- | --- |
| 기사 인덱스 | R2 `news/v1/index.json.gz` | 수집 Job이 쓰고 앱은 읽음 |
| 읽음·중요·관심없음 | R2 `news/v1/status.json` 지원 코드 | 운영 쓰기 권한은 미검증. 쓰기 성공 시 R2, 실패 뒤에는 해당 세션만 유지 |
| 키워드 정본 | `data/news_keywords.json` | 저장소 배포로 변경 |
| 그룹 켜기·끄기 | Streamlit `session_state` | 현재 브라우저 세션만 유지 |
| 로컬 H 작업 | `.local/news-radar.json.gz` | 로컬 파일, Git 추적 제외 |

2026-10-13에 비파괴 방식으로 `runtime_secrets.py`와 뉴스 페이지의 저장 분기를 점검했다. 운영은 `[r2_read]`를 포함한 읽기 전용 별칭을 지원하지만 실제 토큰 정책은 저장소에서 확인할 수 없고 상태 쓰기를 실행하지 않았으므로 **운영 쓰기 권한은 미검증**이다. `_save_status()`는 첫 쓰기 실패 전까지 영구 저장으로 간주하고, 실패하면 `STATUS_SESSION_ONLY_KEY`를 켠다. 현재 화면은 실패 전 `저장되어 다음에 열어도 그대로 보입니다`라고 표시하므로 낙관적이고 모호하다.

H1은 저장 능력을 확인하기 전에는 `읽음·중요 표시는 저장 가능 여부를 확인한 뒤 안내합니다.`처럼 중립적으로 표시하고, 쓰기 성공 또는 실패가 확인된 뒤에만 영구/세션 문구를 보여 준다. 상태 저장이 미확인인 동안 `아직 안 읽음` 수치는 장기 미열람을 뜻하지 않으므로 상단 핵심 지표에서 제외한다. PR #341의 3개 지표 구조와도 일치한다.

## 4. 현재 기사 중요도 규칙과 H1 연결 원칙

현재 `news_radar.rank_entries()`와 `by_priority()`의 규칙은 다음과 같다.

| 입력 | 점수 |
| --- | ---: |
| 제목 필수어 충족(제외어 없음) | +3 |
| 매칭 키워드 중 `our_hospital` 포함 | +4 |
| 매칭 키워드 중 `peer_hospitals` 포함 | +2 |
| 의학·병원 전문지 | +3 |
| 부산 지역지 | +1 |

여러 키워드가 맞아도 그룹 가중치는 가장 큰 값 하나만 쓴다. 중요도순은 총점 내림차순이며, 동점은 입력의 최신순을 유지한다. 출처 도메인은 `data/news_sources.json`의 하위 도메인 포함 매칭을 쓴다(`news_radar.py:131-218`).

H1 이슈 정렬은 제목 일치 기사별 현재 점수의 최댓값을 재사용한다. 수집 Job은 `data/news_sources.json`의 전문매체·지역매체 등급을 군집 함수에 전달한다. 회수·판매중지·리콜·안전성은 매칭 키워드뿐 아니라 허용 필드인 제목에서도 확인해 3점, 서로 다른 추가 매체 최대 3점, 최근성 최대 2점을 더한다. 기사 수 자체는 점수에 넣지 않고 점수는 화면에 노출하지 않는다. 상단에는 최근 보도 시각이 72시간 안인 이슈만 최대 5개 보여 준다. 최종 군집 산식과 임계는 `docs/NEWS_ISSUE_CLUSTER_EVAL_2026-10-13.md`에 기록했다.

## 5. 키워드 설정과 PR #341 예정 구조

키워드 문구·제목 필수어·제외어·알림 방식과 종합 소식 구분어 `issue_roundup_terms`의 정본은 `data/news_keywords.json`이다. 화면 토글은 세션에만 적용되며, 사용자가 키워드 문구를 직접 추가·삭제해 정본에 저장하는 기능은 H1 범위가 아니다. 문자·이메일은 실제 제공 상태에 맞게 표시하고, 구독자 주소는 별도 구독 저장소에 둔다.

PR #341 반영 뒤 구조는 제목·설명 → 핵심 지표 3개 → `새 기사 확인` → 알림 준비 안내 → 접힌 `관심 키워드 설정` → `최신 기사` → 접힌 상세 필터 → 기사 카드 순서다. H1은 `최근 3일 주요 이슈`를 알림 준비 안내 아래, `관심 키워드 설정`과 `최신 기사` 위에 배치했다. PR #341은 2026-10-13에 main으로 병합됐다.

## 7. H1 평가 계약

- 저장 인덱스에서 `title_matches()`가 참인 기사 30~50건만 표본으로 뽑아 사람이 같은 사건 묶음을 만든다.
- 제목·매체·시각·키워드 그룹만 사용한 결과와 기준 묶음을 비교한다.
- 잘못 묶음과 누락을 각각 건수와 비율로 기록한다.
- 시간 창과 제목 유사도 임계는 평가표를 근거로 확정한다.
- 동일 입력은 항상 동일 이슈, 동일 순서, 동일 점수를 만든다.
- 기사 수만으로 중요도를 결정하지 않는다.

2026-10-13 저녁 통합 담당이 최신순·전체 그룹 50건 홀드아웃을 실행해 업계 일반어(진료·솔루션·도입·공급 등)만 겹친 서로 다른 회사 소식이 한 이슈로 묶이는 것을 확인했고, H1 후속 2에서 제목 토큰 불용어를 추가했다. 결과(중요도순 50건 0/0 유지, 최신순 50건 잘못 묶임 40→0쌍, 누락 5→14쌍)는 `docs/NEWS_ISSUE_CLUSTER_EVAL_2026-10-13.md` 2차 평가에 있다. 런타임 마커 `news_radar.MODULES_REVISION = "2026-10-13-h1-review2"`.
