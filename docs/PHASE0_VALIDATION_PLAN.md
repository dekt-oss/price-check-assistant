# Phase 0 — 공개 가격데이터 가능성 검증 계획

작성일: 2026-09-03

## 1. Phase 0의 목적

Phase 0는 특정 10~20개 제품만 지원하기 위한 단계가 아니다.

목적은 **서로 성격이 다른 소수의 기준 제품(benchmark cases)을 정답셋처럼 사용하여, 공개 데이터만으로 가격검토 시스템이 실제로 성립하는지 측정하는 것**이다.

검증 질문은 다음과 같다.

1. 제품명·제조사·모델·규격으로 공개 가격자료를 찾을 수 있는가?
2. 찾은 자료가 동일제품(A) 또는 조건차이 동일모델(B)인지 판정할 수 있는가?
3. 실제 계약·납품가격과 예산·기초금액·일반 판매가를 구분할 수 있는가?
4. VAT·설치·배송·옵션·보증 등 비교조건을 어느 정도 확인할 수 있는가?
5. 모든 가격 근거를 원문 URL과 수집일로 재검증할 수 있는가?
6. 의료기기는 식약처 안전·회수정보까지 연결할 수 있는가?

## 2. 왜 10~20개인가

### 너무 적으면

2~3개 성공 사례만으로는 특정 제품이나 특정 사이트가 우연히 검색이 잘 된 것인지 구분하기 어렵다.

### 너무 많으면

Phase 0에서는 사람의 수작업 검증을 병행해 각 검색결과가 정말 동일 모델인지 확인해야 한다. 수십~수백 품목을 먼저 조사하면 collector 구현 전에 수작업 조사비용만 커진다.

### 따라서

10~20개는 통계적 성능 인증용 표본이 아니라 **기술·데이터 가능성(feasibility)을 빠르게 판별하기 위한 기준셋**이다.

초기 목표는 **15개 benchmark case**로 둔다. 실제 공개자료 분포가 한쪽으로 치우치면 10개에서 중간점검하고 최대 20개까지 보강한다.

## 3. Benchmark 구성 원칙

특정 품목군만 잘 되는 시스템을 만들지 않기 위해 난이도와 자료형태를 섞는다.

| 구간 | 목표 수 | 목적 |
|---|---:|---|
| 의료장비 | 5 | 모델·규격·옵션 차이가 큰 고가 장비 검증 |
| 의료기구·의료비품 | 3 | 중간가격대 및 규격 중심 비교 검증 |
| 전산·공기구비품 | 4 | 모델 식별과 일반 공개판매가 비교 검증 |
| 소프트웨어·유지보수 | 3 | 라이선스/계약조건형 가격의 한계 검증 |
| **합계** | **15** | |

각 구간에서 공개자료가 잘 나올 것으로 예상되는 품목과 어려울 것으로 예상되는 품목을 함께 포함한다.

## 4. 현재 우선 데이터원

### S1. 나라장터쇼핑몰 품목정보

- 단가계약 상품
- 다수공급자계약(MAS)
- 일반단가·3자단가 계약
- 납품요구·물품구매실적 계열 정보

**우선순위: 매우 높음**

실제 조달단가와 제품 식별번호를 확보할 가능성이 높아 첫 collector 후보로 본다.

### S2. 나라장터 계약정보

- 물품 계약 목록·상세
- 계약기관·수요기관
- 품명
- 계약체결일
- 계약번호 및 관련 계약정보

**우선순위: 매우 높음**

실제 체결 계약 근거를 찾는 핵심 데이터원으로 본다.

### S3. 나라장터 입찰공고

- 입찰공고
- 기초금액
- 공고 상세

**우선순위: 보통**

기초금액은 실제 낙찰·계약가격이 아니므로 직접 비교가격(A/B price evidence)으로 자동 승격하지 않는다.

### S4. 나라장터 사전규격

- 품명/사업명
- 배정예산액
- 규격서 파일

**우선순위: 보통**

제품 식별·규격 확인에는 유용하지만 배정예산은 실제 구매단가가 아니므로 보조근거로 취급한다.

### S5. 식약처 의료기기 회수·판매중지정보

- 제조·수입업체명
- 품목명
- 모델명
- 제조번호
- 회수·판매중지 사유
- 공표·명령일

**우선순위: 의료기기 필수 보조원**

가격자료는 아니며 의료기기 안전정보 연결에 사용한다.

### S6. 제조사 / 공개 유통 / 일반 판매 웹

Phase 0에서 병행 조사하되 사이트별 약관·robots·접근안정성·가격조건 표시 수준을 확인한 후 collector 대상 여부를 결정한다.

## 5. 가격 근거 타입을 처음부터 분리한다

| Evidence type | 예 | 직접 가격비교 사용 |
|---|---|---|
| CONTRACT_PRICE | 실제 체결 계약 단가 | O |
| SHOPPING_CONTRACT_PRICE | 나라장터쇼핑몰 계약단가 | O |
| DELIVERY_ORDER_PRICE | 납품요구/구매실적 단가 | O, 조건 확인 |
| PUBLIC_SALE_PRICE | 제조사·유통 공개 판매가 | B/C 가능 |
| BID_BASE_AMOUNT | 입찰 기초금액 | X — 보조근거 |
| BUDGET_AMOUNT | 사전규격 배정예산 | X — 보조근거 |
| QUOTE_SAMPLE | 공개 견적 사례 | 조건 확인 후 판단 |

**예산과 실제 구매가격을 혼합하지 않는 것이 Phase 0의 필수 계약이다.**

## 6. 제품별 검증 기록 필드

각 benchmark case마다 최소 아래 값을 기록한다.

- benchmark_case_id
- category
- manufacturer
- product_name
- model_name
- specification
- search_aliases
- source
- source_url
- evidence_type
- observed_price
- quantity
- unit
- VAT 상태
- 설치비 상태
- 배송비 상태
- 옵션/구성품
- 보증기간
- 계약일 또는 가격기준일
- 수집일
- match_grade (A/B/C/D/X)
- match_reason
- usable_for_direct_range (true/false)
- reviewer_note

## 7. Phase 0 측정지표

### 7.1 Source Hit Rate

`가격 또는 가격 관련 원문을 1건 이상 찾은 benchmark 수 / 전체 benchmark 수`

### 7.2 Direct Evidence Rate

`A/B 등급의 직접 비교 가능한 가격을 1건 이상 확보한 benchmark 수 / 전체 benchmark 수`

### 7.3 Multi-source Rate

`서로 다른 2개 이상 출처에서 근거를 확보한 benchmark 수 / 전체 benchmark 수`

### 7.4 Condition Completeness

VAT·설치·배송·옵션·보증 등 핵심 조건 중 확인 가능한 필드 비율을 기록한다.

### 7.5 Traceability Rate

`원문 URL + 날짜 + 출처를 재현 가능한 evidence 수 / 전체 evidence 수`

### 7.6 Safety Match Rate

의료기기 benchmark 중 식약처 모델/품목 기준 안전정보 검색을 정상 수행할 수 있는 비율을 기록한다.

## 8. Phase 0 진행 순서

### Step 0-A. 데이터원 계약 확인

각 API의 인증방식, 검색키, 응답필드, 호출제한, 데이터 갱신주기를 확인한다.

### Step 0-B. Benchmark 15개 확정

제품군·난이도·가격대가 한쪽으로 치우치지 않게 실제 제조사/모델까지 확정한다.

### Step 0-C. 사람 기준 수작업 조사

각 제품을 사람이 직접 검색하여 어떤 근거가 실제로 존재하는지 ground truth를 만든다.

### Step 0-D. 자동수집 PoC

우선순위가 높은 데이터원 1~2개를 API/collector로 연결하여 사람이 찾은 결과를 재현하는지 비교한다.

### Step 0-E. Go / Adjust / Stop 판단

- **Go**: A/B 가격근거와 제품식별이 충분히 재현됨
- **Adjust**: 특정 품목군·데이터원만 가능하여 범위를 수정해야 함
- **Stop/Redesign**: 공개정보만으로 직접 가격비교가 대부분 불가능함

## 9. Phase 0 완료조건

1. 10개 이상 benchmark의 수작업 ground truth 확보
2. 목표 15개 benchmark 검증 완료
3. 각 근거에 원문 URL·출처·수집일 저장
4. A/B/C/D/X 기준을 실제 사례에 적용해 모호한 부분 기록
5. 데이터원별 확보율·직접비교 가능률 비교
6. 첫 production-like collector 2~3개 우선순위 확정
7. 공개정보만으로 가능한 품목과 어려운 품목을 명확히 구분

## 10. 현재 결정

- 진료재료·진료소모품은 Phase 0 benchmark에서 제외한다.
- 실제 본원 단가, 실제 업체 견적서, 내부 계약문서는 Public PoC에 사용하지 않는다.
- benchmark 제품은 시스템 지원범위를 제한하기 위한 목록이 아니라 품질측정을 위한 기준셋이다.
