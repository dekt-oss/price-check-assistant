# 스킬 지도 · 안내 규칙 (Claude Code · Codex 공용)

> ⚠️ claude-config `shared/SKILL-MAP.md` 에서 **자동 배달**된 사본이다. 여기서 고치지 말 것.
> Claude Code 는 `skill-router` 스킬이, Codex 는 `AGENTS.md` 가 이 파일을 가리킨다 — 정본은 이 파일 하나다.

## 1. 언제 판정하나
- **작업을 시작할 때**(파일을 고치거나 명령을 돌리기 전) 한 번.
- **작업 중 상황이 바뀔 때** 다시 — 예: 조회가 0건으로 나왔다, 배포했는데 반영이 안 됐다, 같은 실패가 두 번째다.
- 질문에 답만 하는 턴, 파일 하나 읽어 주는 턴은 판정하지 않는다.

## 2. 판정 결과에 따라 이렇게 말한다

먼저 맞는 스킬을 두 종류로 가른다.
- **무료** — 읽기·점검·절차 스킬(이 지도 4절의 공용 스킬은 전부 무료다). 서로 충돌하지 않으면 같이 쓴다.
- **유료** — 실행하면 돈이 드는 것(유료 LLM·이미지·영상 API 호출, 렌더, 유료 외부 서비스). 프로젝트 전용 스킬의
  `description`·본문에 비용이 적혀 있으면 유료로 본다. 애매하면 유료로 본다.

| 상황 | 할 일 | 말하는 형식 |
|---|---|---|
| 맞는 스킬 0개 | 아무 말 없이 진행 | — |
| 무료 1~3개, 같이 써도 됨 | **한 번에 알리고 진행** | `🔧 스킬: <이름1>, <이름2> — <한 줄>` |
| 무료 4개 이상 | 지금 단계에 **가장 직접 맞는 3개만** 알리고 진행. 나머지는 이름만 덧붙이고, 그 단계가 오면 쓴다 | `🔧 스킬: <a>, <b>, <c> — <한 줄> (다음 단계 후보: <d>, <e>)` |
| 무료끼리 **방향이 갈림**(예: 원인 진단 먼저 vs 바로 수정) | 추천을 붙여 **묻는다** | 아래 "묻는 형식 A" |
| 유료가 하나라도 끼어 있음 · 승인 범위 **밖** | 무료 부분은 진행해도 되고, 유료는 **명시적 승인 전까지 실행하지 않는다** | 아래 "묻는 형식 B" |
| 유료 · 이미 승인한 범위 **안** | 다시 묻지 않고 진행, 한 줄 알림 | `🔧 스킬: <이름> — 승인 범위 안(<범위 요약>)` |

**묻는 형식 A — 무료끼리 방향이 갈릴 때**
```
이 상황에 맞는 스킬이 있습니다:
  1) <이름> — <무엇을 해 주는지 한 줄>  ← 추천
  2) <이름> — <한 줄>
번호로 답하시거나 "알아서"라고 하시면 1번으로 진행합니다.
```

**묻는 형식 B — 유료가 끼어 있을 때** (추천 1번은 무료 선택지가 있으면 항상 무료)
```
이 상황에 맞는 스킬이 있습니다:
  1) <무료 이름> — <한 줄>  ← 추천
  2) <유료 이름> — <한 줄>  💰 유료: <대상·횟수> · 약 ₩<금액> (상한 ₩<금액>)
💰 항목은 "2번 승인"처럼 번호를 들어 승인해 주셔야만 실행합니다. "알아서"는 1번(무료)으로 진행합니다.
```

**승인 규칙(유료)**
- 승인으로 인정하는 것은 **그 유료 항목을 지목한 명시적 동의**뿐이다: "2번 승인", "그 렌더 해", "₩5,000 까지 써도 돼".
- 승인이 **아닌** 것: 침묵, "알아서", "좋아"처럼 무엇을 승인하는지 모호한 말, 질문에 답하지 않고 다른 지시를 한 것.
  → 이때 유료는 **시작하지 않는다.** 무료 추천(1번)이나 새 지시를 진행하고, 끝 보고에 "💰 <항목>은 승인 대기"를 한 줄 남긴다.
- 승인 범위는 **스킬 · 대상 · 횟수 · 금액 상한**으로 기록한다: `승인: <스킬>, <대상>, <N회>, 상한 ₩<금액>`.
  범위 **안**이면 다시 묻지 않는다. 대상이 바뀌거나, 횟수·금액이 상한을 넘거나, 다른 유료 스킬이면 **다시 묻는다.**
- 승인은 그 대화(세션)에서만 유효하다. 새 대화에서는 다시 묻는다. 프로젝트 CLAUDE.md 의 비용 규칙이 더 엄격하면 그것을 따른다.

**공통**
- 한 작업 단계에 알림은 **한 번만**. 같은 스킬을 매 메시지마다 다시 알리지 않는다.
- 묻는 형식 A 에 답하지 않고 다른 지시를 하면 그 지시를 따르고, 무료 추천 1번을 쓴다(유료는 위 승인 규칙대로 시작하지 않는다).
- 작업 끝 보고(다섯 덩어리)의 "어떻게 해결했나"에 **`사용한 스킬: …`** 한 줄. 안 썼으면 생략하거나 `사용한 스킬: 없음`(승인 대기면 그 사실도).

## 3. 사용자가 쓸 수 있는 말
| 말 | 동작 |
|---|---|
| "스킬 지도 보여줘" | 아래 4절 표를 이 저장소에 실제로 있는 스킬만 골라 보여 준다 |
| "스킬 알림 꺼" / "켜" | 이 대화 동안 `🔧` 알림만 끄거나 켠다(스킬은 계속 쓴다). 방향이 갈리는 질문과 💰 승인 질문은 꺼도 묻는다 |
| "<스킬 이름> 써" | 판정과 상관없이 그 스킬을 쓴다 |
| "스킬 쓰지 마" | 이 작업에서는 스킬 없이 한다 |

## 4. 상황 → 스킬 지도
스킬 본문은 `.claude/skills/<이름>/SKILL.md` 에 있다. **이 저장소에 그 폴더가 없으면 그 줄은 건너뛴다**(공개 저장소는 일부를 싣지 않는다) —
없는 스킬은 알리지도, 추천하지도, `사용한 스킬` 에 적지도 않는다.

표는 각 스킬 `description` 의 발동 조건을 **빠짐없이** 옮긴 것이다(2026-11-10 대조). 표와 `description` 이 다르면 `description` 이 맞다 —
표를 고친다. 한 줄에 여러 상황이 있으면 **하나만 맞아도** 후보다.

**스킬이 아닌 것**(같은 시점에 함께 한다): 커밋·PR 직전 독립 검사(5절) · "됐다"고 말하기 전 `bash scripts/smoke.sh`(마지막 줄 `SMOKE OK n/n`).

**프로젝트 전용 스킬:** `.claude/skills/` 중 `.claude/shared/managed-skills.txt` 에 없는 것은 그 프로젝트 것이다
(예: Aria `aria-task`, VIDEO-ARTICLE `verify-before-done`). 각 `SKILL.md` 맨 위 `description` 을 읽고 같은 규칙(2절)으로 판정한다.

## 5. 도구별로 쓰는 법
**어느 검사 AI 인가**(두 도구 공통, 정본은 HARNESS §3): 프로젝트 `CLAUDE.md`·`AGENTS.md` 가 이름으로 지정한 검사 AI(예: Aria → `aria-reviewer`)가
있으면 `.claude/agents/<그 이름>.md`, 없으면 `.claude/agents/harness-reviewer.md` + 점검표 `.claude/review-checklist.md`.

- **Claude Code**(PC·클라우드): 스킬은 Skill 도구로 부르고, 검사 AI 는 위 파일 이름의 서브에이전트로 **새 맥락에서** 띄운다.
- **Codex**: Skill 도구가 없다 — 고른 스킬의 `.claude/skills/<이름>/SKILL.md` 를 **직접 읽고 그 절차를 따른다.** 리뷰는 두 경우를 구분한다.
  - **(가) 사용자가 리뷰를 맡겼을 때**(읽기 전용 리뷰): Codex 가 독립 검사자다. 위 검사 AI 파일의 순서·보고 형식을 그대로 따르고,
    파일을 고치지 않고, 마지막 줄을 `판정: PR 진행 가능` / `판정: 수정 후 재검사 필요 (❌ N건)` 로 끝낸다.
  - **(나) Codex 가 코드를 바꾼 뒤 커밋·PR 직전**: 같은 세션의 점검은 독립 검사가 아니다(HARNESS §3). 검사 AI 파일 절차로 점검하되
    **"자체 점검(독립 검사 아님)"** 으로 적고, PR·보고에 **"독립 검사 대기"** 를 남기고, 독립 검사 판정 전에는 머지하지 않는다.
