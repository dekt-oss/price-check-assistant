# 공통 하네스 (모든 프로젝트 공통 규칙)

> ⚠️ 이 파일은 `dekt-oss/claude-config` 의 `shared/HARNESS.md` 에서 **자동 배달**된 사본이다.
> 여기서 고치지 말 것 — 다음 배달 때 덮어써진다. 고칠 곳은 claude-config 한 곳뿐이다.
> **프로젝트 CLAUDE.md 가 이 파일과 다르게 말하면 프로젝트 쪽이 이긴다**(머지 방식·검사 명령 등).
> 공용 스킬(목록: `.claude/shared/managed-skills.txt`)과 완료 보고 훅(`.claude/hooks/wcr-*.sh`)도 같이 배달된다 —
> 그것들도 여기서 고치지 말고 claude-config 에서 고친다. 목록에 없는 스킬은 그 프로젝트 것이다.

## 1. 완료는 말이 아니라 증거로
- "됐다·고쳤다·통과했다"는 **그 프로젝트의 검사 명령을 실제로 돌린 출력**을 보고에 붙일 때만 쓴다.
  **`bash scripts/smoke.sh`** 를 돌려 마지막 줄(`SMOKE OK n/n`)을 그대로 붙인다. smoke.sh 가 없는 저장소는
  CLAUDE.md 의 검사 명령(test·typecheck·lint 등) 결과 줄을 붙인다. `SMOKE FAIL` 이면 완료라고 쓰지 않는다.
- smoke.sh 는 프로젝트가 단계(검사 명령)만 적고, 출력 형식은 공용 `.claude/shared/smoke-run.sh` 가 정한다.
  돈이 드는 호출·외부 쓰기·배포는 smoke 단계에 넣지 않는다.
- 증거가 없는 문장에는 `(미검증)` 을 붙인다. 머지·배포·PR 생성은 "완료"가 아니다.

## 2. 같은 문제로 2번 실패하면 멈춘다
- 같은 오류·같은 목표로 **두 번 연속** 고치기에 실패하면 세 번째 시도를 하지 않는다.
- 멈추고 보고한다: ① 증상 ② 시도한 두 가지와 각각 왜 안 됐는지 ③ 다음 가설 하나 ④ 필요한 것(권한·정보·결정).
- 돈이 드는 호출(LLM·이미지·영상·유료 API)이 실패하면 **한 번**에서 멈추고 원인부터 본다.

## 3. 만든 AI 와 검사하는 AI 를 나눈다
- 코드를 바꾼 작업은 커밋·PR 직전에 **독립 검사**를 받는다: 고치지 않고 보고만 하는 서브에이전트를 새 맥락으로 띄워
  변경 diff 만 주고(내 결론·가설은 주지 않는다) ✅/⚠️/❌ 로 판정받는다.
- **어느 검사 AI 를 쓰나:** 프로젝트 `CLAUDE.md`(또는 `AGENTS.md`)가 **이름으로 지정한** 검사 AI(예: Aria → `aria-reviewer`)가 있으면 그것,
  없으면 공용 **`harness-reviewer`**. `.claude/agents/` 에 다른 `*-reviewer.md` 가 있다는 것만으로 고르지 않는다(지정이 기준).
  harness-reviewer 는 그 프로젝트의 점검표 **`.claude/review-checklist.md`** 를 읽고 항목마다 판정한다 — 프로젝트에서
  "이건 꼭 봐야 한다"가 생기면 그 파일에 한 줄 더한다(점검표는 프로젝트 소유, 배달되지 않는다).
- ❌ 가 있으면 고친 뒤 **다시 검사**받는다. 검사 결과 요약은 PR 설명에 적는다.
- **기본 방식(Claude Code 가 주 작업자일 때, 2026-11-10·11-12 소유자 결정):** 큰 작업은 기획 → Codex 계획 리뷰 → 승인 → 구현 →
  Codex 코드 리뷰 → 위 검사 AI 를 **model `fable`** 로 띄운 최종 검사, 간단한 작업은 구현 → 페이블 최종 검사. 순서·Codex 명령·
  한도 초과 자동 생략은 **`.claude/shared/ORCHESTRATE.md`**(스킬 `orchestrate`). Codex 는 추가 감리이고 독립 검사를 대신하지 않는다.
- **새 맥락으로 띄울 수 없는 도구**(서브에이전트가 없는 Codex 단일 세션 등)에서는 같은 세션이 한 점검을 독립 검사라고 부르지 않는다:
  ① 검사 절차대로 점검하되 보고·PR 에 **"자체 점검(독립 검사 아님)"** 으로 적고 ② **"독립 검사 대기"** 를 남기고
  ③ 독립 검사(다른 세션 — 예: Claude 의 검사 AI, 새 Codex 세션 — 의 판정)를 받기 전에는 머지하지 않는다(프로젝트가 에이전트 머지를 허용해도).
- 문서만 바꾼 작업은 생략할 수 있다(보고에 "문서만 — 검사 생략" 이라고 적는다). **단, 프로젝트 CLAUDE.md 가
  검사를 필수로 정했으면(예: Aria) 문서만 바꿔도 생략하지 않는다.**

## 4. 돈 드는 대량 작업은 승인 먼저
- 유료 LLM·이미지·영상 API 를 수백 번 이상 부르거나 비용이 예상되는 작업은 무료 대안(기존 결과 재사용·규칙·SQL·
  표본 소량)을 먼저 찾고, "N건 · 약 ₩X" 를 말한 뒤 **명시적 승인**을 받는다. "전수조사 해봐" 는 승인이 아니다.

## 5. 지어내지 않는다 · 우회하지 않는다
- 외부 API 형식·가격·URL·데이터는 **실제로 확인한 것만** 쓴다. 확인 못 하면 확인 못 했다고 쓴다.
- 사이트가 봇 차단·요청 제한을 걸면 멈춘다. UA 위장·IP 변경·프록시 같은 우회를 하지 않는다.
- 문서에 적힌 옛 상태를 그대로 말하지 말고 지금 상태를 실제로 확인한다.

## 6. 비밀값
- 키·토큰은 코드·커밋·로그·PR 에 쓰지 않는다. `.env` 는 커밋 금지, `.env.example` 만 커밋.
- 브라우저·앱 번들로 나가는 변수(`NEXT_PUBLIC_*`·`EXPO_PUBLIC_*`)에는 공개 가능한 값만 둔다.

## 7. 지시서(CLAUDE.md)를 짧게 유지한다
- CLAUDE.md 에는 **항상 지킬 규칙과 문서 지도**만 둔다. 사고 경위·운영 이력·실측 기록은 `docs/` 로 보내고 링크만 남긴다.
- 규칙을 하나 더할 때는 지울 수 있는 낡은 규칙이 있는지 같이 본다.
- 줄이는 대상은 이력·경위다. 헌법·불변 원칙·최상위 기준 절(예: Aria 의 "분석 헌법")은 이 규칙을 이유로 줄이지 않는다.
- 여러 프로젝트에 공통인 규칙이면 프로젝트 CLAUDE.md 가 아니라 claude-config `shared/HARNESS.md` 에 넣는다.

## 8. 보고 형식
- 모든 답은 두괄식(결론 먼저). 코드·설정·데이터·문서를 바꾼 턴의 마지막 보고는 다섯 덩어리
  **시키신 것 / 문제가 뭐였나 / 어떻게 해결했나 / 이렇게 확인하세요 / 다음 작업** 순서로, 코드를 안 읽는 사람이
  이해하는 쉬운 말로 쓴다. 자세한 형식: `work-completion-report` 스킬.

## 9. 스킬은 알리고 쓴다
- 작업을 시작할 때와 상황이 바뀔 때 **`.claude/shared/SKILL-MAP.md`** 로 맞는 스킬을 판정한다(Claude Code 는 `skill-router` 스킬).
- 무료 스킬은 `🔧 스킬: 이름 — 이유` 한 줄로 알리고 진행(4개 이상이면 지금 단계에 맞는 3개), 무료끼리 방향이 갈리면 번호로 묻는다.
- **유료 스킬은 그 항목을 지목한 명시적 승인 없이는 시작하지 않는다** — "알아서"·침묵·다른 지시는 승인이 아니다(§4 와 같은 원칙).
  이미 승인한 범위(스킬·대상·횟수·금액 상한) 안이면 다시 묻지 않는다.
- 끝 보고에 `사용한 스킬: …` 을 적는다. 사용자는 "스킬 지도 보여줘"·"스킬 알림 꺼"·"<스킬> 써" 로 조정할 수 있다.
