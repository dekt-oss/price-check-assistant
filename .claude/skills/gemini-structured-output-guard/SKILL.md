# Gemini Structured Output Guard

## 언제 쓰나
- Gemini를 새 정형 출력(JSON) 단계에 붙일 때 — 채점·추출·분류·라벨 OCR 등
- Claude → Gemini로 백엔드를 교체하거나 폴백 체인에 넣을 때
- "JSON이 비었다/잘렸다", "응답 시간이 들쭉날쭉하다", "무료로 쓰는데 어느 순간부터 결과가 이상하다"를 진단할 때

## 왜 필요한가
세 레포가 **각자 독립적으로** 같은 문제를 겪고 같은 결론에 도달했다(3개 레포 3회 — 횟수·다양성
기준을 동시에 충족).

- **k-vivino** `5c67722` — 라벨 OCR이 7.8초 걸린다는 지적에서 출발했는데, 재보니 사진 크기는 원인이
  아니었다(400px 23.8초 · 1200px 7.1초로 **거꾸로**). 진짜 원인은 Gemini 2.5 계열의 thinking이
  기본으로 켜져 있어 매번 "생각"을 붙이는 것 — 글자를 읽어 JSON으로 옮기는, 추론할 게 없는 일인데
  크기와 무관하게 7~29초로 널뛰었다.
- **Aria** — 정형 출력 JSON이 잘려서 `reasoning_effort=none` + 출력 상한 상향으로 해소했다.
  (`llm_structured.py`가 Gemini 기본 · Anthropic 폴백 구조인 이유가 여기 있다)
- **VIDEO-ARTICLE** — Edge Function의 Gemini 무료 쿼터가 소진되자 유료 러너 키로 전환해야 했다.
  쿼터 소진은 **에러가 아니라 성공처럼 생긴 응답**으로 와서 별도 감지가 필요했다.

세 처방이 이미 같은 방향으로 수렴해 있다 — thinking을 코드에 박지 말고 env로 빼서 0(끔)을
기본으로, 출력 상한은 별도로 확보, 쿼터 소진은 따로 감지.

## 체크리스트

### 1. thinking / reasoning 예산
- [ ] thinking(추론) 예산을 **명시적으로 0 또는 끔**으로 설정했는가? 기본값에 맡기지 않는다.
- [ ] 그 값을 **코드에 하드코딩하지 않고 env로** 뺐는가? (k-vivino `GEMINI_THINKING_BUDGET`,
      Aria `reasoning_effort=none` — 나중에 되돌리거나 단계별로 다르게 줄 수 있어야 한다)
- [ ] 이 단계가 정말 추론이 필요한 일인가? 글자 읽기·형식 변환·분류는 필요 없다.

### 2. 출력 예산
- [ ] thinking을 끈 것과 별개로 **출력 토큰 상한을 충분히** 잡았는가?
      (thinking이 켜져 있으면 completion 예산을 먼저 먹어 JSON이 비거나 잘린다)
- [ ] 같은 로직이 두 런타임(엔진 vs Edge Function)에 복제돼 있다면 **양쪽 상한이 같은가?**
      — VIDEO-ARTICLE에서 엣지 트윈만 2048로 남아 있던 사고가 반복됐다
      (`value-duplication-drift-audit`와 함께 본다)

### 3. 무료 쿼터 소진 감지
- [ ] 쿼터 소진 시 응답이 **에러가 아니라 성공 형태**로 올 수 있다는 것을 전제로 짰는가?
- [ ] 응답 본문이 안내문·빈 결과일 때 명시적으로 예외를 던지는가?
      (`error-vs-empty-audit`의 대표 사례가 정확히 이것이다)
- [ ] 폴백(Anthropic 등)으로 넘어갈 때 **폴백이 실제로 걸리는지** 로그로 확인 가능한가?

### 4. 전후 실측 비교 (필수)
- [ ] 설정을 바꾼 뒤 **같은 입력 세트로 전후를 실제로 재봤는가?**
      k-vivino 사례는 "효과는 아직 미측정 — Edge Function 배포 권한이 없어 재보지 못했다"를
      커밋에 명시한 채 남았다. 같은 라벨/문서 10건 이상으로 응답시간·성공률을 전후 비교한다.
- [ ] JSON 파싱 실패 시 1회 재시도 → 실패 시 로그 남기는 경로가 있는가?

## 사용 방법
Gemini를 정형 출력에 붙이는 커밋 직전에 §1~§3을 설정으로 못박고, 배포 후 §4로 전후를 실측한다.
"느리다/비었다"는 증상을 만나면 사진 크기·프롬프트 길이 같은 그럴듯한 원인을 추정하기 전에
§1(thinking 기본 켜짐)부터 확인한다 — 실측이 추정을 뒤집은 사례가 이미 있다.
