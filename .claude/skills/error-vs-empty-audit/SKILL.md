# Error vs Empty Audit

## 언제 쓰나
- 외부 API·DB를 조회해 결과를 세거나 화면에 뿌리는 코드를 쓸 때
- 루프 안에서 조건에 안 맞는 항목을 `continue`/`skip`으로 넘길 때
- 배치·워커·크론이 여러 항목을 처리하고 잡 단위로 성공/실패를 보고할 때
- "0건이다", "데이터가 없다", "사이트에 사진이 없나 보다" 같은 결론을 내리기 직전
- 비용 원장·주문 기록·계측 수치가 예상보다 적거나 0일 때
- 이미 돌고 있는 수집·주문 처리에 **운영 감시**를 붙일 때 (v1.1)

## 왜 필요한가
**3개 레포 21회.** 메커니즘은 매번 다르지만 결과는 같다 — 실패가 화면·로그·CI 어디에도
도달하지 못하고 사라져서, 사람이 "없는 것"으로 읽는다. 실제로 돈을 잃을 뻔한 사례가 있다.

- **Aria** `de4ce15` — psycopg2가 UUID를 어댑트 못 해 매수 사이클 INSERT가 예외를 던지고 장중
  루프 전체가 죽어 **5일간 BUY 주문 0건**이었는데 화면 어디에도 안 보였다.
- **Aria** `4c2ab13` — 청산 멱등키에 회차가 빠져 재진입 종목의 손절 신호가 중복 처리되고, 그
  중복은 `order_log`에도 `research_signal`에도 흔적을 안 남겨 **손절 8회 중 매도 0건**이
  실측으로만 발견됐다(-1.75% 손실 보유 중).
- **k-vivino** `a0f680c` — Apify 수집 Actor가 무료 한도를 소진하면 결과 대신 안내문 1행을 담고
  `status: SUCCEEDED`로 끝난다. 495종 중 46종만 받고도 "성공"으로 기록됐다.
- **k-vivino** `337bcd9` — `ignoreDuplicates`로 스킵된 행을 삽입 건수로 세어, 실제 삽입 0건인데
  "적재 완료: 5건"으로 보고했다(성공 카운트 자체가 거짓인 변종).
- **k-vivino** `d98cd2f` — 채널 등록이 목록에만 적히고 행 생성 insert가 빠져 이후 update가 0건짜리
  무동작으로 돌았고, 적재 스크립트도 매핑 없는 항목을 세지 않고 `continue`해 **나흘간 3,383건이
  조용히 버려졌다.**
- **k-vivino** `20f3023` — Supabase가 402(요금 한도)로 막힌 것을 "랭킹 데이터가 0건"으로 오판할
  뻔했다. 화면이 비어 보이는 것과 데이터가 없는 것을 구분하지 못했다.
- **k-vivino** `b0c0311` — `price_observations`가 append-only인데 필터 없이 세어, 이미 새 관측으로
  대체된 과거 값까지 "살아있는 관측"으로 잡았다(이력≠현재 제품 4,900개).
- **VIDEO-ARTICLE** `410c67e`·`bc4efe9`·`244739f` — 비용 원장이 **세 번** 0행이 됐다(설계상 예외
  삼킴 → 조회 error 폐기 → 외래키 위반 거부, 셋 다 "기록 실패는 삼켜진다").
- **VIDEO-ARTICLE** `dd21fc2` — Supabase 조회의 조용한 상한 두 가지에 호출부가 error를 버려,
  프로덕션에 478건 있는데도 "채점 결과가 없습니다 — 엔진을 실행하세요"로 보였다.

## 체크리스트

### 1. 실패를 삼키는 자리 찾기
- [ ] `catch {}`·`except: pass`·`.catch(() => [])`처럼 예외를 **빈 값으로 바꾸는** 자리가 있는가?
      의도적 방어라도 "못 물어봤다"와 "없다"가 같아지면 안 된다.
- [ ] 조회 응답의 `error` 필드를 버리고 `data`만 반환하는 자리가 있는가?
- [ ] 루프 안 `continue`/`skip`이 **세지도 로그하지도 않고** 넘어가는가?
- [ ] 잡·워크플로가 항목 단위 실패를 삼키고 전체는 `success`로 끝나는가?

### 2. 무엇을 세고 있는지 확인하기
- [ ] 이 카운트는 **시도 수**인가 **실제 성공 수**인가? (`ignoreDuplicates` 스킵을 삽입으로 세지 않는가)
- [ ] 조회에 **조용한 상한**이 있는가? (PostgREST 기본 1,000행 캡, `.in()` 목록 길이 한계 등 —
      `range()`/청크 없이 읽으면 잘린 결과가 전체인 척한다)
- [ ] 읽는 테이블이 **append-only(이력)** 인가? 그렇다면 현재값만 골라내는 필터가 있는가?
- [ ] 화면이 "결과 없음"을 판정하는 기준과 계측이 세는 기준이 **같은 값**인가?

### 3. 상태를 갈라서 남기기 (처방)
- [ ] 실패·차단·스킵을 빈 결과와 **다른 상태값**으로 기록했는가?
      (예: `log_signal("blocked", 사유)`, 사이클 메타데이터에 소스별 상태·오류 수)
- [ ] 성공 응답으로 위장하는 외부 실패(쿼터 소진 안내문 등)를 명시적으로 예외로 바꿨는가?
- [ ] 재발 시 CI/테스트가 잡도록 고정했는가? (`enforce-by-type-or-test` 스킬과 함께 쓴다)

### 4. 실패가 "멈춘 상태"로 숨는 경우 (v1.1 추가)
예외도 빈 값도 아니고, 항목이 **중간 상태에 머문 채** 아무 일도 안 일어나는 형태다. 에러 로그가
없어서 가장 오래 숨는다.
- [ ] "접수됨·시도 중·대기" 같은 중간 상태에 **얼마나 오래 머물 수 있는지** 상한이 있는가?
      Aria `2f0ab5a`(09-30) — 두 API 가 같은 주문번호를 앞자리 0 이 있고 없게 줘서 매칭이 안 됐고,
      6월 이후 미국 주문 **214건이 한 번도 체결 확정 없이 '접수' 상태**로 남았다.
- [ ] 두 시스템의 식별자를 비교할 때 **표기를 정규화**했는가? (앞자리 0, 대소문자, 공백, 하이픈)
- [ ] 페이지가 이어지는 조회에서 "다음 페이지 있음" 신호를 **응답 헤더까지** 읽는가? 본문만 보면
      첫 페이지에서 조용히 멈춘다(Aria `36c1c92` 10-04, KIS 연속조회 `tr_cont`).

### 5. 바깥이 바뀌어 조용히 0건이 되는 경우 — 운영 감시 (v1.1 추가)
§1~§3 은 코드를 **쓸 때** 점검이다. 코드는 그대로인데 바깥(외부 사이트·API)이 바뀌면 정상 코드가
매일 0건을 성공으로 기록한다. 이건 쓸 때 점검으로는 못 잡고 **돌고 있는 동안 감시**해야 한다.
- [ ] 수집·동기화마다 **평소 몇 건이 정상인지 실측 기준선**이 있는가? (추측 숫자 금지 —
      `magic-number-audit`) Aria `5c2fca2`·`f89ad4c`(10-04) — 네이버 리서치 페이지 개편으로
      9/10 부터 **3주 넘게 0건**이었는데 로그에만 남았다. 처방은 6/8~10/2 실측(영업일 0건은 한 번도 없음)을
      근거로 직전 영업일 출처별 0건을 아침 브리핑에 올리는 것.
- [ ] 0건이 기준선보다 낮으면 **사람이 보는 곳**(알림·대시보드)에 뜨는가? 로그만으로는 안 된다.
- [ ] 외부 API 가 필수 파라미터가 빠져도 200 과 0건을 돌려주지 않는지 처음 붙일 때 확인했는가?
      (k-vivino `17d9d1f` 09-09 몰테일)
- [ ] 실패를 빈 결과로 **캐시하지** 않는가? 실패가 한 시간 동안 "없음"으로 고정된다
      (k-vivino `0629415` 10-01 — 앱이 timeout 을 빈 배열로 받아 캐시해 상세의 가격 위치가 사라짐.
      처방: 오류는 던져서 재시도하게 하고 캐시하지 않는다).
- [ ] 일시적 사고(429·timeout)와 진짜 판정 실패를 **다른 결과로** 남기는가? 사고로 0점을 저장하면
      영영 "점수 낮은 항목"으로 보인다(VIDEO-ARTICLE `08582e9` 09-22, `TransientScoringError` 로
      사고는 저장하지 않고 다음 실행이 다시 집어 가게 함).

## 사용 방법
조회·수집·집계 코드를 쓰는 커밋 직전에 §1·§2를 훑고, 하나라도 걸리면 §3으로 상태를 갈라 놓는다.
"0건이다"라는 결론을 보고하기 전에는 반드시 §2를 먼저 통과시킨다 — 0건은 결론이 아니라
**확인이 필요한 신호**다. 이미 운영 중인 수집·주문에는 §4·§5 로 "멈춤"과 "조용한 0건"을 감시한다.
