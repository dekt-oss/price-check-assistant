# Gate–Prompt–Feedback Parity

## 언제 쓰나
- LLM 출력에 상한(컷 수·초수·에셋 수·비용)이나 금지 조건을 새로 걸 때
- 검증 함수·계약(contract)·게이트를 추가하거나 기준을 바꿀 때
- 재생성·재시도 루프를 만들거나 고칠 때
- **"모델이 계속 같은 자리에서 막힌다"**, "재생성해도 똑같다", "정상 산출물이 승인 단계에서 막힌다"를 진단할 때

## 왜 필요한가
VIDEO-ARTICLE이 **하루(2026-08-31) 안에만 5회 이상** 같은 형태를 반복했고, 커밋들이 스스로
"네 번째다"·"세 번째다"라고 셌다. 형태는 항상 같다 — 게이트는 어떤 기준으로 막을지 정확히 알고
있는데, **그 기준을 프롬프트가 모델에게 말해 준 적이 없어** 모델은 자기가 왜 막힐지 알 방법이 없다.

- `5e40254` — 원문 확보 수준(`source_depth`)이 낮으면 특정 서술을 통째로 금지하는데, 프롬프트는
  **그 값 자체를 모델에게 말한 적이 없었다.** 커밋이 "네 번째"라고 셌다(앞선 셋: 컷 수 상한,
  영상 초수 상한, 에셋 상한).
- `6b700f6` — 금지문을 `[motion_prompt 금지]`처럼 특정 필드로 좁혀 썼는데 게이트는 실제로 두
  필드를 검사했다. *"금지문이 필드 이름으로 범위를 만들고 있었다."*
- `d4fd876` — **되먹임 자체가 반쪽**이었다. 차단 사유를 두 계약에서 모으는 함수는 있는데 재생성
  루프는 하나만 읽어, 다른 계약만 위반한 산출물은 **재생성 기회 없이 그대로 사람 검수로** 넘어갔다.
  `feedback_prompt` 함수는 저장소 어디서도 안 불리고 있었다(grep 0건). 게다가 차단 사유 24개 중
  **7개는 처방 문장 자체가 없어** 걸려도 무엇을 고쳐야 하는지 모델에게 전달할 말이 없었다.
- `836db36` — 영상 상한을 48→110초로 올리며 하드캡은 올렸는데 **승인 예산은 그대로 둬**, 등급제가
  만든 정상 편이 매번 승인 단계에서 막혔다. *"내가 만든 게이트가 스스로를 막았다."*

커밋이 스스로 정리한 규칙이 이 스킬의 뼈대다:
> **게이트는 셋을 같이 넣어야 한다 — ① 검사 ② 모델이 그 기준을 알 방법(프롬프트)
> ③ 걸렸을 때 고치는 법(되먹임). 하나라도 빠지면 게이트가 아니라 함정이다.**

## 체크리스트

### ① 검사 (gate)
- [ ] 무엇을 어떤 임계로 막는지 코드로 명확한가?
- [ ] 검사가 보는 **필드 범위**와 프롬프트 금지문이 말하는 범위가 같은가?
      (한쪽은 필드 하나, 다른 쪽은 두 필드를 보고 있지 않은가)
- [ ] 이 게이트가 **다른 게이트와 모순되지 않는가?** 상한을 올렸다면 승인 예산·하드캡 등 연동된
      값도 함께 올렸는가? (순서를 회귀 테스트로 고정하는 것을 권한다: 승인 예산 < 예상 비용 < 하드캡)

### ② 프롬프트 고지 (모델이 알 방법)
- [ ] 게이트가 쓰는 기준값이 **프롬프트에 실제로 들어가는가?**
- [ ] 그 값을 **게이트가 쓰는 것과 같은 함수**에서 가져오는가?
      (`directive.source_depth_guidance()`, `photo_contract.target_cut_range` 같은 형태 —
      값을 프롬프트에 손으로 다시 적으면 `value-duplication-drift-audit` 대상이 된다)
- [ ] 조건부 금지라면, 그 **조건을 판정하는 입력값 자체**를 모델이 아는가?
      (`source_depth`가 낮아서 금지되는데 모델은 그 값을 못 본 사례가 바로 이것이다)

### ③ 되먹임 (걸렸을 때 고치는 법)
- [ ] 차단 사유마다 **처방 문장이 있는가?** 사유 목록과 처방 목록의 개수를 세어 대조한다
      (24개 중 7개가 비어 있던 사례).
- [ ] 재생성 루프가 **모든 계약의 차단 사유를 읽는가?** 하나만 읽으면 나머지 위반은 재시도 없이
      사람에게 넘어간다.
- [ ] 처방을 만드는 함수가 실제로 **호출되는가?** (grep 0건이면 `dead-wiring-audit` 대상)

### 연동 확인
- [ ] 게이트를 추가·수정한 뒤 실제 산출물을 **한 편 끝까지 돌려** 정상 편이 안 막히는지 봤는가?
      (`render-required-verification-audit`와 함께 쓴다)

### ④ 통과 가능성 — 단계끼리 교착하지 않는가 (v1.1 추가)
게이트 하나하나는 맞는데 **앞뒤 단계와 합치면 원리상 통과할 수 없는** 경우다. 모델이 몇 번을
다시 해도 같은 자리에서 막힌다.
- [ ] 이 게이트의 요구가 **앞 단계가 만든 산출물로 충족 가능한가?** 앞 단계가 아예 넘기지 않는
      정보를 뒤 단계가 요구하면 영원히 막힌다(VIDEO-ARTICLE `90b3f44` 09-27 — 대조용 원문(PMC 본문)에
      초록이 빠져 있어, 초록 문장을 인용한 주장이 전부 "원문에 없음"으로 차단됐고 지시서를 다시
      만들어도 같은 원문으로 대조하니 계속 잠겼다).
- [ ] **같은 판정을 두 단계가 다른 기준으로 하지 않는가?** VIDEO-ARTICLE `5fab247`(10-04) — 같은
      핵심 질문 문장을 Phase 6 은 "낱말 60%만 같으면 통과", Phase 7 은 "글자 그대로 같아야 통과"로
      봐서, 모델이 말투만 바꿔도("~는가?"→"~는 걸까요?") 실제 실행 2건이 모두 Phase 7 에서 막혔다.
      처방: 두 단계가 **같은 판정 함수 하나**를 부르게 한다.
- [ ] 한 값을 여러 단계가 나눠 쓰는가? 앞 단계가 다 넘기고, 다음 단계는 바꾸지 말라 하고, 그
      다음은 개수를 제한하면 셋이 동시에 만족될 수 없다(`67f242b` 10-04 — 말로 읽을 숫자를 Phase 5
      에서 미리 고르고 나머지는 화면 카드로 보내는 것으로 풀었다).
- [ ] 코드 정리와 게이트가 서로 물지 않는가? `6c1f02a`(09-27) — 모델이 첫 문장을 훅 칸에 옮기면
      코드가 "중복"이라 지우고, 게이트는 빈 훅을 막았다. 논문 실사형 36건 중 7건이 최종 잠김.

### ⑤ 출력 계약 — 모델이 낼 모양을 정했는가 (v1.1 추가)
게이트가 없어도 같은 원리가 적용된다. 모델이 무엇을 낼지 모르면 **파이프라인이 죽는다.**
- [ ] 받는 필드마다 **뜻(무엇을 담나)과 형식(허용값 목록·타입)** 을 둘 다 프롬프트에 줬는가?
      Aria `f0fd5db`(09-22)가 `blocking_reasons` 실제 응답을 세어 보니 자유서술 224종 중 222종이
      1회성이었고, 다음 날 `ed5b25a` 에서 모델이 문자열 대신 dict 를 내자 `dict.fromkeys` 가 터져
      **채점 회차 전체가 TypeError 로 중단**됐다.
- [ ] 파서는 프롬프트가 약속하지 않은 모양(dict·숫자 대신 등급 단어 `'high'` 등)을 받으면
      **회차를 죽이지 않고** 그 항목만 경고로 드러내는가?
- [ ] 프롬프트의 **예시를 모델이 그대로 베끼지 않는가?** VIDEO-ARTICLE `bea7a34`(09-29) — 첫 컷이
      프롬프트 예시 문장을 그대로 따라 썼다. 예시는 실제 소재와 겹치지 않게 쓰고, 베낌을 검사한다.

## 진단 기법 (v1.1 추가 — 실제로 효과를 본 것)
- **발생률을 전수로 센다.** 저장된 산출물 전부에 대해 경고·차단 사유별 발생률을 세어
  **100% 짜리**를 찾는다. 100% 는 모델 잘못이 아니라 게이트가 입력을 못 보고 있다는 신호다
  (`52e0e2d` 09-20 리포트 8편 전부에서 뜬 경고 5종, `e66f5ee` 09-21 지시서 17/17 이 같은 사유로 차단 → 고친 뒤 0건).
- **세 다리 대조를 테스트로 고정한다.** 승격(09-04) 뒤에도 `e66f5ee` 에서 `vseq_screen_world` 가
  차단 분류인데 경고 목록에 들어 있고 처방도 없었다. 사유 목록·분류·처방 목록이 서로 빠짐없이
  짝지어졌는지 정적 테스트로 센다(`enforce-by-type-or-test`).
- **반복해서 못 맞추면 묻지 않는다.** 모델이 되먹임을 받고도 같은 칸을 계속 틀리면, 그 칸을
  스키마에서 빼고 코드가 정한다(`581cc41` 09-28 — 코드가 정할 칸 28개를 더는 묻지 않음).
- **돈 들기 전에 0원으로 본다.** 유료 모델 호출 전 사전 점검(`2de1295` 10-04)과, 저장된 실제
  응답을 다시 돌려 게이트만 검증하는 재생(`5fab247`)으로 기준을 바꿀 때마다 확인한다.

## 사용 방법
LLM 게이트를 추가·수정하는 커밋에서 ①②③을 한 번에 넣는다. 셋 중 하나만 넣고 커밋하지 않는다.
"계속 막힌다"는 증상을 만나면 ②(모델이 기준을 아는가)부터 확인한다 — 이 저장소에서 다섯 번 중
네 번이 거기였다. ②가 갖춰졌는데도 막히면 ④(단계 교착)를, 파이프라인이 죽었으면 ⑤를 본다.
