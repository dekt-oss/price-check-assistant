# 작업 완료 보고

## 언제 쓰나
- 코드·설정·스키마·데이터·문서를 **바꾼** 턴이 끝날 때 (커밋·PR 유무와 무관)
- 여러 단계를 거친 조사·디버깅을 끝내고 결론을 전할 때
- 사용자가 "정리해줘", "뭐 했어?", "어떻게 확인해?"라고 물을 때

## 언제 생략하나
한 줄 질문에 답만 하는 턴, 파일 하나 읽어주는 턴처럼 **바꾼 게 없는 작업**. 이때는 그냥 답한다.

---

## 쓰기 전에 — 증거 게이트 (건너뛰지 말 것)

보고서를 쓰기 시작하기 전에 아래를 먼저 통과한다.

1. **"머지·배포·PR 생성"은 "동작·해결"이 아니다.** 둘을 같은 문장에 뭉개지 않는다.
2. 사용자에게 보이는 **최종 결과를 실제 증거로 확인하기 전에는** "완료/해결/됩니다"라고 쓰지 않는다.
   확인 못 했으면 그 문장에 **`(미검증)`** 을 붙이고, 무엇을 어떻게 확인해야 하는지 명시한다.
3. 증거로 인정되는 것: 실제로 돌린 테스트 결과, 명령어 출력, SQL 조회 결과, 로그 줄, 화면 확인.
   **"코드를 읽어보니 맞다"는 증거가 아니다.**
4. 검증이 막혔으면(키·권한·네트워크·실기기 없음 등) 막혔다는 사실과 남은 검증 단계를 밝히고 끝낸다.
   "아마 될 것"으로 완료 처리 금지.
5. 이 저장소에 `verify-before-done`처럼 **저장소 전용 검증 지시서**가 있으면 그 검증 표를 함께 적용한다.

## 보고 형식 (다섯 소제목을 그대로, 이 순서로)

사용자가 정한 흐름이다: **뭘 시켰고 → 문제가 뭐였고 → 어떤 방법으로 어떻게 해결했고 →
나는 이렇게 확인하면 되고 → 다음 작업은 이렇게 하면 된다.** 각 레포 CLAUDE.md 의
"작업 결과 보고" 절이 같은 순서를 요구한다 — 둘을 바꿀 때는 같이 바꾼다.

### ① 시키신 것
사용자가 요청한 내용을 **사용자의 말로** 한두 문장. 내가 범위를 줄였거나 넓혔으면 여기서 밝힌다
("~까지 요청하셨는데 ~는 이번에 하지 않았습니다").

### ② 문제가 뭐였나
증상부터 쓴다 — 사용자가 화면에서·실제로 겪은 것. 그다음 진짜 원인 한 문장.
함수명·스택트레이스 나열 금지. 버그가 아니라 새 기능이면 "지금까지는 ~를 못 했다"로 결핍을 쓴다.

### ③ 어떻게 해결했나
**방법**(어떤 접근을 택했는지, 버린 대안이 있으면 한 줄)과 **결과**(바뀌기 전 → 바뀐 후)를
관찰 가능한 말로 쓴다. 고친 파일은 많아야 2~3개만 이름을 댄다. "리팩터링했다" 같은 뭉뚱그린
표현 금지. 여기서 **되는 것 / 아직 안 되는 것**을 반드시 나눈다. 머지·배포·PR·사용자가 눌러야
할 버튼·넣어야 할 키는 전부 "아직 안 된 것" 쪽이다.

### ④ 이렇게 확인하세요
사용자가 **직접 밟을 수 있는** 순서. 체크박스로 쓴다.
```
- [ ] (어디서) (무엇을 한다) → (무엇이 보이면 성공)
```
- 화면 경로·버튼 이름·명령어를 구체적으로. 명령어·SQL은 **복붙 가능한 형태**로.
- 각 항목 끝에 **성공 판정 기준**을 한 줄 붙인다. 판정 기준 없는 항목은 체크리스트가 아니다.
- 사용자 환경에서만 되는 것(실기기 카메라, 유료 키, 프로덕션 배포)은 그렇게 표시한다.
- 맨 끝에 **"제가 이미 확인한 것"** 을 따로 붙인다: 테스트 이름·통과 개수·조회 결과·로그 줄.

### ⑤ 다음 작업
이어서 할 일을 **누가·무엇을·어떻게**로 1~3개. 사용자가 결정해야 하는 것이 있으면 맨 앞에
"결정해 주실 것:"으로 하나만 묻는다. 남은 일이 없으면 "남은 작업 없음"이라고 쓴다.
```
- (누가: 제가/사용자께서) (무엇을) — (어떻게: 명령어·화면·순서)
```

## 쉬운 언어 규칙
- 전문용어는 처음 한 번 괄호로 푼다: "워크플로(자동 실행 스크립트)".
- 추론을 화살표로 나열하지 않는다(`A → B → 실패` 금지). 약어·조각 문장도 금지, 완결된 문장으로 쓴다.
  단 ④ 체크리스트의 "이렇게 한다 → 이게 보이면 성공" 표기는 예외다(추론이 아니라 판정 기준이므로).
- 숫자는 구체적으로: "여러 건" 대신 "5건", "최근" 대신 "07-27·07-29".
- 사과·자책·장황한 서론 없이 바로 본론.
- 전체 길이는 화면 한 눈에 들어오게. 길어지면 ②·③을 줄이고 ④·⑤는 줄이지 않는다.

## 예시 (짧은 형태)

> **① 시키신 것**
> 로그인 후 첫 화면이 빈 화면으로 뜨는 문제를 고쳐 달라고 하셨습니다.
>
> **② 문제가 뭐였나**
> 로그인에 성공해도 홈 화면에 아무 것도 안 나오고 흰 화면만 보였습니다. 원인은 사용자 정보를
> 불러오기 전에 화면을 그리려다 오류가 나서 그 아래 내용이 통째로 멈춘 것이었습니다.
>
> **③ 어떻게 해결했나**
> 정보를 다 받은 뒤에 그리도록 하는 방법 대신, 기다리는 동안 로딩 표시를 보여 주는 방법을
> 택했습니다(느린 회선에서도 화면이 멈추지 않게). 이전에는 화면이 멈췄고, 지금은 "불러오는 중"이
> 보였다가 홈 화면이 나옵니다(`src/app/(tabs)/index.tsx`).
> 되는 것: 로그인 후 홈 화면 표시. 아직 안 된 것: PR 상태라 병합·배포는 안 했습니다.
>
> **④ 이렇게 확인하세요**
> - [ ] 앱을 껐다 켜고 로그인한다 → 흰 화면 대신 홈 화면이 3초 안에 보이면 성공
> - [ ] 비행기 모드로 바꾸고 로그인한다 → 흰 화면이 아니라 "불러오는 중" 표시가 보이면 성공
>
> 제가 이미 확인한 것: `npm test` 전체 통과(42개), `npm run typecheck` 오류 0건.
>
> **⑤ 다음 작업**
> - 결정해 주실 것: PR 을 지금 병합할지 정해 주세요.
> - 병합되면 제가 OTA 업데이트를 내보내고, 실기기에서 위 ④를 한 번 더 돌려 결과를 알려 드리겠습니다.
