# Value Duplication Drift Audit

## 언제 쓰나
- 임계값·상한·가중치·화이트리스트를 추가하거나 바꿀 때
- 같은 로직이 두 런타임(Python 엔진 vs Edge Function, 앱 vs SQL 함수)에 존재할 때
- 디자인 토큰·색·치수·카드 스타일을 새 화면에 적용할 때
- **"값을 올렸는데 동작이 안 바뀐다"** 는 증상을 진단할 때 (상한이 여러 겹인 신호다)
- fixture·목업 데이터를 화면별로 만들 때

## 왜 필요한가
**2개 레포 12회.** 다른 후보들과 달리 세 번째 레포가 안 나왔지만, 한 레포에서만 7번 재현돼
"레포 다양성" 기준의 예외로 등재했다. 프로덕션 DB부터 디자인 목업까지 층을 가리지 않는다.

- **VIDEO-ARTICLE** `65b09df`→`884874a`→`9dc298a` — 영상 클립 상한이 **세 계층에 각자 하드코딩**돼
  있어 20분 동안 하나씩 발견하며 풀었다. *"개수 상한 두 개를 8개로 올렸는데 지시서가 세 번 연속
  영상 2개로 나왔다 … 상한이 세 겹인 것을 몰랐다."* 값이 어긋난 게 아니라 **같은 정책을 세 곳이
  각자 집행해 한 번에 풀 수 없는** 형태였다.
- **VIDEO-ARTICLE** `c3fc8cc`/`e3a4841`/`f9663c2`/`dc32d92` — Python 엔진과 Edge Function 두 런타임에
  같은 LLM 호출이 복제돼 출력 예산(8192 vs 2048)·타임아웃이 각자 하드코딩돼 어긋났다. **네 번**
  같은 자리에서 재현됐다.
- **VIDEO-ARTICLE** `b044b33` — 대본 정본이 `script_md`와 `scenes` 두 벌로 저장돼, 운영자가 지운
  문장이 지시서에 **되살아났다**(상수가 아니라 콘텐츠 정본의 이중화).
- **k-vivino** `62db7e2` — 출시 게이트 임계값이 SQL과 `gates.ts` 양쪽에 있다가 완화 변경이 한쪽만
  반영돼, 게이트 리포트는 false인데 프로덕션은 이미 기능을 노출 중이었다.
- **k-vivino** `4275967` — 카드 스타일을 **31개 파일이 각자 선언**하고 있었음을 grep으로 실측했다.
  그 전에 `4a2a530`이 손으로 4곳을 맞췄는데, 커밋이 스스로 *"직전 PR에서 내가 베껴 쓴 것 포함"*
  이라고 인정했다 — **값을 손으로 맞추는 수정은 드리프트를 없애지 않고 복제할 뿐이다.**
- **k-vivino** `c40b729` — 나라 구분 규칙이 인계 문서엔 "두 벌"이라 적혀 있었는데 실제로 세니
  **세 벌**이었고 그중 둘이 틀렸다. 목록을 맞추는 방식으로는 못 잡아 규칙을 걷어내고 컬럼 하나를
  진실원으로 삼았다.
- **k-vivino** `89b581f` — Design Lab 화면 셋이 같은 술의 최저가를 각자 손으로 적어 72,000원 /
  78,000원으로 갈렸고, 72,000원은 **어느 관측 기록에도 없는 숫자**였다. 아직 DB도 안 붙은
  목업 단계에서 같은 실패가 났다.

## 체크리스트

### 1. 지금 이 값이 몇 곳에 있는지 센다
- [ ] 값 자체(숫자·문자열)로 저장소 전체를 grep해 **실제 개수를 세었는가?** 문서·인계 노트가
      말하는 개수를 믿지 않는다(k-vivino는 "두 벌"이 실제로 세 벌이었다).
- [ ] 코드 밖 계층도 훑었는가 — SQL 함수, DB 기본값, 마이그레이션, 워크플로 YAML, fixture, 목업
- [ ] 같은 정책을 **집행하는 지점**이 여럿인가? (값이 같아도 집행이 세 겹이면 한 번에 못 푼다)

### 2. "값을 바꿨는데 안 먹는" 증상 진단
- [ ] 상한·필터가 **여러 겹**인지 먼저 의심한다. 하나를 고치고 재확인 → 여전하면 다음 겹을 찾는다.
- [ ] 두 런타임에 복제된 로직이라면 **양쪽 다** 확인했는가?
- [ ] 화면이 읽는 정본과 생성기가 읽는 정본이 **같은 저장 위치**인가?

### 3. 처방 — 손으로 맞추지 말고 모은다
- [ ] 값을 복사해 맞추려는 손을 멈춘다. 그 수정은 드리프트를 복제한다(k-vivino가 직접 인정).
- [ ] 단일 진실원을 정한다: config 상수 하나 / 공용 컴포넌트 하나 / DB 컬럼 하나 / fixture 파일 하나
- [ ] 파생값(가격대·최저가·대표 스타일)은 **저장하지 말고 진실원에서 계산**한다.
- [ ] 진실원으로 모은 뒤 **어긴 것이 기계에 잡히게** 고정한다 → `enforce-by-type-or-test` 판단표를 쓴다.
      (이 스킬은 "어디에 모을까", 그 스킬은 "어떻게 강제할까"를 담당한다 — 같은 작업의 앞뒤다)

## 사용 방법
임계값·정책·정본을 손대는 커밋 직전에 §1로 실제 개수를 세고, 둘 이상이면 §3으로 모은다.
"올렸는데 안 먹는다"는 증상을 만나면 §2를 먼저 돌린다 — 원인 추정보다 겹 수를 세는 것이 빠르다.
