# Dead Wiring Audit

## 언제 쓰나
- 새 서비스·스케줄 잡·API 라우트·컴포넌트를 추가한 직후
- 스키마에 새 필드·새 사유 코드·새 상태값을 추가한 직후
- 자가검증·셀프테스트·QA 스크립트를 새로 만든 직후
- "기능은 만들었는데 아무 데도 안 나타난다", "표본이 안 쌓인다", "이 상태가 한 번도 안 뜬다"를 진단할 때

## 왜 필요한가
`deploy-staleness-check`("배포됐지만 재배포가 안 걸려 옛 버전이 돈다")와도,
`adjacent-path-guard-audit`("가드가 한 경로엔 있고 인접 경로엔 없다")와도 다르다 —
**이건 애초에 어떤 경로에서도 호출된 적이 없는 코드다.** 3개 레포 9회.

- **Aria** `9ab03b0` — M6 표본 테이블에 INSERT하는 서비스가 scheduler를 포함해 런타임 어디서도
  호출되지 않았다. "표본 축적 대기"가 실은 **영원히 안 끝나는 상태**였음을 실측으로 확인했다.
- **Aria** `5ae8526` — `scheduler._run_kr_validation`이 `_scheduled_jobs()`에 등록돼 있지 않아
  어떤 진입점에서도 안 불리는 죽은 코드였다.
- **Aria** `a57d13c` — `selftest.py`의 결손 검사 2건이 main에서도 오래 빨간불이었는데 아무도 몰랐다.
  근본 원인은 **그 자가검증 자체가 CI에 안 물려 있었던 것** — 검사가 있어도 안 돌면 없는 것과 같다.
- **VIDEO-ARTICLE** `e9e37d1`/`ebfaf52` — `viz_template`·`viz_params`·`asset_source`가 스키마·프롬프트엔
  있지만 **저장소 전체 grep 0건**이라 해당 타입 전용 시각 경로가 애초에 없었다.
- **VIDEO-ARTICLE** `57cdb4cc` — 한 커밋 안에 두 건이 함께 나왔다: 사유 코드·처방이 있는데 내보내는
  곳이 없었고, QA의 `degraded_summary`도 "그릇만 있고 넣는 곳이 없었다".
- **VIDEO-ARTICLE** `d4fd876` — `feedback_prompt` 함수가 저장소 어디서도 안 불려(grep 0건) 재생성
  루프가 반쪽으로 돌았다.
- **k-vivino** `3769160`·`62509c5` — `BottomTabInset`·`AppButton`이 선언은 돼 있는데 실제로 쓰는
  화면이 0곳이었다(이틀 연속 재발).
- **k-vivino** `c21e522` — `Freshness` 타입의 `unknown` 상태로 가는 유일한 분기가 앞선 early return
  뒤에 있어 **구조적으로 도달 불가능**했다(테스트는 통과하지만 실행되지 않는 코드).

## 체크리스트

### 1. 호출부가 실재하는지 실측
- [ ] 새로 만든 함수·서비스·컴포넌트 이름으로 저장소 전체를 `grep`했을 때, **정의부 말고 호출부**가
      최소 1건 나오는가? (0건이면 죽은 코드다)
- [ ] 새 스키마 필드를 **쓰는 쪽(읽기·표시·내보내기)** 이 있는가? 만드는 쪽만 있으면 반쪽이다.
- [ ] 새 사유 코드·상태값·enum 항목이 실제로 **발생시키는 자리**가 있는가?

### 2. 진입점에 물려 있는지 확인
- [ ] 스케줄 잡이면 `_scheduled_jobs()`류 등록 목록에 실제로 들어갔는가?
- [ ] 워크플로/크론이 이 스크립트를 부르는가? (워크플로 YAML을 직접 열어 확인)
- [ ] API 라우트면 라우팅 테이블·파일 기반 라우팅 규칙에 실제로 잡히는 경로인가?
- [ ] **검증 장치(셀프테스트·QA·계약 테스트)를 만들었다면, 그것이 CI에 물려 있는가?**
      안 물린 검사는 빨간불이어도 아무 데도 도달하지 않는다(Aria `a57d13c`).

### 3. 도달 가능성 확인
- [ ] 이 분기로 가는 조건이 **앞선 early return·가드 뒤에 갇혀** 있지 않은가?
- [ ] 이 상태를 실제로 만들어 내는 입력이 존재하는가? 테스트/fixture에서 한 번이라도 도달하는가?
- [ ] 도달 불가능한 상태라면, 코드를 배선하는 대신 **타입에서 지우는** 편이 나은가?
      (k-vivino는 `Freshness | null`로 바꿔 "가격이 없으면 최신성도 없다"를 타입에 드러냈다)

### 4. 자동화
- [ ] 반복된다면 훑기 도구를 만든다 — VIDEO-ARTICLE `scripts/sweep_unwired.py`가 선례다
      (선언된 이름 목록과 호출부를 대조해 미배선 항목을 보고).

## 사용 방법
새 서비스·필드·컴포넌트를 만든 커밋 직전에 §1을 grep으로 실측한다. 스케줄·워크플로·CI가 관련되면
§2를 반드시 함께 본다. "만들어 놓고 한쪽만 연결"이 세 번 이상 반복되는 저장소라면 §4의 훑기
도구를 만들어 커밋 전 자동 점검으로 돌린다.
