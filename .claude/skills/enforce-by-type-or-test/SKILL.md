# Enforce by Type or Test

## 언제 쓰나
- 같은 실수가 **두 번째** 반복됐을 때 (세 번째를 기다리지 않는다)
- "다음부터 X할 때는 Y를 확인할 것" 같은 주석·문서 리마인더를 쓰려고 할 때
- 목록·화이트리스트·팔레트처럼 **값이 하나 늘 때마다 무너지는** 구조를 만들 때
- 문서화된 계약(명세서·CLAUDE.md)이 실제 코드와 어긋난 것을 발견했을 때

## 왜 필요한가
**주석 리마인더는 지켜지지 않는다.** 이 저장소들이 두 달에 걸쳐 직접 증명했다.

- **k-vivino** `ddad7d6`(2026-09-04) — 가장 결정적인 사례. 마이그레이션 파일명 접두가 겹치면 CI가
  죽는데, "겹치는 접두를 쓰지 말 것"이라고 주석에 적어 둔 **뒤에도 두 번 더 겹쳤다**(총 4회 재발,
  `migration-runtime` CI가 11일간 빨간불). 커밋이 스스로 정리한다 — *"글 대신 검사로 막는다."*
  결국 `migration-filenames.test.ts`(접두 중복을 커밋 시점에 기계적으로 검사)로 옮겨 끝냈다.
- **k-vivino** `7c6b2f1` — 카테고리 필터 목록에 새 값을 빠뜨리는 사고가 두 번째 재발하자, "목록을
  바꿀 때 DB와 대조할 것"이라는 주석 대신 `categories.ts` 단일 소스 + `Record<Category, …>`
  exhaustive 표로 옮겨 **컴파일이 깨지게** 만들었다.
- **k-vivino** `4336682` — 신뢰 배지 색이 "라이트·다크 공통"이라는 주석과 달리 다크에서 대비 2.65로
  실패였다. 원인은 그 색이 팔레트 **밖** 고정값이라 자동 대비검사의 순회 대상에 애초에 안 들어간
  것 — 색을 팔레트로 흡수해 **예외 자체를 없앴다.**
- **Aria** `b2f0142` — psycopg2 UUID 바인딩 규약을 Shadow 서비스 7종 전수 정적 소스검사 테스트로
  강제하고, **한 서비스를 일부러 되돌려 실제로 잡히는지 회귀 검증**까지 했다.
- **VIDEO-ARTICLE** `b169208`·`b044b33` — 비용 원장 배선을 단언 테스트로 못박고, 외래키를 뗀 자리에
  CHECK 제약을 넣어 임의 문자열이 들어가던 상태를 막았다.
- **k-vivino** `4685384` — 회귀 테스트를 특정 구현이 아니라 **성질**("끝까지 넘기면 원본 전부가
  정확히 한 번씩 나온다")로 고정해, 나중에 서버 RPC로 바꿔도 같은 성질을 지켜야 하게 만들었다.

## 강제 수단 판단표 (이 스킬의 본체)

| 규약의 모양 | 쓸 수단 | 실제 사례 |
|---|---|---|
| 값 목록에 새 항목이 추가될 때 처리부를 빠뜨리면 안 됨 | **타입 exhaustive** (`Record<K, …>`, 빠짐없는 switch) | k-vivino `categories.ts` |
| 여러 파일이 같은 호출 규약을 지켜야 함 | **전수 정적 소스검사 테스트** (소스를 읽어 패턴 검색) | Aria `b2f0142`, k-vivino `cap-header-no-double-head.test.ts` |
| 파일명·경로·접두 같은 저장소 규칙 | **파일 목록 검사 테스트** | k-vivino `migration-filenames.test.ts` |
| DB에 들어갈 수 있는 값의 범위 | **DB CHECK 제약 / 외래키** | VIDEO-ARTICLE `0039` |
| 구현이 바뀌어도 지켜야 하는 결과의 성질 | **성질 기반 테스트** | k-vivino `4685384` |
| 색·치수처럼 자동 순회 검사가 있는 값 | **예외를 없애고 순회 대상 안으로 흡수** | k-vivino `4336682` |
| 사람이 배포 전 눈으로 봐야만 아는 것 | 강제 불가 → `render-required-verification-audit`로 넘긴다 | — |

## 체크리스트
- [ ] 이 규칙을 어겼을 때 **무엇이 깨지는가?** 아무것도 안 깨지고 사람이 나중에 발견한다면 강제 수단이 없는 것이다.
- [ ] 위 판단표에서 이 규약에 맞는 수단을 골랐는가?
- [ ] 강제 수단을 만든 뒤, **일부러 규칙을 어겨 실제로 잡히는지** 확인했는가?
      (Aria `b2f0142`·k-vivino `4bff482` 둘 다 이 역검증을 했다 — 안 하면 검사가 죽어 있어도 모른다)
- [ ] 그 검사가 **CI에 물려 있는가?** (안 물린 검사는 `dead-wiring-audit` 대상이다)
- [ ] 값이 검사의 **순회 대상 집합에 실제로 들어가는가?** 팔레트 밖 예외처럼 집합 밖에 있으면 검사는 통과하고 값은 틀린다.

## 사용 방법
같은 실수를 두 번째 발견한 순간 이 스킬을 연다. 주석을 강화하려는 손을 멈추고 판단표에서 수단을
고른다. 수단을 만든 뒤에는 반드시 역검증(일부러 어겨 보기)까지 하고, 그 검사를 CI에 문다.
